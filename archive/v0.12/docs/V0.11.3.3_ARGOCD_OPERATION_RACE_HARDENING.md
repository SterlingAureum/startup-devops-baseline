# v0.11.3.3 Argo CD Operation Race Hardening

> Successor note: v0.11.3.5 adds revision content preflight and separates
> pre-merge feature restoration from post-merge HEAD restoration. Follow
> `docs/V0.11.3.5_PRE_MERGE_BASELINE_RESTORATION.md` for current commands.

## Outcome

The local feature and HEAD-restoration workflows now tolerate the short Argo
CD API lock hand-off in which the Application custom resource appears idle but
the API still rejects a mutation with `FailedPrecondition: another operation
is already in progress`.

The repair is fail-closed and bounded. It retries only that exact operation-busy
class, waits for the affected Application before retrying, stops after five
attempts, and prints Application diagnostics on exhaustion. Permission,
validation, repository, and every other error remain immediate failures.

## Observed Failure

The v0.11.3.2 clean replay stopped immediately after the Root Application was
rendered in manual mode:

```text
==> Syncing the root once so child Applications are created from the feature revision
rpc error: code = FailedPrecondition desc = another operation is already in progress
```

This occurred before child automation, revisions, or local-image Helm
parameters were mutated. The failed run therefore does not count as clean
acceptance, but it also did not complete a partial feature deployment.

## Why v0.11.3.1 Was Insufficient

v0.11.3.1 correctly removed the Root automatic-sync creation race and added
Application idle checks. Those checks observed `.operation` and
`.status.operationState.phase`. A short server-side lock can outlive those
observable fields, so two idle samples were not a proof that the next Argo CD
mutation would be accepted.

The old validator confirmed only that wait-related source markers existed. It
did not execute a mutation that fails operation-busy once and then succeeds.

## Implementation

`scripts/lib/argocd-operation.sh` is now the single implementation for:

- stable Application idle observation;
- exact operation-busy classification;
- bounded retry and delay;
- exhaustion diagnostics.

Both `deploy-local-feature-gitops.sh` and
`restore-local-gitops-head.sh` use the helper for Argo CD `sync`, `set`, and
`unset` mutations. Defaults are:

```text
APPLICATION_IDLE_OBSERVATIONS=3
OPERATION_BUSY_MAX_ATTEMPTS=5
OPERATION_RETRY_DELAY_SECONDS=2
WAIT_TIMEOUT_SECONDS=180
```

These values are configurable for diagnostics and tests, but invalid or
unbounded values are rejected before a workflow mutates Argo CD.

## Offline Validation

```bash
bash -n scripts/*.sh scripts/lib/*.sh
./scripts/validate-v0.11.3.3-argocd-operation-race-hardening.sh
./scripts/validate-ci-quality-gates.sh
```

The v0.11.3.3 validator executes four regression classes:

1. first mutation is operation-busy and the second succeeds;
2. operation-busy persists and stops at the configured bound;
3. a non-busy error fails after one attempt;
4. an invalid retry bound is rejected.

## Clean Live Acceptance

v0.11.3.4 later removes direct child `set` and `unset` mutations while retaining
this bounded helper for Root and child sync operations. Its unified revision
model supersedes the Root `OutOfSync` acceptance state described by the earlier
workflow.

This increment is not accepted from offline tests alone. Push the exact source
to `feature/v0.11-observability-sre-baseline`, restore the stable baseline, and
replay the feature workflow:

```bash
./scripts/restore-local-gitops-head.sh

IMAGE_TAG=v0.11.3-local \
  ./scripts/build-load-demo-api-image.sh

TARGET_REVISION=feature/v0.11-observability-sre-baseline \
IMAGE_TAG=v0.11.3-local \
  ./scripts/deploy-local-feature-gitops.sh
```

Acceptance requires:

- no concurrent-operation fatal exit;
- the Root resolves the feature commit and remains manual;
- same-repository children resolve that same commit;
- the exact four local-image Helm parameters are present;
- Chart `demo-api-0.5.1`, ServiceMonitor, and Prometheus address checks pass;
- the Canary AnalysisRun completes under the v0.11.3.2 no-data guard;
- `validate.sh` and `check-monitoring.sh` pass;
- `restore-local-gitops-head.sh` completes without operation-busy failure;
- Root and children return to `HEAD`, live Helm parameters are empty, and Root
  prune/self-heal are restored.

Do not use `argocd app terminate-op` merely to make the test pass. A genuinely
stuck operation must be preserved and diagnosed separately.

## Boundary

This increment changes no Helm Chart, image, application telemetry,
ServiceMonitor, Prometheus query, Canary strategy, AWS state, production
automation, or active tracked GitOps revision.
