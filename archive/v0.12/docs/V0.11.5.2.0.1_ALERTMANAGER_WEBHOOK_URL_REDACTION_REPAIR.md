# v0.11.5.2.0.1 Alertmanager Webhook URL Redaction Repair

## Outcome

The first v0.11.5.2.0 local acceptance run proved that the monitoring
Application was Synced and Healthy, the Alertmanager Pod was Ready, both drill
receivers and webhook integrations were loaded, and both integrations enabled
resolved delivery. `check-alertmanager.sh` nevertheless failed because it
required `/api/v2/status` to expose each configured webhook URL as plaintext.

The active Alertmanager configuration represented both values as:

```text
url: <secret>
```

This is an acceptance-parser defect, not a runtime configuration defect.

## Repair

The checker now separates desired-state and runtime representations:

- repository and literal-fixture validation still requires the exact two
  internal URLs under
  `alert-lifecycle-drill-sink.observability.svc.cluster.local:8080`;
- live `/api/v2/status` validation requires exactly two `url:` lines and
  requires both to equal `<secret>`;
- a missing redacted URL, an additional URL, or mixed plaintext/redacted live
  representation is rejected;
- the existing public-URL negative fixture remains rejected;
- route, receiver, matcher, `continue`, timing, webhook, and `send_resolved`
  cardinality remains exact.

Alertmanager global defaults such as `slack_app_url` and `pagerduty_url` do not
constitute configured notification integrations. The repository still rejects
actual `slack_configs`, `pagerduty_configs`, email, SNS, and other external
receiver blocks.

## Unchanged runtime

This repair changes no Helm Chart, Application, Alertmanager route or receiver,
NetworkPolicy, PrometheusRule, formal alert, webhook sink, live drill,
application image, AWS declaration, or release workflow. The local platform
Chart remains `0.4.1 / v0.11.5.2.0`; the observability views Chart remains
`0.4.1 / v0.11.5.1.1`.

No monitoring redeployment is required. The already loaded v0.11.5.2.0
runtime is the correct target for the repaired check.

```bash

```

Expected final line:

```text
v0.11.5.2.0.1 Alertmanager redacted webhook URL, runtime configuration, and Prometheus discovery acceptance passed.
```

After that check passes, continue directly to the guarded local drill without
redeploying monitoring:

```bash
CONFIRM_ALERT_DRILL=true \
  ./scripts/check-alert-lifecycle-drill.sh
```

The drill must still end with its zero-residual success line. Then rerun:

```bash
./scripts/check-alertmanager.sh
PROFILE=local ./scripts/check-actionable-alerts.sh
```

This repair is accepted only when the corrected checker, full drill, cleanup,
and exact nine-alert inactive baseline all pass.

The corrected checker did pass. The following drill run then proved warning
firing delivery but exposed a separate delete-before-resolved lifecycle defect.
That defect is repaired by v0.11.5.2.0.2, which retains the same rule and alert
identity through an explicit empty-vector transition before cleanup. The
redaction repair remains unchanged and is the predecessor of that successor.

## Boundary

webhooks, formal AWS execution, SLOs, logging, and tracing remain later work.
