# v0.11.6.2.0 demo-api OpenTelemetry Tracing Contract

## Outcome

This increment adds the application half of the minimal tracing path without
deploying a trace transport or backend. `demo-api` can accept W3C Trace Context,
create one bounded HTTP server span and a controlled PostgreSQL client child
span, and place valid trace and span identifiers in its existing JSON logs.

OTLP export is disabled by default. In that state the process creates no
exporter, batch processor, background export thread, or network attempt. The
later v0.11.6.2.1 increment may deploy an environment-local Collector and Tempo
before this switch is enabled.

## Trace Shape

```text
W3C traceparent
  -> demo-api SERVER span
     -> PostgreSQL CLIENT span
        -> correlated JSON record
```

The local profile intentionally keeps PostgreSQL disabled. Unit tests prove the
parent-child and correlation contract in memory; this increment does not invent
a local database or claim a live database trace. Formal live PostgreSQL trace
qualification remains an environment-scoped v0.11.8 responsibility.

## Runtime Contract

The exact application dependencies are:

```text
opentelemetry-api==1.44.0
opentelemetry-sdk==1.44.0
opentelemetry-exporter-otlp-proto-http==1.44.0
```

The Helm default is:

```yaml
telemetry:
  tracing:
    enabled: false
    endpoint: http://observability-otel-collector.observability.svc.cluster.local:4318/v1/traces
    protocol: http/protobuf
    timeoutSeconds: 5
```

Both Deployment and Rollout templates render the same four environment
variables. The endpoint is a future private service identity; no Collector
Service exists in this increment, and the disabled switch prevents use of the
endpoint.

The application does not configure ratio sampling. The Collector boundary owns
sampling policy once export is enabled. The SDK receives the six canonical
release attributes from `runtime_identity.py`, the same source used by JSON
logging:

```text
service.name
service.version
deployment.environment.name
platform.release.id
platform.source.commit
container.image.digest
```

## Span Boundaries

The HTTP span records only:

```text
http.request.method
http.route
http.response.status_code
```

Route templates are used after routing; unmatched input collapses to
`__unmatched__`. Requests to `/health`, `/ready`, and `/metrics` create no span;
their failures remain visible through the existing bounded logs and metrics.
The PostgreSQL span records only:

```text
db.system.name=postgresql
db.operation.name=health|marker.write|marker.read
```

Readiness calls the database health function with tracing suppressed so probe
traffic cannot create database-span noise. The explicit `/db/health` endpoint
and the internal marker operations retain the controlled client span.

## Security Boundary

The implementation does not collect raw URLs, query strings, request or
response bodies, Authorization or Cookie headers, database URLs, raw SQL,
parameters, or exception messages. It does not accept baggage, use automatic
instrumentation, or call a Tempo-, Jaeger-, X-Ray-, or vendor-specific API.
Failure spans receive only an error status; exception events are disabled.

The OTLP endpoint validator accepts HTTP or HTTPS, rejects embedded credentials,
query strings, and fragments, and caps the configured timeout at 30 seconds.
Ambient OTLP header, certificate, client-key, and credential-provider settings
are rejected in this credential-free increment. Ambient
`OTEL_RESOURCE_ATTRIBUTES` cannot add fields to the controlled trace resource.

## Log Correlation

While a valid span is current, the JSON formatter adds lowercase fixed-width
`trace_id` and `span_id` fields. It omits both fields when no valid context
exists. The application never generates placeholder identifiers. These fields
remain JSON content and are not added to the existing six-label Loki index.

## Offline Acceptance

Run:

```bash
./scripts/validate-v0.11.6.2.0-demo-api-opentelemetry-tracing-contract.sh
./scripts/validate-ci-quality-gates.sh
```

The complete gate builds the Docker test stage and runs all demo-api tests. The
focused validator also renders both Helm workload paths and rejects default
export, application sampling, baggage, sensitive span data, premature Tempo,
fake local PostgreSQL qualification, and a stale-image deployment.

## Local Live Acceptance

This increment changes application dependencies and therefore requires a
unique image rebuild and demo-api reconciliation. It does not require a Loki,
Alloy, Grafana, monitoring, Collector, Tempo, database, or PVC redeployment.

After deploying the unique image with tracing still disabled, run:

```bash
IMAGE_TAG=<unique-v0.11.6.2.0-tag> \
  ./scripts/check-demo-api-tracing-contract.sh
```

The check proves the exact image, dependency versions, disabled provider and
export boundary, preserved structured logging behavior, and absence of
fabricated correlation identifiers. It makes no trace-query claim.
