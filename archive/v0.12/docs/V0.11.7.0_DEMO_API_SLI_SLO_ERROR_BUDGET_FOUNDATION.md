# v0.11.7.0 Demo API SLI, SLO, and Error-Budget Foundation

## Outcome

This increment converts the accepted demo-api HTTP metrics into two explicit
service objectives and one Git-provisioned Grafana view. It changes no
application code or image and does not yet connect SLO state to alerts or Argo
Rollouts.

| Objective | Eligible traffic | Target | Rolling window |
| --- | --- | ---: | --- |
| Availability | `GET /version`; a `5xx` response is bad | 99.9% | 30 days |
| Latency | `GET /version` completed in 500ms or less | 99% | 30 days |

Health, readiness, and metrics traffic are not eligible. Kubernetes probes
therefore cannot inflate service reliability.

## Recording model

`demo-api-slo-recording-rules` publishes eight bounded series:

- eligible request rate and 5xx rate;
- availability ratio and remaining availability error budget;
- latency request rate and good-latency rate;
- latency ratio and remaining latency error budget.

Every series retains only environment, service, version, and platform release
identity. Request IDs, URLs, trace IDs, Pod names, and container identities are
not labels. Missing traffic is no-data, not a synthetic healthy value.

Remaining budget is clamped to `[0, 1]`. Zero means exhausted; one means no
observed budget consumption. The formula does not authorize deployment or
remediation decisions in this increment.

## Dashboard

Grafana provisions the immutable Dashboard
`startup-devops-demo-api-slo`. Its four panels use recording rules only:

1. availability SLO;
2. availability budget remaining;
3. latency SLO;
4. latency budget remaining.

Environment and release variables preserve the existing release-correlation
model.

## Local acceptance

Reconcile the committed feature revision and retain the fresh, tracing-capable
demo-api artifact accepted by v0.11.6.2.3.1. Then run:

```bash
./scripts/check-local-slo-foundation.sh
```

The check sends bounded `GET /version` traffic, waits for scrape and rule
evaluation, verifies all eight rules, checks ratio and budget ranges, and
confirms the immutable Dashboard through Grafana.

The local cluster normally has less than 30 days of history. A successful
check proves rule semantics, resource provisioning, current-sample evaluation,
and query wiring. It does not claim that a production service has achieved a
30-day SLO.

## Explicit boundary

This version adds no burn-rate alert, Alertmanager route, Canary gate,
automatic rollback, automatic promotion, synthetic failure, cross-environment
aggregation, or AWS runtime evidence. Those controls require independent
increments after these formulas are accepted.
