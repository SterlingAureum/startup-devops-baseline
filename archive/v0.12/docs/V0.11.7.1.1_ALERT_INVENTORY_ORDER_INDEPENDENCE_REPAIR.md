# v0.11.7.1.1 Alert Inventory Order-independence Repair

## Symptom

The complete quality gate can fail in the historical v0.11.5.1 validator with:

```text
Alert rule exists outside the successor-aware bounded inventory
```

All 13 expected alerts may still be present and valid.

## Cause

The v0.11.7.1 successor check collected alerts by iterating
`Path.glob("*.yaml")` and compared that list with a fixed concatenated list.
Filesystem directory iteration order is not a repository contract, so another
filesystem can return the two alert templates in the opposite order.

## Repair

The validator now independently enforces:

1. exact cardinality;
2. globally unique alert names;
3. set equality with the expected predecessor and successor inventories.

Only ordering across separate template files is ignored. Ordering inside each
owned template and the actual alert definitions remain covered by their
version-specific validators.

## Acceptance

The repair validator proves that normal and reversed template order both pass,
while duplicate and unexpected alert fixtures still fail. No reconciliation or
live cluster run is required because desired state is unchanged.
