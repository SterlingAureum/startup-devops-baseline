# v0.11.7.1.3 Burn-rate Rule Inventory jq Repair

## Symptom

The burn-rate live checker passes the SLO Dashboard and 13-alert clean state,
then jq reports `unexpected ';', expecting '|'` and the script misleadingly
claims the 28 recording rules are not loaded.

## Cause

The jq expression used `all($windows[] as $w; ...)`. A jq `as` binding requires
a following pipe, so the program failed to compile before reading the
Prometheus response.

## Repair

The checker now constructs the exact 28 expected names from seven windows and
four rule families, subtracts the loaded recording-rule names, and prints every
missing rule. Invalid or unsuccessful Prometheus payloads have a distinct error.

The check requires all expected rules but permits unrelated recording rules.
No PrometheusRule or runtime resource changes in this repair.

## Acceptance

```bash
./scripts/validate-v0.11.7.1.3-burn-rate-rule-inventory-jq-repair.sh
./scripts/check-local-slo-burn-rate-alerts.sh
```

Fixtures cover a complete inventory, one precisely reported missing rule, an
unsuccessful API payload, and malformed JSON.
