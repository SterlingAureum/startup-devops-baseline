# v0.11.7.3.1 Final Rollout Convergence Wait Troubleshooting

## Symptom

The first `CLOSURE_PHASE=final` invocation failed the immediate Healthy/stable
ReplicaSet assertion. Repeating the unchanged command succeeded and completed
all SLO, Dashboard, alert, and burn-rate checks.

## Cause

The second AnalysisRun can finish before the Rollouts controller completes the
remaining asynchronous status transitions: set weight to 100%, assign the new
stable ReplicaSet, scale old capacity, converge Ready/Available replicas, and
publish `status.phase=Healthy`. The first final checker observed this valid
intermediate state.

## Repair

The final phase now waits up to 300 seconds and polls every two seconds. Every
sample must retain the exact expected application version, so the wait cannot
silently follow a newer deployment. Expensive final observability checks begin
only after all strict Healthy/stable/replica assertions pass.

On timeout, diagnostics include phase, step index, current/stable hashes,
desired/current/updated/ready/available replicas, application version, and
pause conditions. Progressing remains fail-closed after the bounded deadline.

## Operation

Run the same final command once:

```bash
CLOSURE_PHASE=final \
EXPECTED_APPLICATION_VERSION=<accepted-release-version> \
  ./scripts/check-local-slo-progressive-delivery-closure.sh
```

No new release, image build, reconciliation, promotion, or cleanup is required
for this validation-only repair.
