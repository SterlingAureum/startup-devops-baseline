# v0.11.8.0 Environment Observability Qualification Foundation

## Purpose

The local v0.11.7 closure proves the local SLO-aware delivery path. It does not prove that the same metrics, dashboards, alerts, logs, traces, or SLO signals are deployed or correct in an AWS environment. This increment establishes the contract that prevents that inference.

No live environment is qualified by v0.11.8.0. The increment supplies the capability vocabulary, evidence schema, identity lock, action policy, and negative acceptance needed by the later environment-specific live increments.

## Qualification model

Qualification answers three separate questions:

1. Is the capability declared for this environment profile?
2. Is its runtime currently available?
3. Was the declared capability observed successfully against an exact environment and release identity?

The answers must not be collapsed into one Boolean.

| Status | Meaning |
| --- | --- |
| `supported-verified` | The profile declares the capability and the current qualification produced passing evidence. |
| `supported-not-verified` | The profile declares it, but the current qualification has no successful runtime evidence. |
| `not-deployed` | The profile intentionally has no runtime for the capability. |
| `not-applicable` | The capability is outside that environment profile. |

`not-deployed` and `supported-not-verified` are never aliases for success.

The whole environment receives exactly one of:

- `qualified`: all mandatory profile checks passed;
- `waiting-runtime`: the required environment or endpoint is absent and the operation may be resumed later;
- `failed`: an available runtime violated identity, capability, safety, or semantic checks.

`waiting-runtime` is not `qualified` and must never be converted to success merely to keep a pipeline green.

## Environment matrix

| Environment | Live increment | Runtime ownership | v0.11.8 observation boundary |
| --- | --- | --- | --- |
| `local` | accepted predecessor evidence | operator-owned | read-only reuse; do not repeat destructive drills |
| `aws-dev` | v0.11.8.1 | operator-owned disposable runtime | read-only qualification |
| `aws-test` | v0.11.8.2 | operator-owned disposable runtime | release-bound read-only qualification |
| `aws-prod` | v0.11.8.3 | externally approved runtime | approval-protected read-only qualification |

The absence of a disposable AWS environment is a resumable wait. v0.11.8 never creates or destroys it automatically.

## Capability matrix rules

The evidence record contains independent entries for metrics, dashboards, alerts, logs, traces, SLOs, and progressive-delivery telemetry. A later live checker must derive each expected capability from the selected environment profile.

In particular:

- local Loki and Tempo acceptance does not prove that either backend exists in AWS;
- a Prometheus target alone does not prove Dashboard, alert, or SLO semantics;
- an exact Git revision does not prove that the running application carries the expected release identity;
- evidence from aws-dev cannot qualify aws-test or aws-prod.

## Exact identity lock

Every runtime evidence record binds the observation window to:

- environment name;
- AWS account and region for AWS profiles;
- cluster name and Kubernetes context;
- 40-character repository commit;
- immutable 40-character target revision;
- exact application version.

A branch name, `HEAD`, `latest`, or another moving alias cannot serve as final evidence. A mismatch fails the qualification rather than silently selecting another environment.

## Production read-only boundary

aws-prod observation requires an explicit approval before the first read. The approved process may validate identity, observe runtime state, and collect evidence. It may not:

- apply, patch, delete, restart, or synchronize Kubernetes resources;
- promote, abort, or retry a Rollout;
- dispatch a workflow or change Git;
- generate traffic or synthetic alerts;
- inject faults;
- create or destroy an environment.

The policy entry point is:

```bash
QUALIFICATION_ENVIRONMENT=aws-prod \
QUALIFICATION_ACTION=observe \
APPROVED_PRODUCTION_OBSERVATION=true \
  ./scripts/check-environment-observability-qualification-policy.sh
```

This script is a fail-closed action preflight, not a live qualification implementation.

## Evidence requirements

The schema at `delivery/contracts/v0.11.8.0-environment-observability-qualification-evidence.schema.json` defines the portable evidence envelope. Later increments add their exact check inventory without weakening it.

Evidence must contain UTC start and finish timestamps, exact identities, approval state, individual capability states, and explicit check outcomes. It must not contain credentials, bearer tokens, kubeconfig bytes, signed URLs, or unredacted secrets.

The reviewed evidence is append-only. Re-running qualification creates another observation record; it does not rewrite a failed historical observation into success.

## Offline acceptance

```bash
./scripts/validate-v0.11.8.0-environment-observability-qualification-foundation.sh
```

The validator exercises every allowed environment/action pair, rejects production observation without approval, rejects every mutation action, and tests evidence mutations that would conflate waiting, deployment, or verification states.
