# v0.11.8.1.3 AWS deployment entrypoint repair

## Incident: info57

The deployment guide used the endpoint maintenance script for first creation.
Preserving live logging required DescribeCluster before Terraform, so an absent
cluster failed before plan/apply. Static checks did not exercise this path.
ResourceNotFound also warrants checking account and region; do not equate
AccessDenied, network errors or expired credentials with an absent environment.

## Initial dev creation (billable, operator-controlled)

Remain on the current feature branch. Prepare and review
`infra/terraform/aws/environments/dev/terraform.tfvars` from the example if it
does not already exist; never overwrite existing variables or Terraform state.
Keep AWS_REGION aligned with the Terraform region. No workstation IP belongs
in Git. Review account identity and the Terraform plan before applying.

```bash
aws sts get-caller-identity
./scripts/validate-terraform.sh
EXPECTED_AWS_ACCOUNT_ID='<intended-12-digit-account>' \
AWS_REGION=us-east-1 \
CONFIRM_AWS_DEV_APPLY=create-ephemeral-aws-dev \
  ./scripts/apply-aws-dev.sh
```

The initial disposable dev log profile is explicitly `[]`. The script requires
an absent cluster and empty state, then asks for `apply-aws-dev` after planning.
If an apply partially succeeds, STOP and review the state and cloud resources.
Do not erase state or blindly rerun creation. This increment does not provide
automatic recovery of partial creation.

After EKS creation:

```bash
./scripts/validate-eks-baseline.sh
./scripts/validate-karpenter-foundation.sh
./scripts/bootstrap-eks-argocd.sh
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
  ./scripts/deploy-aws-dev-root-app.sh
```

Push the reviewed feature commit before Root deployment. The .8.1.2 dev overlay
aligns same-repository children. Follow its qualification and restoration
instructions. EXPECTED_APPLICATION_VERSION is the intended approved application
release identity from Git/release evidence, not a value automatically copied
from the live cluster to make a check pass. No application image rebuild is
required by this repair.

## Existing cluster: workstation/VPN IP change

```bash
AWS_ENVIRONMENT=aws-dev \
CONFIRM_EKS_API_CIDR_UPDATE=restrict-current-ip \
  ./scripts/apply-eks-api-access-cidr.sh
```

This preserves live log settings unless explicitly overridden. It plans the
whole Terraform root, not just the endpoint: review all planned changes before
invoking it. Missing clusters now produce an actionable creation hint.

## test is a separate environment, not a dev script flag

| Phase | dev | test |
| --- | --- | --- |
| Terraform root | environments/dev | environments/test |
| Infrastructure | apply-aws-dev.sh | apply-aws-test.sh |
| GitOps | bootstrap-eks-argocd.sh then deploy-aws-dev-root-app.sh | bootstrap-aws-test.sh |
| Source policy | current feature accepted for .8.1.2 | clean main required |

Existing stable test flow (reference only; NOT part of this increment):

```bash
CONFIRM_AWS_TEST_APPLY=apply-ephemeral-aws-test ./scripts/apply-aws-test.sh
CONFIRM_AWS_TEST_BOOTSTRAP=bootstrap-ephemeral-aws-test ./scripts/bootstrap-aws-test.sh
```

Both test scripts enforce a clean main worktree. Do not bypass this guard or
merge the unfinished feature merely to run them. See
`AWS_MULTI_ENVIRONMENT_LIFECYCLE.md` for preparation, promotion, evidence and
cleanup. Feature-based test qualification needs its own reviewed design.
No prod deployment or test resource creation is requested here.
