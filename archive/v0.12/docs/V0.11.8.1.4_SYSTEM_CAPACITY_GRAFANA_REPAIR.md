# v0.11.8.1.4 aws-dev system capacity and Grafana repair

Successor note: v0.11.8.1.5 makes the capacity CLI operational by default.
Use `--mode strict` for this document's historical per-node reserve predicate.
See `V0.11.8.1.5_CAPACITY_STATUS_WAIT_CLOSURE.md` for warnings and the read-only
node waiter. Do not repeat this historical migration after runtime recovery.

## Incident and scope

info58 showed independent Grafana Secret/checksum drift and an unavailable
Prometheus Operator. info59/60 proved both t3.medium system nodes held 17/17
Pods. Operator and two node-exporter Pods could not schedule. CPU requests
were 88%/73%; many controllers had zero requests, so these were not utilization
measurements. Increasing timeouts does not create Pod slots.

This repair uses four existing-type system nodes (additional EC2/EBS cost),
without changing CNI, maxPods, taints, database/application pools, test or prod.
The tracked dev auto.tfvars sets min/desired/max to 4; it overrides ordinary
terraform.tfvars, but CLI vars or later auto.tfvars can override it. All later
dev Terraform operations will consume it. This is not single-node-loss HA or
a guarantee of sufficient CPU/memory under load.

Grafana uses an independent create-once Kubernetes Secret, outside Helm/Argo
ownership. This is a bounded dev repair, not automatic credential rotation or
production external-secret management. The dev overlay only is changed.

## 1. Apply locally, validate, then prepare credentials BEFORE pushing

Run the package apply script and offline validator first. Do not push the
overlay until its prerequisite Secret exists: an auto-syncing Root may apply
the new reference immediately after push.

```bash
export EXPECTED_AWS_ACCOUNT_ID='<intended-12-digit-account>'
export AWS_REGION=us-east-1
aws sts get-caller-identity
aws eks update-kubeconfig --region "$AWS_REGION" --name startup-devops-baseline-dev
CONFIRM_GRAFANA_SECRET=prepare-aws-dev \
  ./scripts/prepare-aws-dev-grafana-secret.py
```

It preserves an existing target, otherwise copies only admin-user/admin-password
from the current Chart Secret, or generates credentials when no source exists.
It never prints values, copies tracking metadata, overwrites, or rotates an
existing target. API/RBAC failures stop the script. A malformed Secret stops
the operation. Do not include credentials in diagnostic attachments.

Grafana currently has persistence disabled. Its rollout discards local users,
sessions and manually saved dashboards; review/export needed user-created
content securely before proceeding. Git-provisioned dashboards are recreated.
The copied Kubernetes Secret might already differ from Grafana's initialized
database after prior drift; login after rollout uses the new stable Secret.

For a fresh cluster: create EKS, bootstrap Argo CD, run this Secret preparation,
THEN deploy the Root Application. Never automatically regenerate credentials
on every bootstrap. Destroying the cluster destroys this runtime Secret too.

## 2. Expand system capacity (explicit billable action)

```bash
CONFIRM_SYSTEM_SCALE=scale-aws-dev-to-four \
  ./scripts/scale-aws-dev-system-capacity.sh
```

The full Terraform plan must contain only an in-place scaling_config update
of module.eks.aws_eks_node_group.general. Unrelated changes, replacements,
unknown changes and scale-down are rejected. Live EKS CIDRs/logging are passed
through. No IP is committed. Review the plan and type the requested confirmation.
If rejected, investigate drift/variables; do not bypass by using -target.
Wait for four Ready system nodes:

```bash
kubectl get nodes -l workload=system -o wide
kubectl describe nodes -l workload=system
./scripts/check-aws-dev-system-capacity.py
```

The checker needs at least one free slot on EACH eligible node and eight total
reserve slots beyond unassigned relevant Pods. It is a conservative Pod-slot
check, not a complete scheduler simulation. Review CPU/memory requests, missing
requests, PVC zone constraints and events separately. A single large node does
not satisfy the four-node profile.

## 3. Relocation if old nodes remain full

Expansion does not rebalance running Pods. The two old nodes may retain 17/17,
blocking their node-exporters. Do not drain all nodes, remove taints, delete
stateful Pods, or force past a PDB. Work one old node at a time in a maintenance
window. Inspect its Pods, owner Deployment, replicas, readiness and PDBs:

```bash
kubectl get pdb -A
kubectl get pods -A -o wide
```

Choose one replaceable stateless controller Pod with another healthy replica
(for example the ALB controller, after checking its actual availability).
Cordon ONLY its exact old node, then submit an eviction through the eviction
API, which respects PDBs. Never use direct Pod deletion to bypass a refusal.
Keep a second terminal ready to uncordon the node if interrupted.

```bash
# Fill these from the live inventory; review before executing.
NODE='<one-full-system-node>'
POD_NAMESPACE='<reviewed-namespace>'
POD_NAME='<reviewed-replicated-stateless-pod>'
kubectl cordon "$NODE"
printf '{"apiVersion":"policy/v1","kind":"Eviction","metadata":{"name":"%s","namespace":"%s"}}' \
  "$POD_NAME" "$POD_NAMESPACE" | \
  kubectl create --raw "/api/v1/namespaces/$POD_NAMESPACE/pods/$POD_NAME/eviction" -f -
# Wait for the replacement on a new node and its owner Deployment to be Ready.
kubectl get pods -n "$POD_NAMESPACE" -o wide
kubectl uncordon "$NODE"
```

Do not proceed to the other node before recovery. One relocation may only
make room for node-exporter; repeat a separately reviewed relocation if the
per-node spare slot remains zero. If no safe replicated candidate exists,
stop and plan the required downtime instead of force-evicting.

## 4. Push, reconcile, and accept

After preparing the Secret, reviewing capacity and running local quality gates,
commit/push the feature branch. Do not merge main or change test/prod.

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline ./scripts/deploy-aws-dev-root-app.sh
kubectl -n observability get pods,pvc
kubectl -n observability rollout status deployment/observability-metrics-operator --timeout=10m
kubectl -n observability rollout status deployment/observability-metrics-grafana --timeout=10m
kubectl -n observability rollout status daemonset/observability-metrics-prometheus-node-exporter --timeout=10m
./scripts/check-aws-dev-system-capacity.py
argocd app get monitoring-aws-dev --hard-refresh
argocd app diff monitoring-aws-dev
```

Require Synced/Healthy, ready Prometheus/Alertmanager Pods, bound PVCs and no
relevant Pending Pods. Repeat hard-refresh/diff after another reconciliation;
admin-password and checksum/secret must no longer drift. Do not print passwords.
Run the existing .8.1.2 live qualification with the intended release identity
from Git, NOT a version copied from the current runtime to manufacture a pass.

## Recovery boundaries

The independent Secret is not pruned by Argo CD; the old Helm-owned Secret may
be pruned after reconciliation. Never delete the new Secret as cleanup while
Grafana references it. Reverting only the overlay restores the old random-secret
behavior, not a durable fix. Do not shrink the node group back to two while this
stack remains deployed. No automated drain or credential rollback is included.

When later restoring the .8.1.2 feature revision before main merge, remove ONLY
the targetRevision patch; retain the independent Grafana admin patch.
