# v0.11.8.2.1.2 — Existing test variables and saved-plan repair

Baseline: applied v0.11.8.2.1.1, on the existing feature branch. This repair
does not deploy anything, switch branches, touch dev/prod, edit local tfvars,
or change the example, Terraform profile, runtime manifests or application image.

## Troubleshooting case: valid local configuration rejected before plan

Symptoms: plan stopped with `Remove/review automatic variable file ... terraform.tfvars`;
an attempted apply then reported missing `review.json`.

Cause: the feature preparation guard rejected every automatically loaded tfvars
file. The reported local file retained the test example's shape, with a real
Owner tag and enabled persistent test runtime-role mapping. The blanket guard
was incompatible with that legitimate configuration. No successful plan meant
there was no completed review bundle for apply. These errors are not evidence
of an EKS deployment failure or a need to destroy the existing dev cluster.

The previous mock tests covered target/capacity and destructive-plan checks,
but not this existing-local-file workflow. This repair adds that regression.

## Supported input boundary

- Optional `infra/terraform/aws/environments/test/terraform.tfvars` stays in place.
  Terraform parses it; the helper does not attempt an incomplete HCL parser.
- Owner and other non-overridden settings remain Terraform inputs. This does
  not automatically approve every custom infrastructure setting: review the
  complete plan for naming, costs, resources and unintended changes.
- The explicitly loaded profile wins for capacity (4/4/4). CLI arguments pin
  environment, project, region and management /32. JSON plan checks remain active.
- Extra automatic variable files, JSON variant and symlinked local tfvars fail
  closed. Environment TF_VAR/TF_CLI_ARGS injection remains filtered.
- Enabled runtime identity requires the expected account's exact test Role ARN
  and the test EKS entry/group. Read-only `iam:GetRole` must succeed at plan and
  apply. A missing Role or denied lookup stops; do not disable identity or broaden
  permissions merely to bypass the guard. Review the existing identity setup.
  Existence alone does not prove IAM trust/policy correctness.
- The example's commented ARN is unchanged. Only a real local configuration
  should enable a real Role. No private tfvars or account identifiers ship here.
- The review records the optional file's presence and SHA256, not its contents.
  Added/removed/changed inputs, profile drift, stale plans and legacy bundles fail.
  Hashes protect against accidental drift, not malicious rewriting of both the
  plan and review record; retain private bundle storage and trusted operators.

## Recovery

1. Apply the patch, run the offline/full local gates, review and commit/push on
   `feature/v0.11-observability-sre-baseline`. Do not merge/switch to main for this.
2. Keep existing reviewed test tfvars and independent test state. Do not overwrite
   the real settings using the example, or delete/move state to bypass a guard.
3. Re-export `EXPECTED_CONTROL_PLANE_SHA` after committing. Set the reviewed
   account and current public IPv4 per the main runbook.
4. Create a fresh timestamped bundle and run plan. Use create only if test state
   is empty and the test cluster absent; resume needs existing test state. An
   existing dev cluster is independent and may remain running.
5. Continue to apply only after `Plan saved:` and human review, within one hour.
   Missing review files require a successful fresh plan, never hand-written JSON.
6. Bootstrap and read-only qualification remain separate existing runbook steps.

## Verification boundary

`validate-v0.11.8.2.1.2-test-variable-input-repair.sh` runs mocked positive/negative
tests plus the existing feature and preview regressions. It does not invoke AWS
or Terraform. Actual HCL/provider resolution and live IAM/EKS behavior must be
validated locally through reviewed plan/apply. A renderer SKIP is not a pass.
