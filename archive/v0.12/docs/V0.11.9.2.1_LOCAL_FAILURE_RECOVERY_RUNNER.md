# v0.11.9.2.1 Local failure/recovery runner implementation

## Status and safety boundary

This increment implements the reviewed v0.11.9.2.0 local-only fault gate,
bounded traffic helper and phase runner. Producer validation is offline/mocked:
no image was built, no cluster was contacted, no traffic was generated and no
Rollout was changed. Live execution is deferred to v0.11.9.2.2 and requires a
separate explicit decision after this code is reviewed, committed and pushed.

The implementation never promotes. It never automatically retries, aborts,
rolls back, cleans evidence or selects a recovery identity. Each mutating phase
has a distinct confirmation phrase and an append-only passed marker.

## Implemented fault isolation

`demo-api` now accepts two environment variables:

- `REHEARSAL_FAULT_MODE`, default `disabled`;
- `REHEARSAL_FAULT_TOKEN_SHA256`, default empty.

Enabled mode is rejected unless `APP_ENV=local`, the mode is exactly
`availability-503`, and the token digest is 64 lowercase hexadecimal characters.
Only `/version` requests carrying the exact `X-Rehearsal-Fault` token return 503.
The token comparison is constant-time. Health/readiness endpoints and ordinary
requests are unchanged. Disabled mode rejects a leftover digest.

The runner generates a per-run token in the private evidence bundle with mode
`0600`. The raw token is never a command-line argument or terminal/log field.
The traffic helper supplies it through a protected temporary curl header file
and removes that file with its owned port-forward processes on exit.

## Preconditions for the later v0.11.9.2.2 live run

Do not execute the phases below merely to validate this increment. At the live
checkpoint, first establish the newly built fault-capable image as a successful,
fault-disabled baseline using the v0.11.9.1.1 successful-release runbook. This
is necessary because the failing candidate must reuse the exact baseline image
reference and runtime imageID.

Before creating a plan, require all of the following:

- clean pushed feature HEAD and exact source SHA;
- loopback `kind-...` context and Healthy Rollout;
- fault-disabled Ready stable Pods;
- successful baseline version/release/rollout UID/image reference/runtime imageID;
- no active AnalysisRun and no incomplete Rollout;
- review reference, operator, recovery owner and recovery deadline;
- a new private evidence directory outside the repository.

## Build the private plan

Use a separate shell only after live execution is approved:

```bash
cd ~/startup-devops-baseline
PLAN_PARENT=$(mktemp -d /tmp/local-failure-recovery-plan.XXXXXX)
PLAN_FILE="$PLAN_PARENT/plan.json"
cp delivery/examples/v0.11.9.2.0-local-failure-recovery-plan.json "$PLAN_FILE"
chmod 600 "$PLAN_FILE"
```

Gather read-only identity values with an explicit context:

```bash
kubectl --context "$LOCAL_CONTEXT" -n startup-apps get rollout demo-api \
  -o json >"$PLAN_PARENT/rollout.json"
kubectl --context "$LOCAL_CONTEXT" -n startup-apps get pods \
  -l app.kubernetes.io/name=demo-api -o json >"$PLAN_PARENT/pods.json"

jq '{uid:.metadata.uid,
     version:.metadata.annotations["platform.startup.dev/application-version"],
     releaseId:.metadata.annotations["platform.startup.dev/release-id"],
     stableRS:.status.stableRS,
     phase:.status.phase}' "$PLAN_PARENT/rollout.json"

jq '[.items[] | {
  name:.metadata.name,
  version:.metadata.annotations["platform.startup.dev/application-version"],
  releaseId:.metadata.annotations["platform.startup.dev/release-id"],
  image:.spec.containers[0].image,
  imageID:.status.containerStatuses[0].imageID,
  ready:any(.status.conditions[]?; .type=="Ready" and .status=="True")
}]' "$PLAN_PARENT/pods.json"
```

Fill every `REPLACE` field and set `evidence_directory` to a new path such as
`/tmp/local-failure-recovery.ABC123/run`. Validate it offline:

```bash
python3 scripts/check-v0.11.9.2.0-failure-recovery-plan.py \
  --plan "$PLAN_FILE"
```

The result must still say `execution_authorized: false`; approval remains an
external human decision.

## Phase command map for v0.11.9.2.2

The commands are listed now so the implementation can be reviewed. Do not run
them as part of v0.11.9.2.1 acceptance.

| Order | Phase | Mutation | Required visible result before continuing |
| --- | --- | --- | --- |
| 1 | `prepare` | None | `prepare passed`; token file is private |
| 2 | `arm` | Deploys candidate-only fault configuration | `arm passed`; candidate Ready, stable fault-disabled |
| 3 | `traffic` | Bounded HTTP requests only | exact measured availability AnalysisRun failure |
| 4 | `rejection-review` | None | reviewer accepts rejection evidence and stable isolation |
| 5 | manual abort if needed | Explicit Rollout abort | status reports `abort: true` |
| 6 | `abort-check` | None | aborted candidate observed |
| 7 | `recovery-approval` | Approval record only | recovery owner authorizes exact baseline |
| 8 | `restore` | Restores GitOps baseline version and disables fault | desired baseline/fault-disabled template observed |
| 9 | manual retry if needed | Explicit Rollout retry after desired-state review | Rollout begins baseline convergence |
| 10 | `final` | None | Healthy runtime plus retained failed AnalysisRun |

Set the bundle path once per terminal. Enter only the path, not
`REHEARSAL_DIR=/tmp/...` at the prompt:

```bash
read -r -p 'Private evidence bundle path: ' REHEARSAL_DIR
```

Commands:

```bash
python3 scripts/local-failure-recovery-rehearsal.py prepare \
  --plan "$PLAN_FILE" --bundle "$REHEARSAL_DIR" --confirm observe-local

python3 scripts/local-failure-recovery-rehearsal.py arm \
  --bundle "$REHEARSAL_DIR" --confirm deploy-reviewed-local-fault-candidate

python3 scripts/local-failure-recovery-rehearsal.py traffic \
  --bundle "$REHEARSAL_DIR" --confirm generate-reviewed-candidate-fault-traffic

python3 scripts/local-failure-recovery-rehearsal.py rejection-review \
  --bundle "$REHEARSAL_DIR" --review "$REVIEW_REF" --confirm observe-local
```

After reviewing the retained evidence, inspect abort state:

```bash
kubectl --context "$LOCAL_CONTEXT" -n startup-apps get rollout demo-api \
  -o json | jq '{phase:.status.phase,abort:.status.abort,currentStepIndex:.status.currentStepIndex}'
```

If analysis semantics have not already set `abort: true`, and only after the
reviewer decides the candidate must be aborted, run exactly once:

```bash
kubectl argo rollouts abort demo-api \
  -n startup-apps --context "$LOCAL_CONTEXT"
```

Then continue:

```bash
python3 scripts/local-failure-recovery-rehearsal.py abort-check \
  --bundle "$REHEARSAL_DIR" --confirm observe-local

python3 scripts/local-failure-recovery-rehearsal.py recovery-approval \
  --bundle "$REHEARSAL_DIR" --review "$REVIEW_REF" \
  --confirm approve-reviewed-local-recovery

python3 scripts/local-failure-recovery-rehearsal.py restore \
  --bundle "$REHEARSAL_DIR" --confirm restore-reviewed-local-baseline
```

Review the desired Rollout template before any retry:

```bash
kubectl --context "$LOCAL_CONTEXT" -n startup-apps get rollout demo-api -o json |
  jq '{version:.metadata.annotations["platform.startup.dev/application-version"],
       faultMode:(.spec.template.spec.containers[0].env[] |
         select(.name=="REHEARSAL_FAULT_MODE").value),
       faultDigest:(.spec.template.spec.containers[0].env[] |
         select(.name=="REHEARSAL_FAULT_TOKEN_SHA256").value),
       phase:.status.phase,abort:.status.abort}'
```

It must show the exact planned baseline version, `faultMode: disabled` and an
empty digest. If the Rollout remains aborted and the recovery owner explicitly
approves resumption, run once:

```bash
kubectl argo rollouts retry rollout demo-api \
  -n startup-apps --context "$LOCAL_CONTEXT"
```

Finally:

```bash
python3 scripts/local-failure-recovery-rehearsal.py final \
  --bundle "$REHEARSAL_DIR" --confirm observe-local
```

## Live logs and stop rules

Each runner phase prints its attempt directory. Observe the active command log:

```bash
ATTEMPT_DIR=$(find "$REHEARSAL_DIR" -mindepth 1 -maxdepth 1 -type d \
  -name '*-*' -printf '%T@ %p\n' | sort -n | tail -1 | cut -d' ' -f2-)
tail -n 100 -f "$ATTEMPT_DIR/command.log"
```

Inspect without mutation:

```bash
kubectl --context "$LOCAL_CONTEXT" -n startup-apps get rollout demo-api -o wide
kubectl --context "$LOCAL_CONTEXT" -n startup-apps get analysisruns \
  --sort-by=.metadata.creationTimestamp
kubectl --context "$LOCAL_CONTEXT" -n startup-apps get pods \
  -l app.kubernetes.io/name=demo-api -o wide
```

Stop immediately if stable control requests fail, Pod identities/configuration
do not match, the wrong metric fails, the AnalysisRun is Error/Inconclusive,
the candidate becomes stable, or any deadline expires. Preserve the bundle and
failed AnalysisRun. Never delete passed markers, retry until green, repeat abort,
promote the failed candidate or guess a recovery identity.
