## Canonical two-terminal sequence

Choose one new application version and use the same value in both terminals.
Start the first observer before deploying the new revision:

```bash
export RECOVERY_VERSION='v0.11.9.2.2.3-recovery-<commit-prefix>'

EXPECTED_APPLICATION_VERSION="$RECOVERY_VERSION" \
MINIMUM_MATCHING_ANALYSIS_RUNS=1 \
bash scripts/check-local-slo-aware-rollout-analysis.sh
```

In the deployment terminal, deploy one pushed immutable source revision and an
image already loaded into kind:

```bash
TARGET_REVISION='<full-pushed-commit-sha>' \
IMAGE_REPOSITORY='startup-devops-baseline/demo-api' \
IMAGE_TAG='<loaded-local-image-tag>' \
APPLICATION_VERSION="$RECOVERY_VERSION" \
REHEARSAL_FAULT_MODE='disabled' \
REHEARSAL_FAULT_TOKEN_SHA256='' \
bash scripts/deploy-local-feature-gitops.sh
```

The first observer must report a ready Prometheus target, bounded traffic and a
successful AnalysisRun. Confirm the Rollout is at its reviewed 50 percent pause:

```bash
kubectl argo rollouts get rollout demo-api -n startup-apps
```

Then start the second observer:

```bash
EXPECTED_APPLICATION_VERSION="$RECOVERY_VERSION" \
MINIMUM_MATCHING_ANALYSIS_RUNS=2 \
bash scripts/check-local-slo-aware-rollout-analysis.sh
```

Do not promote merely because the Rollout is paused. Wait until the second
observer prints both of these signals:

```text
Prometheus target identity is ready for <release-id>.
==> Generating bounded traffic across Prometheus scrape intervals
```

Only then may the human operator promote once:

```bash
kubectl argo rollouts promote demo-api -n startup-apps
```

The namespace flag belongs after the plugin command. The following form is
invalid because kubectl interprets the flag before resolving the plugin:

```text
kubectl -n startup-apps argo rollouts promote demo-api
```

Keep the observer running until it reports the second successful AnalysisRun.
Finally require terminal health and matching stable/current hashes:

```bash
kubectl argo rollouts status demo-api -n startup-apps --timeout 5m

kubectl -n startup-apps get rollout demo-api -o json | jq '{
  phase: .status.phase,
  abort: (.status.abort // false),
  stableRS: .status.stableRS,
  currentPodHash: .status.currentPodHash,
  version: .metadata.annotations["platform.startup.dev/application-version"],
  releaseId: .metadata.annotations["platform.startup.dev/release-id"]
}'

argocd app get startup-devops-root
argocd app get demo-api
argocd app diff startup-devops-root
argocd app diff demo-api
```

An empty `argocd app diff` is the successful no-drift result. Historical failed
AnalysisRuns remain visible and require no cleanup.

Applying or validating this increment performs no Kubernetes, Rollout, traffic
or AWS operation.
