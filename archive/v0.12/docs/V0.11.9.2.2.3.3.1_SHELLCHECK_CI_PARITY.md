# v0.11.9.2.2.3.3.1 ShellCheck CI parity

## Finding

Image-publish workflow run `34035241036` stopped in `quality-gates`. The image
build-and-push and promotion jobs were skipped, so the run produced neither a
new baseline image nor a promotion change.

The focused baseline-restoration validator skipped ShellCheck on a workstation
where the command was unavailable. GitHub Actions had ShellCheck installed and
reported `SC1091`, `SC2097`, `SC2098`, and `SC2015`. This was deterministic
local/CI tool-parity debt, not a transient workflow failure.

## Repair

The validator now invokes `shellcheck -x`, allowing it to follow the explicitly
reviewed `scripts/lib/argocd-operation.sh` source declaration. The restoration
script captures the validated target revision before constructing the child
process environment, so `TARGET_REVISION` and `GIT_TARGET_REVISION` receive the
same value without assignment-order ambiguity. The second-analysis 50% pause
guard is an explicit `if` statement instead of an `A && B || C` expression.

These changes preserve runtime behavior. Validation is offline and performs no
Kubernetes operation, Rollout retry, promotion, traffic generation, image
publication or AWS operation.

## Operator boundary

After applying this increment, run the focused validator and the complete CI
quality gates on a workstation with ShellCheck installed. Commit and push only
after both pass. Then start a new image-publish workflow run; do not rerun the
failed job from run `34035241036`, because it was bound to the superseded source
commit. Revision 69 remains failed evidence and must not be retried or promoted.
