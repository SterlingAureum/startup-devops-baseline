# v0.11.9.2.2.3.3 request-series image compatibility

## Revision 69 finding

Revision 69 restored the historical `sha-3e50802` image. Prometheus reported
the exact Candidate target as up, and the observer generated bounded traffic,
but all three release-scoped Candidate request queries returned empty vectors.
The first AnalysisRun failed and Argo Rollouts safely aborted the revision.
Revision 68 remained the stable, available runtime.

Target readiness is therefore necessary but insufficient. `up` proves that
Prometheus can scrape a target carrying the expected identity; it does not
prove that the selected application image exposes the labels and metric shape
required by the current AnalysisTemplate.

Revision 69 and its failed AnalysisRun are retained as rejection evidence.
Do not promote or retry revision 69.

## Repair

The bounded-traffic observer now waits for a positive `/version` request count
with the exact Candidate release ID after traffic begins. A target that is up
without that request series produces an explicit image-compatibility error.

The baseline-restoration wrapper snapshots AnalysisRun UIDs when each observer
starts. Only a run created after that snapshot can satisfy the checkpoint. This
removes dependence on historical ordinal counts when an application version or
release ID is reused. `first-analysis` can now be armed before the restoration
changes the Rollout version.

The pre-merge restoration entrypoint rejects the live-proven incompatible
`sha-3e50802` default before invoking any Kubernetes restoration operation.
Restoration stays blocked until a newly published immutable image passes the
current metric contract and replaces that tag in the declarative baseline.

## Next operator boundary

Applying and validating this increment does not publish an image, change the
cluster, retry the Rollout, generate traffic or restore the baseline. After it
is committed, the next separately reviewed step is to publish a current
demo-api image through the existing image workflow, capture its digest, update
the declarative baseline, and qualify a fresh Rollout revision with the two
observer checkpoints.
