## Why this is separate from creation

`scripts/apply-aws-dev.sh` deliberately enters Terraform plan/apply and creates
billable infrastructure after two confirmations. It is not a discovery tool.
The v0.11.9.3.5 entrypoint never invokes it, Terraform, kubectl or Argo CD.

The preflight checks only whether a later, separately approved create phase can
be considered. A successful result still contains:

```json
"execution_authorized": false
```

## Read-only live preflight

Run from a clean local `main` whose `HEAD` equals `origin/main` and the plan's
full `control_plane_commit`:

```bash
CONFIRM_AWS_DEV_PREFLIGHT='observe-reviewed-aws-dev-rehearsal' \
  python3 scripts/preflight-v0.11.9.3.5-aws-dev-live-rehearsal.py \
    --plan "$PLAN_FILE"
```

The only AWS API operations are:

- `sts get-caller-identity`
- `eks list-clusters`

The local dev Terraform state is parsed directly. Only file existence,
resource-block count, instance count and whether it owns an EKS cluster are
reported. State attributes and outputs are never emitted.

## Result states

`ready-for-separate-aws-dev-create-approval` means all three rehearsal clusters
are absent and the expected dev state is absent or empty. It does not execute or
authorize creation.

The preflight exits `2` for an operationally blocked inventory:

- aws-test or aws-prod is active;
- more than one rehearsal environment is active;
- aws-dev exists without its expected Terraform ownership;
- aws-dev already exists and requires a reviewed resume/maintenance decision;
- local dev state is nonempty while its EKS cluster is absent.

Preserve nonempty state. Never delete it to make a create check pass. A command,
credential, plan, permission, Git identity or response error exits `1` and must
not be interpreted as proof of absence.
