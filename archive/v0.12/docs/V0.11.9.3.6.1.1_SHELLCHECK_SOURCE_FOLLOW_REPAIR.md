# v0.11.9.3.6.1.1 ShellCheck source-follow repair

## Failure

The `.3.6.1` focused validator supplied
`scripts/apply-eks-api-access-cidr.sh` to ShellCheck without enabling external
source following. The script already declared its controlled dependency:

```text
# shellcheck source=scripts/aws-environment-context.sh
```

ShellCheck therefore emitted `SC1091` when it reached the dynamic absolute
`source` expression. This was a deterministic validation defect, not an AWS,
Terraform or executor failure.

## Repair

The focused validator now runs `shellcheck -x` from the repository root. The
source annotation remains unchanged, so ShellCheck can resolve and inspect the
repository-controlled dependency without weakening the check.

The successor validator substitutes a recording ShellCheck executable and
runs the predecessor entrypoint. It asserts that the final lint invocation
contains `-x` and the expected apply script. This regression runs even on a
machine where the real ShellCheck binary is absent. When ShellCheck is
installed, the same scripts are also linted directly with `-x`.

## Boundary

This increment changes validation only. It does not run the private preflight,
the create executor, Terraform, AWS, Kubernetes, Argo CD, traffic generation or
teardown. The separately reviewed `.3.6.2` execution checkpoint remains the
next live-action boundary.

Validate with:

```bash
bash scripts/validate-v0.11.9.3.6.1.1-shellcheck-source-follow-repair.sh
bash scripts/validate-v0.11.9.3.6.1-aws-dev-live-rehearsal-create-executor.sh
```
