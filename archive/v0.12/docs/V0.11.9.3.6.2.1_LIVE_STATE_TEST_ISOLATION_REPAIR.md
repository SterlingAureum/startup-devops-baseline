# v0.11.9.3.6.2.1 live-state test isolation repair

## Failure

After the successful aws-dev infrastructure creation, the local Terraform
state contains 103 addresses. The historical
`test_complete_ready_preflight_uses_mocked_read_only_discovery` test mocked Git
and AWS discovery but passed the real repository root to production preflight.
Its unmocked `summarize_state` call therefore read the live nonempty state.

The test combined a mocked empty EKS inventory with a real nonempty Terraform
state. Production correctly classified that inconsistent input as
`blocked-partial-aws-dev-state` and returned exit code 2, while the historical
test incorrectly expected a ready result and exit code 0.

## Repair

The test now also replaces `PREFLIGHT.summarize_state` with its explicit
`self.empty_state` fixture. It asserts that the intercepted call used the exact
repository-relative dev state path. This completes the test boundary: Git,
AWS and filesystem state are all deterministic mocked inputs.

Production preflight is not changed. Its fail-closed behavior for a real absent
cluster plus nonempty or partial state remains intact.

## Live-environment boundary

Applying and validating this repair does not read or change the live Terraform
state. It performs no AWS, Terraform, Kubernetes, Argo CD, creation, bootstrap,
qualification or teardown command. The `.3.6.2` EKS creation evidence remains
unchanged, and the live environment must not be recreated merely to satisfy a
unit test.

Validate with:

```bash
python3 scripts/test-v0.11.9.3.5-aws-dev-live-rehearsal-preflight.py
bash scripts/validate-v0.11.9.3.6.2.1-live-state-test-isolation-repair.sh
```
