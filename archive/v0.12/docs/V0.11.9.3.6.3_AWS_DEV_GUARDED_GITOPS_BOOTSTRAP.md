# v0.11.9.3.6.3 aws-dev guarded GitOps bootstrap

## Outcome

This checkpoint implements, but does not execute, the next live aws-dev
rehearsal phase. It operates on the EKS environment recorded by `.3.6.2` and
repairs the previous bootstrap's mutable Argo CD default.

The executor has two explicit phases:

- `verify` performs only reviewed AWS, Terraform and Kubernetes reads;
- `execute` repeats the same fail-closed inventory and then invokes
  `scripts/bootstrap-eks-argocd.sh` once.

Argo CD is pinned to exact release `v3.5.2`. The generic bootstrap rejects
`stable`, `latest` and other non-`vMAJOR.MINOR.PATCH` selectors, while an
explicit exact release remains possible for separately reviewed workflows.

## Preconditions

Use the later commit produced after this increment has passed CI and reached
protected `main`; do not use the package's implementation baseline SHA as the
live target. The executor requires all of the following:

- current branch is `main`;
- worktree is clean;
- `HEAD`, `origin/main` and the supplied reviewed SHA are identical;
- `EXPECTED_AWS_ACCOUNT_ID` is a private 12-digit input and matches STS;
- `startup-devops-baseline-dev` is `ACTIVE` in `us-east-1`;
- the current kubectl server exactly matches that EKS cluster endpoint;
- the dev Terraform state contains exactly the recorded 103 addresses and an
  EKS cluster address;
- Kubernetes `/readyz` returns exactly `ok`;
- namespace `argocd` is absent;
- ALB controller and Karpenter role outputs belong to the reviewed account;
- the Terraform VPC output has a valid `vpc-...` form.

If the Argo CD namespace already exists, stop. This is treated as possible
partial bootstrap state and is never automatically resumed or overwritten.

## Later read-only verification

Only after the increment is committed, pushed, merged and the protected-main
checks succeed:

```bash
git switch main
git pull --ff-only origin main

export EXPECTED_CONTROL_PLANE_COMMIT="$(git rev-parse HEAD)"
export EXPECTED_AWS_ACCOUNT_ID='<reviewed 12-digit account>'
export CONFIRM_AWS_DEV_GITOPS_PREFLIGHT='observe-reviewed-aws-dev-gitops-bootstrap'

python3 scripts/execute-v0.11.9.3.6.3-aws-dev-gitops-bootstrap.py \
  verify \
  --expected-control-plane-commit "${EXPECTED_CONTROL_PLANE_COMMIT}"
```

Review the JSON. Expected status is
`aws-dev-gitops-bootstrap-inputs-verified`, `execution_authorized` remains
`false`, the state count is 103 and `argocd_namespace_present` is `false`.
Account ID, role ARNs, VPC ID and Terraform addresses are intentionally not
emitted.

## Separately approved execution

The verify result does not authorize writes. After explicit review and a new
approval in the active session, retain the observation confirmation and set:

```bash
export CONFIRM_AWS_DEV_GITOPS_BOOTSTRAP='bootstrap-reviewed-aws-dev-gitops'

python3 scripts/execute-v0.11.9.3.6.3-aws-dev-gitops-bootstrap.py \
  execute \
  --expected-control-plane-commit "${EXPECTED_CONTROL_PLANE_COMMIT}"
```

The execution configures kubeconfig, creates and annotates the two IRSA
ServiceAccounts, installs Argo CD `v3.5.2`, waits for its core controllers and
applies the AWS Load Balancer Controller Application rendered with the
Terraform VPC ID. There is no automatic retry.

Successful output ends with:

```text
"status": "aws-dev-gitops-bootstrap-complete"
"root_application_deployed": false
"runtime_qualified": false
"next_action": "review-separate-root-application-deploy"
```

## Boundary retained

This checkpoint does not invoke `deploy-aws-dev-root-app.sh`. It does not
create the Root Application, reconcile demo-api, generate traffic, run runtime
qualification, replay a fault, promote aws-test or destroy aws-dev. Those are
separate decisions. If execution fails after creating namespace `argocd`,
preserve Terraform state and inspect the partial cluster state before any
retry or teardown.
