# v0.11.9.3.6.4.3 AWS environment teardown convergence

## Outcome

This checkpoint repairs the shared disposable aws-dev/aws-test teardown after
the first complete v0.11 aws-dev rehearsal exposed three asynchronous AWS
dependency classes. The repair is offline-tested and does not claim that its
new path has already completed another live teardown.

`scripts/destroy-aws-test.sh` remains a thin wrapper around
`scripts/destroy-aws-dev.sh`; therefore both disposable environments receive
the same convergence behavior. The entrypoint continues to refuse aws-prod.

## Observed closure

The approved aws-dev teardown started from 103 Terraform state addresses. The
first interactive logging wrapper did not deliver the exact Terraform
confirmation and left all 103 addresses unchanged. A real destroy then reached
two state addresses but a detached `aws-K8S-*` ENI blocked one private subnet.
After that dependency was removed, Terraform reached one state address but an
unreferenced EKS-created security group blocked VPC deletion. Terraform then
reached zero state addresses; the residual-cost audit correctly rejected two
detached dynamic-PVC EBS volumes. Exact guarded cleanup removed them.

The next-day read-only audit passed with zero Terraform state addresses and no
continuing cluster, network, compute, volume, load-balancer, bucket,
certificate, DNS or tagged-resource identity. Four terminal EC2 Fleet records
were accepted as non-actionable history. Raw logs and AWS resource IDs remain
private; the repository records only three private-log SHA-256 fingerprints,
dependency classes and bounded counts.

## Repaired sequence

The shared destroy entrypoint now:

1. captures every EBS-backed PV/PVC identity before pruning starts;
2. preserves the existing CNPG-first and Karpenter controller ordering;
3. waits for Root Application finalizer-driven child pruning;
4. explicitly deletes all captured EBS-backed PVCs;
5. invokes a fail-closed dependency helper before Terraform;
6. deletes only exact detached dynamic-PVC volumes and exact detached
   `aws-K8S-*` ENIs whose parent instance is terminal or absent;
7. runs the operator-reviewed interactive Terraform destroy plan;
8. if Terraform fails with only VPC/subnet state remaining, requires EKS to be
   absent, deletes at most one exact unreferenced EKS-created cluster security
   group, and inventories remaining VPC dependencies;
9. retries Terraform only after the inventory is empty. Terraform presents a
   new plan and requires the operator to type `yes` again;
10. repeats bounded dynamic-volume cleanup after Terraform success before the
    existing Fleet retirement and residual-cost audit handoff.

The helper never deletes attached volumes, attached/requester-managed ENIs,
security groups with ENI or rule references, unknown non-default security
groups, live instances, NAT Gateways, VPC endpoints, load balancers, target
groups, Internet Gateways, custom network ACLs or non-main route tables. Any
such identity blocks retry and requires a new review.

## Interactive logging

Do not pipe the interactive destroy command itself through `tee`. That can
change Terraform stdin semantics. Run it directly, or use a real pseudo-TTY
when a private transcript is required:

```bash
script --quiet --return \
  --command \
  "env AWS_ENVIRONMENT=aws-dev CONFIRM_AWS_ENVIRONMENT_DESTROY=destroy-with-backups bash scripts/destroy-aws-dev.sh" \
  /path/outside-the-repository/aws-dev-destroy.log
```

The transcript can contain resource identities and must remain outside Git
with mode `0600`. Terraform still requires exact interactive `yes` input for
each plan.
