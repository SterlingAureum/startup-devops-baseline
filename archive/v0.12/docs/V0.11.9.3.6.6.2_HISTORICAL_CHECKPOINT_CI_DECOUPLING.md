# v0.11.9.3.6.6.2 historical checkpoint CI decoupling

## Problem

The v0.11.9.3.2 readiness validator preserved an exact aws-test release hash
and also ran in current CI. A legitimate reviewed aws-dev to aws-test promotion
therefore failed an obsolete snapshot assertion.

## Repair

The historical contract remains unchanged as evidence of the state reviewed at
that checkpoint. Its validator now applies two different policies:

- aws-test is delegated to the current reviewed successor allowlist;
- aws-prod remains pinned to the historical release bytes and must not contain
  the candidate identity before a separate production promotion.

Unknown, partial, or mixed aws-test identities remain rejected. This repair does
not authorize a workflow dispatch, PR merge, cluster operation, or teardown.

## Productization rule

Customer-facing baselines should keep historical contracts as audit artifacts,
but the default CI path should enforce current invariants and permitted state
transitions. Milestone snapshot validators belong in an archive or explicit
audit suite once their state has been superseded. This repository retains the
older checkpoint in CI for now because later contracts still inherit it; the
delegation removes its obsolete mutable-state assertion without discarding the
remaining revision, trust-boundary, and production guards.
