# v0.11.9.3.6.6.5 aws-dev teardown preflight

This checkpoint adds a dedicated read-only preflight before the destructive
aws-dev wrapper. It verifies exact main, the expected private account, the
one-active-environment boundary, Terraform ownership, and backup-bucket
presence. Its JSON deliberately omits the account, VPC, bucket, endpoint, ARN,
and other resource identities.

The operator must keep `EXPECTED_AWS_ACCOUNT_ID` private and must leave
`CONFIRM_AWS_ENVIRONMENT_DESTROY` unset. Run only after this increment is merged:

```bash
umask 077
export EXPECTED_CONTROL_PLANE_COMMIT='<exact merged main SHA>'
export EXPECTED_AWS_ACCOUNT_ID='<private 12-digit account ID>'
unset CONFIRM_AWS_ENVIRONMENT_DESTROY
export TEARDOWN_PREFLIGHT_DIR="$(mktemp -d /tmp/v011936665-aws-dev.XXXXXX)"

CONFIRM_AWS_DEV_TEARDOWN_PREFLIGHT='observe-reviewed-aws-dev-teardown-preflight' \
python3 scripts/preflight-v0.11.9.3.6.6.5-aws-dev-teardown.py verify \
  --expected-control-plane-commit "$EXPECTED_CONTROL_PLANE_COMMIT" \
  >"$TEARDOWN_PREFLIGHT_DIR/preflight.json" \
  2>"$TEARDOWN_PREFLIGHT_DIR/preflight.stderr"
```

Review the exit code, redacted JSON, empty stderr, hashes, and `700/600`
permissions before requesting a separate destructive approval. Do not reuse the
old runtime-qualification time window.
