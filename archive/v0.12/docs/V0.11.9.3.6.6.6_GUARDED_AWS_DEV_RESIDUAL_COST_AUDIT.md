# v0.11.9.3.6.6.6 guarded aws-dev residual-cost audit

## Purpose

This checkpoint implements—but does not execute—the read-only residual-cost
audit required after the recorded aws-dev teardown and before any aws-test
infrastructure creation.

The historical `scripts/validate-aws-cost-cleanup.sh` remains unchanged for
older lifecycle and runbook compatibility. Its direct output can contain AWS
resource identities, and its optional Terraform-state branch can treat a
failed state read as empty. Direct invocation is therefore not accepted as
v0.11.9.3.6.6 audit evidence. The guarded path adds exact-account and strict
state-read checks before invoking that existing comprehensive sweep once.

Applying and validating this package performs no GitHub, AWS, Terraform,
Kubernetes or residual-cost-audit operation.

## Guarded model

The preflight requires:

- clean `main` with `HEAD` and `origin/main` equal to one reviewed full SHA;
- `AWS_ENVIRONMENT=aws-dev` and the private expected 12-digit account ID;
- byte-exact `.5.2` teardown evidence and existing audit entrypoint;
- no active aws-dev, aws-test or aws-prod rehearsal EKS cluster;
- a successful Terraform backend read with zero aws-dev state resources;
- an authoritative bucket listing proving the expected backup bucket absent;
- an authoritative Secrets Manager listing proving the runtime secret absent
  or present only as a recovery-window tombstone;
- all create and destroy confirmations unset.

The returned JSON is redacted. It emits neither the account ID nor resource
identities and authorizes no execution.

The executor binds that reviewed preflight file to a UTC window no longer than
four hours with at least fifteen minutes remaining. `verify` reruns the
preflight but never invokes the full audit. `execute` additionally requires:

```text
CONFIRM_AWS_DEV_RESIDUAL_COST_AUDIT_EXECUTION=execute-reviewed-aws-dev-residual-cost-audit
```

It runs the existing audit once, with no automatic retry. Raw stdout and
stderr are written as new `0600` files beneath an existing `0700` private
directory. Public JSON contains only pass/fail state, counts, file hashes and
explicit no-mutation boundaries. A failure returns nonzero and hands off to
private-log inspection plus a new review.

## Post-merge preflight

Do not run this from the implementation commit. After the increment reaches
protected main, use that new exact SHA:

```bash
umask 077
export AWS_ENVIRONMENT='aws-dev'
export EXPECTED_CONTROL_PLANE_COMMIT='<exact new protected-main SHA>'
export EXPECTED_AWS_ACCOUNT_ID='<private 12-digit account ID>'
export CONFIRM_AWS_DEV_RESIDUAL_COST_AUDIT_PREFLIGHT='observe-reviewed-aws-dev-residual-cost-audit-preflight'
unset CONFIRM_AWS_ENVIRONMENT_DESTROY
unset CONFIRM_AWS_DEV_TEARDOWN_EXECUTION
unset CONFIRM_AWS_DEV_APPLY
unset CONFIRM_AWS_TEST_APPLY

export RESIDUAL_AUDIT_PRIVATE_DIR="$(mktemp -d /tmp/v011936666-aws-dev.XXXXXX)"
export RESIDUAL_AUDIT_PREFLIGHT_JSON="$RESIDUAL_AUDIT_PRIVATE_DIR/preflight.json"

python3 scripts/preflight-v0.11.9.3.6.6.6-aws-dev-residual-cost-audit.py verify \
  --expected-control-plane-commit "$EXPECTED_CONTROL_PLANE_COMMIT" \
  >"$RESIDUAL_AUDIT_PREFLIGHT_JSON" \
  2>"$RESIDUAL_AUDIT_PRIVATE_DIR/preflight.stderr"
```

Review the exit code, redacted JSON, empty stderr, SHA-256 and `0700/0600`
permissions before establishing a fresh UTC window:

```bash
stat -c '%a %n' \
  "$RESIDUAL_AUDIT_PRIVATE_DIR" \
  "$RESIDUAL_AUDIT_PREFLIGHT_JSON" \
  "$RESIDUAL_AUDIT_PRIVATE_DIR/preflight.stderr"
sha256sum \
  "$RESIDUAL_AUDIT_PREFLIGHT_JSON" \
  "$RESIDUAL_AUDIT_PRIVATE_DIR/preflight.stderr"
cat "$RESIDUAL_AUDIT_PREFLIGHT_JSON"
```

Then define a fresh reviewed window and run executor `verify` with the same
exported preflight confirmation. Omitting it would cause the immediate
preflight to fail closed before the full audit:

```bash
export RESIDUAL_AUDIT_PREFLIGHT_SHA256='<reviewed preflight.json SHA-256>'
export RESIDUAL_AUDIT_START_UTC='<fresh UTC start>'
export RESIDUAL_AUDIT_END_UTC='<fresh UTC end, at most four hours after start>'

python3 scripts/execute-v0.11.9.3.6.6.6-aws-dev-residual-cost-audit.py verify \
  --expected-control-plane-commit "$EXPECTED_CONTROL_PLANE_COMMIT" \
  --preflight-result "$RESIDUAL_AUDIT_PREFLIGHT_JSON" \
  --expected-preflight-sha256 "$RESIDUAL_AUDIT_PREFLIGHT_SHA256" \
  --start-utc "$RESIDUAL_AUDIT_START_UTC" \
  --end-utc "$RESIDUAL_AUDIT_END_UTC" \
  >"$RESIDUAL_AUDIT_PRIVATE_DIR/executor-verify.json" \
  2>"$RESIDUAL_AUDIT_PRIVATE_DIR/executor-verify.stderr"
```

Verify approval is not execute approval.

The execute command and exact window are prepared only after successful verify
review. Execute uses the same preflight file and an additional empty private
output directory; it must not reuse log filenames from a prior attempt.

## Accepted success

The full existing audit must exit `0` and emit both its exact aws-dev success
marker and the no-continuing-identity marker. That means its checks accepted:

- zero Terraform state resources;
- no continuing target EKS, VPC, instance, volume, ENI, NAT Gateway, Elastic
  IP, ALB/target-group, backup-bucket, log-group, certificate, DNS or unexpected
  tagged-resource identity;
- only a recovery-window Secrets Manager tombstone, if present;
- only terminal or expired EC2 Fleet records, if still visible.

An audit error or residual identity is not absence. It stops without retry,
environment creation or cleanup mutation.
