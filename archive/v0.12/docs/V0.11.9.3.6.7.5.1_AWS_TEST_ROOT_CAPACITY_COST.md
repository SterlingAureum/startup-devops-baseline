## Full mutation and revision scope

Applying Root starts automated root/child reconciliation. Karpenter, CSI, CNPG,
monitoring and ALB controllers can create further Kubernetes and AWS resources.
A stopped shell process does not stop those controllers or cloud billing.

The reviewed shared dev helper also prepares namespaces, labels and IRSA
ServiceAccounts, adjusts the CNPG ObjectStore destination, refreshes
Applications and ExternalSecrets, seeds the database credential and reconciles
DNS. Its credential helper can read a CNPG Secret, write/read an AWS secret
value, and may authenticate a preexisting credential through `kubectl exec`.
Those operations were excluded from recovery observation and need explicit
future deployment scope and approval. Keep raw output and credentials private.
DNS reconciliation performs an A Alias UPSERT for the test hostname and needs
an explicit test target, state VPC/zone/ALB ownership checks, and approval.

Do not invoke `deploy-aws-dev-root-app.sh` directly for aws-test. Its defaults
and direct dev guard are insufficient for a test executor, its failure trap
can remove an annotation, and the existing DNS helper selects the ALB by DNS
name without a state VPC check. A future wrapper must bound the complete
operation, validate test-specific inputs, preserve failure evidence and avoid
unapproved repair writes.

Root and same-repository child Applications currently track `main`. Pinning
only Root does not pin that cascade. The future executor must implement and
validate a consistent immutable revision strategy across all same-repository
children, preserve the ALB state-derived VPC configuration, and review external
chart versions. This increment leaves the reviewed source trees unchanged.
The source audit here is not a full Helm/Kustomize render of every chart.

## Pricing evidence

Copy `delivery/contracts/v0.11.9.3.6.7.5.1-cost-profile.example.json` to a
persistent private directory outside the repository and temporary directories.
Set the directory to 0700 and profile to 0600. Every price requires a decimal
string `usd`, a source/reference, a UTC review time and a coverage explanation.
All rates in the shipped example are null; the example cannot pass review.
Synthetic rates in tests are arithmetic fixtures, never pricing guidance.

Use current us-east-1 Linux tenancy/capacity prices. Pool rate bounds must cover
all eligible instance types and relevant Spot changes/fallback; the current
category/generation selectors do not identify one priced SKU. Review T3 credit
mode and surplus exposure separately. `ebs_gib_hourly` is a per-GiB hourly
bound converted from the monthly price, not the monthly figure itself. Review
IOPS, throughput, snapshots and charge rounding. NAT processing belongs in
transfer or another explicit usage allowance without omitting it; include
cross-AZ transfer and image downloads. ALB includes LCU, and public IPv4 count
must include NAT, ALB and any additional addresses. Logs, metrics, S3/WAL,
Secrets Manager, DNS and billing uncertainty are not free merely because a
price or bill is missing. A positive fixed reserve is mandatory.

Official references checked on September 13, 2026:

- [EKS pricing](https://aws.amazon.com/eks/pricing/): standard version support
  is USD 0.10 per cluster-hour; worker resources are additional.
- [EKS version calendar](https://docs.aws.amazon.com/eks/latest/userguide/kubernetes-versions.html):
  1.36 is under standard support at this checkpoint.
- [VPC pricing](https://aws.amazon.com/vpc/pricing/): public IPv4 is USD 0.005
  per address-hour; NAT has hourly and data-processing charges. Regional NAT
  example prices must not be mistaken for a verified us-east-1 quote.
- [EC2 On-Demand pricing](https://aws.amazon.com/ec2/pricing/on-demand/),
  [EBS pricing](https://aws.amazon.com/ebs/pricing/),
  [ELB pricing](https://aws.amazon.com/elasticloadbalancing/pricing/),
  [AWS Pricing Calculator](https://calculator.aws/): obtain the remaining
  region/SKU prices and usage bounds here. They have not been filled in by this
  increment.
- [Karpenter NodePool limits](https://karpenter.sh/docs/concepts/nodepools/):
  limits are eventually consistent and can be exceeded during rapid scale-out.

References and coverage notes must identify what rate and usage were reviewed;
a URL alone is insufficient. Price reviews expire after 24 hours. This offline
review checks completeness, arithmetic and bindings, not the truth of a human
quote or a guarantee of future Spot prices.

## Prepare a private review packet

Use the existing archived observation:

```bash
umask 077
ROOT_REVIEW_DIR='__ABSOLUTE_EXISTING_PRIVATE_ROOT_REVIEW_DIRECTORY__'
COST_PROFILE="$ROOT_REVIEW_DIR/cost-profile.json"
cp delivery/contracts/v0.11.9.3.6.7.5.1-cost-profile.example.json "$COST_PROFILE"
chmod 600 "$COST_PROFILE"
```

Edit that private copy with reviewed rates and reserves. Do not repeat `cp`
after editing. Choose a proposed **cleanup completion** UTC deadline, rather
than assuming another eight hours are affordable:

```bash
CLEANUP_COMPLETE_BY_UTC='__REVIEWED_CLEANUP_COMPLETION_UTC__'
COST_PACKET_DIR="$ROOT_REVIEW_DIR/cost-packet-$(date -u '+%Y%m%dT%H%M%SZ')"
python3 scripts/review-v0.11.9.3.6.7.5.1-aws-test-root-cost.py prepare \
  --pricing "$COST_PROFILE" \
  --observation "$ROOT_REVIEW_DIR/observe-result.json" \
  --expected-observation-sha256 7d9528901ecde9a83ea86255bde89745a98c08bbb693aad076d80d41a3ccc36f \
  --cleanup-complete-by "$CLEANUP_COMPLETE_BY_UTC" \
  --output-directory "$COST_PACKET_DIR"
COST_REVIEW_EXIT=$?
printf 'cost_review_exit=%s\n' "$COST_REVIEW_EXIT"
```

`prepare` intentionally accepts the archived inventory for offline costing;
it never treats it as a fresh execution preflight. An invalid/unfilled profile
stops before creating a packet. A complete model that does not fit writes only
`cost-review.json`, returns 1 and generates no plan draft. Preserve the result
and review cleanup or a separately approved revised budget/session; do not
extend a window or raise USD 8 silently. This increment does not perform cleanup.

The calculator applies the conservative peak hourly estimate from
**2026-09-13T00:27:58Z** through cleanup completion, adds the fixed reserve, and
computes the latest deadline fitting USD 8. It also respects the operator end
**12:48:28Z**, maximum eight-hour new session, minimum one-hour cleanup reserve
and at least 30 minutes for Root work. Elapsed implementation/review time
continues to count. Historical spend remains null and is excluded from any
claim that USD 8 covers the environment's lifetime bill.

If it fits, a private plan draft is generated. It retains false scope review
and authorization flags and placeholders for post-merge main and fresh
observation. It is not an execution token. Complete the scope review and
merge `.7.5.1` with successful CI before obtaining one fresh `.7.5` read-only
observation against the new exact main, using the existing recovered inputs.
Do not regenerate kubeconfig or bootstrap to get that observation.

Then update the draft's current main, fresh observation hash and future start
UTC, and invoke the successor review (all files remain 0600):

```bash
python3 scripts/review-v0.11.9.3.6.7.5.1-aws-test-root-cost.py review \
  --pricing "$COST_PROFILE" \
  --plan "$COST_PACKET_DIR/private-plan-draft.json" \
  --observation '__ABSOLUTE_FRESH_SUMMARY_JSON__' \
  --expected-observation-sha256 '__FRESH_SUMMARY_SHA256__'
```

This requires a <=15-minute fresh observation, matching plan/main/release,
price-profile digest, component estimates at least as large as the derived
capacity estimate, elapsed cost within USD 8, and complete `.7.5` scope review.
A changed profile, stale observation, missing pool or understated component
fails. Passing still requires the separately implemented and reviewed immutable,
bounded deployment executor before approval or Root deployment.
