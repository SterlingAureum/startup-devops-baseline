23 Root resources, 18 child Applications and the nested PostgreSQL overlay.
The Root and all nine same-repository children use the exact newly merged
protected-main commit. External chart versions remain those already reviewed.

Private artifacts are `root-application.json`, `rendered-root-resources.json`,
`rendered-postgresql-resources.json`, `application-source-map.json` and
`private-root-plan.json`. All are 0600 inside a persistent 0700 directory outside
the repository and temporary directories. They contain private resource
identities and must never be committed. Plan checks bind every artifact, the
contract, the inputs and the exact commit by SHA-256. Verify and immediate
preflight render fresh copies and require byte equality.

## Separate execution scope and failure behavior

Execution requires a new explicit approval bound to the exact post-merge
commit, private plan, Root manifest, successful verify fingerprint and fixed
UTC end. It must cover all of these concrete actions:

- Apply two namespaces and two state-derived IRSA ServiceAccounts, then the
  single exact Root Application; allow its declared child/controller resources,
  On-Demand compute, persistent volumes, backups and ALB reconciliation.
- Read the CNPG-generated application credential; create exactly one initial
  AWS Secrets Manager version in the verified, still-empty test container and
  read that version back. Read the ESO target Secret and compare the URI.
- Annotate only the test ExternalSecret's refresh request; leave that annotation
  in place, including on failure. No cleanup trap mutates it after failure.
- UPSERT only the previously absent `demo.test.aureumstack.com` A alias in the
  verified public zone. The ALB must match the ingress, test VPC, internet-facing
  Application type and controller ownership tags. Wait read-only for INSYNC.
- Check exact live sources/revisions, CNPG/ESO readiness, child sync/health,
  allowed NodePools/new-node cost scope, IRSA/bucket/DNS and unchanged state.

CNPG generates its application Secret as described in the
[CloudNativePG security documentation](https://cloudnative-pg.io/docs/1.28/security/).
Secret contents and all raw readback output are private 0600 files. Credential
values travel via stdin, not command-line arguments. Refuse any existing AWS
version rather than overwriting a live credential. The prior shared dev wrapper
is not called. No Terraform, HTTP traffic, migration Job, qualification,
promotion, FIS/restore drill or teardown is executed. Demo/Root may be
Progressing or Suspended; successful deployment reports their health and does
not claim runtime acceptance or qualification.

Only after that separate approval, set all three exact confirmations:
`CONFIRM_AWS_TEST_ROOT_DEPLOYMENT=deploy-reviewed-aws-test-root-once`,
`CONFIRM_AWS_TEST_CREDENTIAL_SEED=seed-reviewed-aws-test-cnpg-credential-once`,
`CONFIRM_AWS_TEST_DNS_UPSERT=upsert-reviewed-aws-test-demo-alias-once`.
Use `execute` with the same inputs/main/bundle, a new private `--output-directory`,
and `--verify-result` / `--expected-verify-sha256` bound to the reviewed bytes.
No live approval is included in this document or increment.

The bundle receives an exclusively created one-time attempt marker before
immediate preflight. Each mutation attempt is journaled before command launch.
Failures and timeouts stop without command retries, automatic fixes or cleanup;
process groups are terminated so local child commands cannot run past their
bounded command duration. Preserve state, kubeconfig, bundle, journals and all
private output. A timeout may have submitted a successful cloud mutation:
inspect read-only before any new approval. Never delete an attempt marker to
repeat execution. Do not infer that controller/cloud work stopped with the
client. Independent cleanup must be reviewed and completed by the operator's
fixed deadline; expired or uncertain status needs a new explicit decision.
