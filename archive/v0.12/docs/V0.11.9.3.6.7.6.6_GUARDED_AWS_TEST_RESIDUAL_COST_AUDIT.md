# v0.11.9.3.6.7.6.6 — guarded aws-test residual-cost audit

Implementation baseline: `9513c92d11b1e3ea794b997db04cf5573f8c50bf`.
This increment implements read-only audit preparation and execution. Packaging is
offline and does not authorize an audit. Teardown is complete and must not be rerun.
No historical deletion deadline or approval is reused.

## Three independently reviewed phases

| Phase | Calls and result | Approval boundary |
| --- | --- | --- |
| preflight | Exact clean remote main, private account/input/result/receipt bindings, empty state; STS identity, EKS inventory, backup bucket absence and credential-container metadata | Read-only preflight confirmation; audit remains unauthorized |
| verify | Repeat preflight, compare stable fields to reviewed preflight; bind fresh UTC window and private preflight hash | Produces a private verify result valid for 15 minutes; audit remains unauthorized |
| execute | Verify result/window/hash binding, one-time marker, immediate preflight; strict service-native/captured/tagged resource audit | Separate explicit one-time approval; no mutation, Terraform, Kubernetes or credential value read |

Preflight validity is one hour. The maximum requested audit window is four hours;
verify/execute starts require at least 900 seconds remaining. Each command is bounded
by 120 seconds and the window end. Verify validity is 15 minutes, clipped to the
window end. Timestamp and raw-manifest changes are excluded from immediate preflight
comparison; the reviewed full preflight bytes remain bound by SHA-256. Other field
changes, including a tombstone becoming absent, require a fresh review.

Every execute attempt consumes an exclusive marker in the reviewed preflight's
private parent directory before its immediate AWS calls. An existing marker blocks
execution. Preserved markers must not be removed to reuse approval. Failure requires
private-output review and a newly approved attempt with fresh inputs/output; no
automatic retry, repair or repeated deletion exists.

## Strict audit scope and errors

The implementation uses its own fixed read-only AWS command allowlist. It does not
invoke the legacy shell audit, whose permissive absence handling is unsuitable here.
AWS_MAX_ATTEMPTS is fixed to 1. Successful responses require structured JSON, expected
list fields and completed pagination. Permission errors, expired credentials, timeout,
malformed JSON, duplicate keys and unknown resource identities stop the audit.
Only a corresponding exact AWS error code in the CLI error envelope is accepted as
absence. No generic grep of NotFound/403 and no empty-output fallback are used.

The native inventory covers Project/test and exact cluster ownership tags, captured
VPC, all eight captured instances and thirteen captured disks, captured SG, ALB/target
groups, EBS snapshots, certificates and EKS logs. Captured ninety managed definitions
also check IAM, EventBridge, SQS, FIS, S3 and metadata-only credential containers.
Captured subnet/route dependencies rely on authoritative captured-VPC absence;
detachable Internet Gateway and EIP receive their own exact native checks.
Global IAM and DNS checks stay limited to captured identities. Two regional tag
sweeps detect otherwise unknown test/cluster identities; an unknown ARN is a failure.
Known stale tags are accepted only after their native absence/terminal checks pass.

Instant Fleet IDs discovered in tags are queried individually. Only deleted,
deleted_terminating (after independent compute absence checks), or the exact
InvalidFleetId.NotFound result are accepted. deleted_running and other states fail.
DescribeFleetInstances is not invoked. See [AWS DescribeFleets](https://docs.aws.amazon.com/AWSEC2/latest/APIReference/API_DescribeFleets.html)
and [Fleet states](https://docs.aws.amazon.com/cli/latest/reference/ec2/describe-fleets.html).

Automatic AWS CLI pagination stays enabled, without max-items/no-paginate, and the
runner rejects residual continuation tokens. See [AWS CLI pagination](https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-pagination.html).
The ACM list explicitly includes configured RSA/EC key types to avoid the default
RSA_2048-only list; captured certificate ARNs are checked independently. See [ACM list-certificates](https://docs.aws.amazon.com/cli/latest/reference/acm/list-certificates.html).
The audit does not claim every certificate origin or every untracked/untagged resource
in the AWS account is covered. It is regional rehearsal residual inventory, not an
account-wide bill or all-region audit. Data is not an atomic inventory snapshot.

## Persistent private inputs and preparation

After merge, require clean main with HEAD == origin/main == remote main; set the
expected commit to that new SHA. It must descend from the implementation baseline.
Do not execute live phases from the feature branch.

The private inputs are the existing durable inputs JSON, final apply result, runtime
record and EKS completion receipt. All four are bound to the preceding evidence by
hash and must remain regular files mode 0600 in directories mode 0700. State must
remain the expected empty local test state, regular mode 0600. No kubeconfig or live
Kubernetes API is required, so loss of an old kubeconfig does not block this audit.

Set these variables to existing persistent private files and the post-merge main:

```bash
umask 077
export AWS_ENVIRONMENT='aws-test'
export EXPECTED_CONTROL_PLANE_COMMIT='<post-merge exact main SHA>'
# EXPECTED_AWS_ACCOUNT_ID must already contain the private 12-digit account.
export AUDIT_INPUTS='<persistent private inputs.json>'
export AUDIT_FINAL_RESULT='<persistent final-apply-output/result.json>'
export AUDIT_RUNTIME_RECORD='<persistent workspace/runtime-record.json>'
export AUDIT_EKS_COMPLETE='<persistent workspace/eks-complete.json>'
# Private parent outside the repository, e.g. the existing private-evidence parent.
export AUDIT_PARENT='<persistent private directory, mode 0700>'
```

Remove all unrelated CONFIRM_* variables (even empty ones), Terraform override
variables, custom AWS endpoint overrides and AWS_TEST_APPLY_MODE. The only allowed
confirmation for preflight/verify is:

```bash
export CONFIRM_AWS_TEST_RESIDUAL_COST_AUDIT_PREFLIGHT='observe-reviewed-aws-test-residual-cost-audit-preflight'
unset CONFIRM_AWS_TEST_RESIDUAL_COST_AUDIT_EXECUTION
```

Create a new persistent session and run ONLY preflight first:

```bash
AUDIT_SESSION="$(mktemp -d "$AUDIT_PARENT/aws-test-residual-audit.XXXXXX")"
python3 scripts/execute-v0.11.9.3.6.7.6.6-aws-test-residual-cost-audit.py preflight \
  --expected-main "$EXPECTED_CONTROL_PLANE_COMMIT" \
  --inputs "$AUDIT_INPUTS" --final-result "$AUDIT_FINAL_RESULT" \
  --runtime-record "$AUDIT_RUNTIME_RECORD" --eks-complete "$AUDIT_EKS_COMPLETE" \
  --private-output-directory "$AUDIT_SESSION/preflight-raw" \
  >"$AUDIT_SESSION/preflight.json" 2>"$AUDIT_SESSION/preflight.stderr"
PREFLIGHT_EXIT=$?
printf 'preflight_exit=%s\n' "$PREFLIGHT_EXIT"
stat -c '%a %s %n' "$AUDIT_SESSION" "$AUDIT_SESSION/preflight.json" "$AUDIT_SESSION/preflight.stderr"
sha256sum "$AUDIT_SESSION/preflight.json" "$AUDIT_SESSION/preflight.stderr"
if [[ "$PREFLIGHT_EXIT" -eq 0 ]]; then cat "$AUDIT_SESSION/preflight.json"; fi
```

Private-output-directory is a NEW leaf that the executor creates; do not precreate
or reuse it. Share only redacted result, modes/sizes and hashes; never raw stdout or
stderr. Successful status is aws-test-residual-cost-audit-preflight-ready-for-separate-approval.

## Verify after preflight review

Record the reviewed preflight hash and a new explicitly reviewed UTC window, maximum
four hours. Use this phase only after preflight is accepted:

```bash
python3 scripts/execute-v0.11.9.3.6.7.6.6-aws-test-residual-cost-audit.py verify \
  --expected-main "$EXPECTED_CONTROL_PLANE_COMMIT" \
  --inputs "$AUDIT_INPUTS" --final-result "$AUDIT_FINAL_RESULT" \
  --runtime-record "$AUDIT_RUNTIME_RECORD" --eks-complete "$AUDIT_EKS_COMPLETE" \
  --preflight-result "$AUDIT_SESSION/preflight.json" \
  --expected-preflight-sha256 "$AUDIT_PREFLIGHT_SHA256" \
  --start-utc "$AUDIT_START_UTC" --end-utc "$AUDIT_END_UTC" \
  --private-output-directory "$AUDIT_SESSION/verify-raw" \
  >"$AUDIT_SESSION/verify.json" 2>"$AUDIT_SESSION/verify.stderr"
VERIFY_EXIT=$?
printf 'verify_exit=%s\n' "$VERIFY_EXIT"
sha256sum "$AUDIT_SESSION/verify.json" "$AUDIT_SESSION/verify.stderr"
if [[ "$VERIFY_EXIT" -eq 0 ]]; then cat "$AUDIT_SESSION/verify.json"; fi
```

Verify status is aws-test-residual-cost-audit-execution-inputs-verified with
execution_authorized=false and full_audit_executed=false. Share the hashes/result;
obtain separate one-time audit approval before execute. The reviewed approval binds
target, exact main, preflight hash, verify hash and UTC window. It allows only the
fixed metadata/native/tagging read operations; no credential values or mutations.

## Execute only with separate valid approval

After explicit approval and while verify/window remain valid, set the exact execution
confirmation and reviewed verify hash. Run the existing entrypoint once with the
same verify arguments plus phase execute, --verify-result pointing to the private
verify.json, --expected-verify-sha256 set to its reviewed hash, and a new output leaf
such as execution-raw. Do not rerun the command on failure or override the marker.

Success is aws-test-residual-cost-audit-complete with audit_passed=true,
full_audit_executed=true, continuing_cost_identity_found=false and mutation_executed=false.
It includes coverage limitations and a raw-output-manifest hash. Failure is a redacted
STOP JSON plus private raw/failure evidence; keep state and every attempt/output.
A passed scoped residual audit does not settle historical spend or guarantee zero
account-wide billing. Execution evidence is a subsequent offline checkpoint.
