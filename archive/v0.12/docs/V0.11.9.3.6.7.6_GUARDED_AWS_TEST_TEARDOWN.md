## Phases and review boundaries

| Phase | Approved action after its separate approval | Required proof |
| --- | --- | --- |
| verify-runtime | Read-only identity and fresh runtime scope; private state snapshot | Persistent recovery inputs, Root bundle and completed deployment result |
| execute-runtime | Pause Root first, then all child Applications; remove only known Argo deletion finalizers and intentionally orphan chart resources; delete owned test DNS, three application/data namespaces, five captured PVs, two NodePools, three NodeClasses and detached captured PV disks | Reviewed runtime-proof SHA, valid for 15 minutes |
| plan-eks | Readonly-lockfile init and destroy-plan/show for module.eks; machine gate refuses VPC deletion | Exact runtime-complete receipt SHA |
| apply-eks | Apply one reviewed saved binary; confirm EKS absence; remove the captured EKS-created security group only if ownership, zero ENIs and no other SG references pass | Reviewed plan-proof SHA and binary/JSON/text hashes, valid for 30 minutes |
| plan-final | Produce a new destroy-plan/show accounting for every remaining managed state address | Exact eks-complete receipt SHA |
| apply-final | Apply one reviewed saved binary including permanent backup/version removal and Terraform-defined credential-container deletion; check captured residuals | Reviewed final plan-proof SHA and binary/JSON/text hashes, valid for 30 minutes |

CNPG, CSI, ALB and Karpenter controllers remain available during runtime cleanup.
Application deletion uses orphan propagation; other resources use background
propagation. Deleting NodePools lets Karpenter finish NodeClaim termination. No
storage/namespace finalizer is forcibly removed, and no reactive ENI/SG repair is
attempted. The hosted DNS zone is preserved. The final Secret metadata check
accepts absence or a scheduled-deletion tombstone; it never reads a credential.
Backup object versions are permanently lost when the approved final Terraform
plan deletes the force-destroy bucket. Review and approve that scope explicitly.

The targeted EKS plan is an exceptional dependency step. Terraform can broaden a
target to dependencies; review the actual saved plan. If it includes VPC deletion
or an unexpected scope, the machine gate stops; do not bypass the gate or run a
legacy wrapper. See [Terraform plan documentation](https://developer.hashicorp.com/terraform/cli/commands/plan).
An attached or externally referenced SG cannot be removed; see
[AWS security-group deletion conditions](https://docs.aws.amazon.com/vpc/latest/userguide/deleting-security-groups.html).
The staged workflow has offline fixtures; its live plans have not been executed
or validated by the package producer.

## First step after merge: read-only verify

Use a persistent evidence parent with mode 0700. Keep inputs, original completed
Root bundle, deployment result and isolated kubeconfig with mode 0600. Existing
recovery inputs replace lost temporary files; do not recreate infrastructure or
reuse expired Root execution approval. The recovered kubeconfig and observation
hashes are still checked. Existing aws-test local state must retain its original
reviewed hash until the explicitly approved EKS apply changes it.

The commands below run only verification. They do not set a mutation confirmation.
Set paths to the existing persistent files and a new workspace/output directory.

```bash
set -Eeuo pipefail
umask 077
export PYTHONDONTWRITEBYTECODE=1
export EXPECTED_CONTROL_PLANE_COMMIT='<new-merged-main-sha>'
export AWS_TEST_RECOVERY_INPUTS='<persistent-inputs.json>'
export AWS_TEST_ROOT_BUNDLE='<existing-immutable-root-directory>/bundle'
export AWS_TEST_DEPLOYMENT_RESULT='<existing-immutable-root-directory>/execution/result.json'
export AWS_TEST_CLEANUP_PARENT='<persistent-private-evidence-parent>'
unset CONFIRM_AWS_TEST_RUNTIME_CLEANUP CONFIRM_AWS_TEST_TEARDOWN_PLAN
unset CONFIRM_AWS_TEST_EKS_DELETE CONFIRM_AWS_TEST_FINAL_DELETE
unset CONFIRM_AWS_TEST_ROOT_DEPLOYMENT CONFIRM_AWS_TEST_CREDENTIAL_SEED
unset CONFIRM_AWS_TEST_DNS_UPSERT CONFIRM_AWS_TEST_APPLY CONFIRM_AWS_DEV_APPLY
unset CONFIRM_AWS_ENVIRONMENT_DESTROY CONFIRM_AWS_DEV_TEARDOWN_EXECUTION
unset CONFIRM_AWS_TEST_GITOPS_EXECUTION
bash scripts/validate-v0.11.9.3.6.7.6-guarded-aws-test-teardown.sh
export AWS_TEST_CLEANUP_WORKSPACE="$AWS_TEST_CLEANUP_PARENT/teardown-workspace"
export AWS_TEST_CLEANUP_VERIFY="$AWS_TEST_CLEANUP_PARENT/teardown-verify"
python3 scripts/execute-v0.11.9.3.6.7.6-aws-test-teardown.py verify-runtime \
  --expected-main "$EXPECTED_CONTROL_PLANE_COMMIT" \
  --inputs "$AWS_TEST_RECOVERY_INPUTS" --bundle "$AWS_TEST_ROOT_BUNDLE" \
  --deployment-result "$AWS_TEST_DEPLOYMENT_RESULT" \
  --workspace "$AWS_TEST_CLEANUP_WORKSPACE" --output-directory "$AWS_TEST_CLEANUP_VERIFY"
```

Use new directory names if either name already exists. Existing-directory refusal
and exclusive attempt markers are deliberate; never delete markers to retry.
If an earlier phase failed, preserve its output and perform separately approved
read-only assessment before deciding on a new operation.

## Binding each subsequent operation

The executable takes `--proof` and `--expected-proof-sha256` for all phases after
verify-runtime. Keep `--inputs`, `--workspace` and `--expected-main` unchanged,
and use a new `--output-directory` each time. execute-runtime also needs the
original `--bundle` and `--deployment-result` for immediate fresh checks.

Manually review workspace/runtime-record.json (all captured identities, storage,
DNS, application scope and private state bindings) before runtime deletion.
Only after review, set `human_reviewed` from false to true in
workspace/runtime-proof.json and hash the changed proof. Preserve every other
field, including its original timestamp. Obtain separate explicit approval bound
to that changed hash, state hash, current main, captured scope and deadline.
The JSON flag alone provides no authorization; the executor additionally requires
the phase-specific confirmation below.

Each plan writes destroy.tfplan, destroy-plan.json, destroy-plan.txt and
plan-proof.json in its output directory. Review the human text, private ID gate,
backup/version loss, credential container and all deletion scope; only then change
plan-proof.json's human_reviewed flag and compute its new SHA. Approve the exact
proof and binary/JSON/text bytes independently. Editing the flag cannot renew TTL.
After runtime/EKS success, use the workspace/runtime-complete.json or
workspace/eks-complete.json receipt respectively as the next plan's proof;
these receipts differ from the sanitized outer result.json.

| Phase | Confirmation variable | Exact value |
| --- | --- | --- |
| execute-runtime | CONFIRM_AWS_TEST_RUNTIME_CLEANUP | cleanup-reviewed-aws-test-runtime-once |
| plan-eks / plan-final | CONFIRM_AWS_TEST_TEARDOWN_PLAN | plan-reviewed-aws-test-teardown |
| apply-eks | CONFIRM_AWS_TEST_EKS_DELETE | apply-reviewed-aws-test-eks-delete-once |
| apply-final | CONFIRM_AWS_TEST_FINAL_DELETE | apply-reviewed-aws-test-final-delete-once |

Only the current phase's confirmation may be present. Legacy confirmations,
Root confirmations, endpoint overrides and TF_CLI_ARGS/TF_VAR/TF_WORKSPACE
injections cause refusal. Saved-plan apply requires the same Terraform version,
default workspace, existing unchanged provider lock, private state bytes and
source pins. Planning accepts Terraform >=1.8,<2 and init uses lockfile=readonly.
No provider upgrade is allowed. All phases recheck clean exact protected main.
The attempted phase is consumed even if its command fails or becomes uncertain.
