# v0.11.9.3.6.7.7.11 dev local CLI preflight

## Result

This increment adds the first local command-line boundary above the dev-only
`.7.7.10` command entry. It exposes only `verify`; there is no CLI `execute`
command and no transport object is constructed. The command reads a real host
UTC value once, reads exactly two private local files, validates the existing
durable receipt prefix and dispatches only to the inherited offline verifier.

The implementation is bound to protected-main
`958b959fdfada3449b2f4c710141c1c1ab118c21` and freezes the `.7.7.10` contract
and core byte hashes.

## Closed CLI

The positional command accepts only `verify`. Required arguments bind:

- exact protected-main and one of the eight ordered aws-dev phases;
- absolute approval and evidence file paths plus their expected SHA-256 values;
- one absolute durable receipt directory;
- the fixed observation confirmation
  `observe-reviewed-aws-dev-command-preflight`.

There is no environment-variable reader, arbitrary endpoint, backend selector,
transport argument or execution confirmation. Parser and validation failures
emit one stable redacted stderr line and preserve private inputs and receipts.

## Strict local inputs

Approval and evidence must be the only two entries in one owner-controlled
`0700` directory. Each input must be a nonempty owner-controlled `0600` regular
file with one hard link, no symbolic-link traversal and a maximum size of one
MiB. The adapter opens the directory and files without following links, checks
device/inode/size stability and accepts only byte-canonical JSON objects.

The receipt directory remains the inherited `.7.7.9` owned `0700` store. This
preflight reads and validates its exact completed prefix or empty state; it
writes no intent, receipt or completion file. Pending, linked, mode-drifted,
unexpected or out-of-order receipt content fails closed.

## Offline adaptation

One host UTC reading is normalized to whole seconds and placed in a `.7.7.10`
`FrozenClock`. The two validated byte strings are placed in a
`FixedPrivateInputReader`. The local CLI then builds the closed `.7.7.10`
request and dispatches only `verify`.

The inherited verifier rechecks exact environment, phase, main, input hashes,
operation set, receipt predecessor, approval window, proof freshness, budget
and false authority flags. A successful report contains hashes and aggregate
flags only; it never emits a private path or private input bytes.

## Offline evidence

Twenty-two tests cover:

- success through both direct invocation and a real local subprocess;
- exactly one host-clock read and two strict private-file reads;
- canonical stdout and redacted parser/runtime failure output;
- mode, ownership, link, path, directory-entry, size and hash failures;
- approval/evidence environment, main, phase, authority, clock and schema drift;
- empty, pending, unexpected and completed durable receipt prefixes;
- absence of environment, network, cloud, Kubernetes and Terraform backends;
- proof that no execute command, fixed-fake call or receipt write is reachable.

The validator recursively replays `.7.7.10` and its complete predecessor chain.

## Authorization boundary and next step

This increment performs real local clock and file reads only. It does not invoke
the fixed fake, access AWS or Kubernetes, run Terraform, write a receipt or
authorize a live execution for any environment. Historical teardown and scoped
residual-audit evidence remain closed.

The next increment may separately implement and review a dev-only local offline
execute prototype. That future step must bind a fresh preflight record, keep the
transport fixed-fake-only and append at most one durable receipt. A live
transport or live mutation remains a later independent design and approval edge.
