# v0.11.9.3.6.7.7.13 dev local offline restart chain

## Result

This increment exercises the complete eight-phase aws-dev offline command chain.
For every ordered phase it starts one fresh `.7.7.11` preflight process and one
fresh `.7.7.12` fixed-fake execute process. The same private receipt directory is
reopened across all sixteen child processes, proving restart-safe predecessor and
receipt-prefix behavior through all 23 closed operations.

The implementation is bound to protected-main
`e729e8966b3d1ab208ea47302498fb6b2416adc3`. It freezes the `.7.7.11` preflight
and `.7.7.12` execute entry hashes and recursively replays the predecessor gate.

## Synthetic fixture boundary

The exercise creates schema-compatible approval and evidence fixtures solely for
offline conformance. Every authority, retry and repair flag remains false. The
fixtures use no account, resource, endpoint, credential, Secret value or live
state identity.

The inherited approval schema retains its historical `mode=live` field, but the
exercise does not grant live authority: it reports `synthetic_fixture_approvals`,
`synthetic_receipt_chain` and `fixed_fake_transport_only` as true, while
`live_receipt_acceptable`, `historical_approval_reusable` and
`live_execution_authorized` remain false. Synthetic receipts cannot seed a
future live chain.

## Process and state chain

The exact ordered chain is:

1. `freeze-applications`
2. `drain-external-secrets`
3. `delete-business-namespaces`
4. `drain-runtime`
5. `delete-node-config`
6. `eks-delete`
7. `eni-sg-cleanup`
8. `final-delete`

Each phase receives a new pair of private fixture files for preflight and a
separate three-file execute input directory. The reviewed preflight bytes are
copied exactly into the execute inputs. A successful execute appends one
exclusive, fsynced intent/receipt/completion triplet.

The next phase binds the preceding receipt SHA-256. Its synthetic state-before
hash also equals the preceding phase's state-after hash, so both receipt and
state continuity are covered. A second exercise against the same session is
rejected before another child process can start.

## Private session

The caller supplies one pre-created, absolute, empty, owner-controlled `0700`
directory. The exercise creates only `0700` subdirectories and exclusive,
fsynced `0600` regular files with one hard link. It preserves each child's raw
stdout/stderr, both private input sets, all 24 receipt files and one canonical
summary. No private path or fixture byte appears in the public result.

The child command is a closed argument array beginning with the active Python
executable. Shell execution, stdin, arbitrary executable selection, endpoints,
environment-variable input and dynamic transport selection are unavailable.
Each child has a fixed 30-second timeout; failure or timeout stops once without
retry or repair and preserves the partial private session.

## Offline evidence

Twenty-one tests cover:

- the real sixteen-process, eight-phase and 23-operation chain;
- exact phase order, receipt predecessor and synthetic state continuity;
- restart reloads, eight receipt triplets and 24 private receipt files;
- separate strict preflight/execute inputs and preserved raw child logs;
- canonical private summary, directory/file/link modes and replay refusal;
- frozen predecessor byte drift, child failure, timeout and binding drift;
- redacted public failure and absence of shell, environment, cloud, Kubernetes,
  Terraform or arbitrary transport access.

The validator recursively replays `.7.7.12` and the complete predecessor chain.

## Authorization boundary and next step

This increment exercises only local Python processes and the inherited fixed
fake. It performs no AWS, Kubernetes or Terraform operation, reads no Secret
value, mutates no live system and grants no live authority to dev, test or prod.

The next increment should be a separate offline gap review comparing this full
process chain and receipt model with the already closed historical aws-dev
execution evidence. Only after that review should a versioned dev live transport
be proposed; aws-test and aws-prod remain disabled.
