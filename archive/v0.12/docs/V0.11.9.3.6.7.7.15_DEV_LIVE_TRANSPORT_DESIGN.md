# v0.11.9.3.6.7.7.15 aws-dev versioned live-transport design

Implementation baseline: `3be7f0248e11b1df0d427c7f61498f81063441d0`.

This checkpoint turns the `.7.7.14` parity gaps into one closed aws-dev
transport design. It is a pure offline specification: no backend, command,
credential reader, endpoint selector or live authority is implemented.

## Design outcome

The design fixes one environment, eight ordered stages and 23 phase-qualified
operation IDs. Every stage requires a fresh separate verification and approval
bound to exact main, phase, private inputs, scope, operation set, proof, state,
receipt predecessor, clock window and budget.

The normal protocol is:

1. verify one exact stage and its predecessor receipt;
2. review and approve that stage independently;
3. durably write one intent before any effect;
4. dispatch exactly one closed operation call per intent;
5. run the exact independent postconditions;
6. commit a terminal-success receipt only after all postconditions pass; and
7. stop on failed or uncertain intent without retry, repair or phase replay.

Historical approvals and historical or synthetic receipts are never accepted.

## Transport boundary

The proposed schema is `guarded-dev-live-transport-v1`, with canonical request
and response envelopes. It accepts no arbitrary command, endpoint selector,
environment fallback or ambient credential reader. This increment defines the
interface only; `backendImplemented`, `commandEntryImplemented` and
`liveEnabled` remain false.

| Stage | Transport kinds | Normal mutation boundary |
| --- | --- | --- |
| freeze-applications | Kubernetes | Exact reviewed Application freeze/finalizer/delete operations |
| drain-external-secrets | Kubernetes | None; observe and wait while cleanup permissions remain |
| delete-business-namespaces | Kubernetes | Exact reviewed resources and namespaces |
| drain-runtime | Kubernetes + AWS | None; read-only absence convergence |
| delete-node-config | Kubernetes | Exact reviewed NodePool/EC2NodeClass objects |
| eks-delete | Kubernetes + AWS + Terraform | One exact reviewed saved-plan apply |
| eni-sg-cleanup | AWS | Exact captured ENI followed by exact captured security group |
| final-delete | AWS + Terraform | One exact reviewed saved-plan apply |

## Terraform saved-plan stages

Only `eks-delete` and `final-delete` may change Terraform state. Each requires
the exact binary, JSON and human-readable plan hashes, machine-gate hash,
provider-lock hash, Terraform version and workspace. Their receipts bind the
reviewed state-before and state-after transition.

Every other stage requires the Terraform state hash to remain unchanged. This
prevents Kubernetes or AWS continuation work from silently becoming a state
mutation.

The old monolithic wrapper and its conditional second-destroy path are not
callable by this design.

## Postconditions and incident powers

Each stage has a closed postcondition set. Examples include Application and
active-operation absence, ESO drain with permissions retained, captured
runtime and volume absence, exact node-configuration absence, EKS dependency
accounting, ENI/SG absence, empty final managed state, backup-bucket absence and
Secret container absence or tombstone.

Seven incident-only powers remain enumerated but disabled, including forced
finalizer removal outside the reviewed Application stage, forced storage
cleanup, uncaptured-resource deletion, ad-hoc backup deletion, Secret value or
force-delete operations and state editing/import. Any such intervention still
requires a separate incident contract and approval.

## Gap disposition

All nine `.7.7.14` gap rows receive an explicit offline design clause:

- per-stage approval and fresh proof;
- terminal receipt predecessor chain;
- state-before/state-after binding;
- immutable scope and postcondition set;
- read-only ExternalSecret drain with permission lifetime;
- exact saved-plan bundle bytes;
- one intent and one call with no retry;
- closed versioned dev transport interface; and
- execution-time freshness, current pricing and budget.

This is design coverage, not live implementation. All nine rows continue to
report `implementedLive=false`.
