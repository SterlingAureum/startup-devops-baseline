# v0.11.9.3.6.7.7.19 aws-dev local offline process chain

Implementation baseline: `cb1065a17afb0feb4efacf3f8c551bf5a2a1dd27`.

This checkpoint exercises the frozen `.7.7.18` command through sixteen fresh
local Python processes: one `verify` and one `execute` process for each of the
eight ordered aws-dev teardown stages. It remains a fixed-fake integration
rehearsal and adds no live backend, credential reader or execution authority.

## Process and artifact boundary

The caller provides one pre-created, owned and empty `0700` session directory.
For each phase the runner creates separate `0700` bundle, preflight and output
directories. Canonical bundle and preflight files, child stdout/stderr, the
redacted output manifest, receipt triplets and the final summary are exclusive,
owned, single-link `0600` regular files with file and directory fsync.

The runner invokes only the exact SHA-256-pinned `.7.7.18` command with the
current Python interpreter, `stdin=DEVNULL`, no shell and a 30-second child
timeout. Every nonzero result, stderr byte, timeout, malformed or noncanonical
stdout, binding mismatch or unexpected receipt transition stops the chain. No
child is retried or repaired.

Each successful phase retains:

- canonical synthetic bundle bytes and their SHA-256;
- canonical reviewed preflight bytes and their SHA-256;
- exact verify and execute stdout/stderr bytes;
- a redacted manifest containing only byte counts, hashes and return status;
- one durable synthetic attempt/receipt/completion triplet.

The final acceptance requires eight ordered stages, 23 closed operations,
sixteen successful child processes, eight receipt triplets, 24 receipt files,
32 retained child-output files and eight redacted output manifests.

## State and saved-plan rules

The receipt predecessor and `state_before_sha256` must be continuous after every
fresh process. Non-Terraform phases keep the synthetic state hash unchanged.
Only `eks-delete` and `final-delete` require a changed synthetic state hash and
an exact synthetic saved-plan bundle. Every postcondition key must match the
frozen stage design and every value must be true.

All approvals, bundles, receipts and reports remain explicitly synthetic. They
cannot seed or authorize a live receipt chain and cannot be reused as historical
approval.

## Deliberate non-live scope

The runner reads the host UTC clock, writes only local private artifacts and
starts only the frozen local Python command. Neither the runner nor `.7.7.18`
reads credentials, environment-selected endpoints or secret values. There is no
AWS, Kubernetes, Terraform or network transport and no live mutation.

Run:

```bash
bash scripts/validate-v0.11.9.3.6.7.7.19-dev-local-offline-process-chain.sh
```

The focused validator checks exact source hashes, AST and privacy boundaries,
runs 23 offline tests and recursively replays `.7.7.18`.
