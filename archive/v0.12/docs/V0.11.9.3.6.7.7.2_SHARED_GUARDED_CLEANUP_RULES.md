# v0.11.9.3.6.7.7.2 共同清理依赖与 captured ENI/SG 纯规则

应用基线：`9b0d172eee26a612c2c492a8ae5e0c361108dfa8`。本包实现 `.7.7` 复核中 ESO 清理顺序和
ENI/SG 续接的纯规则及28项离线 fixtures。它不切换历史执行器，也不创建 live 入口。
“已补纯规则回归”不等于共同 adapter 迁移已完成或 prod 实测通过。

## 清理依赖顺序

`validate_cleanup_step(completed, proposed, observation)` 只验证下一个步骤。
completed 必须是 confirmed receipts 的有序前缀；尝试过但未确认成功的阶段不能加入。
每步 observation 都须是 adapter 已核验 scope 的完整新鲜 inventory。

| 步骤 | 必须成立的前置条件 |
| --- | --- |
| freeze-applications | 当前 scope/inventory 验证通过；调用方独立批准冻结及移除已捕获 Application。 |
| drain-external-secrets | 应用已冻结/移除、无 active operation；pending ExternalSecret 仍有 ESO controller、patch 权限和 scoped RBAC，namespace 尚未请求删除。 |
| delete-business-namespaces | ExternalSecret 已不存在、无未知 finalizer；之后才可删除业务 namespace 和其中的 RBAC。 |
| drain-runtime | 业务 namespace 已不存在，清理所需 controller 仍可用，允许其协调 storage/compute/LB 收尾。 |
| delete-node-config | 已确认 NodeClaim/PV/captured runtime compute/PV volume/LB/target group/test DNS 清空。 |
| eks-delete | 上述 runtime 依赖为空，NodePool/NodeClass 已移除；需要独立 saved plan 和批准。 |
| eni-sg-cleanup | EKS、captured compute/volumes、LB/target group/test DNS 原生 absence 已确认。 |
| final-delete | 上述检查加 captured ENI/SG absence；最终 Terraform/container 范围仍由独立 gate 和批准控制。 |

该顺序在 namespace/RBAC 删除前 drain ExternalSecret，避免 ESO ready 却不能 patch。
历史故障因 scoped RBAC 先被删除而卡住；人工中断停止等待，未产生这项依赖缺陷。
规则对此返回失败，既不补 RBAC，也不移除任何 finalizer。未知 finalizer 始终停止。
旧事故的单对象 finalizer 修复批准不能推广为自动修复选项。

## ENI/SG 续接决策

`eni_decision` 和 `sg_decision` 接受 hash-bound captured snapshot、fresh native rows、
完整 inventory、显式 private scope 和 attempted 状态，只返回 `delete-once` 或
`confirmed-absent`。这些字符串没有授权效力，也不写 receipt 或执行 API。

| 规则 | 判定边界 |
| --- | --- |
| ENI 归属 | account/VPC/subnet/SG 与 scope 匹配；Description 只含一个精确 captured instance token；类型为 interface，RequesterManaged=false。 |
| ENI 可删除状态 | Status=available，Attachment/Association 缺省或 null；当前身份 signature 与 captured 匹配，SG 查询和 exact-ID 查询一致。 |
| ENI 已消失 | exact-ID absence 和完整 SG interface 查询均为空；其他 ENI 不能被当作 captured ENI absence 隐藏。 |
| SG 归属 | GroupId/owner/VPC/cluster ownership 与 captured 完整快照匹配。 |
| SG 可删除状态 | 新鲜 group inventory 一致、无 ENI、无其他 SG ingress/egress 引用；自己的 self-reference 不当作外部引用。 |
| attempt 已消费 | 对象仍在时拒绝 repeat-delete；对象原生确认不存在时跳过 mutation，不能据此续期旧批准。 |

scope 中的 environment/account/cluster、captured IDs 和各类 absence facts 必须从已审核
private inputs 与 native observations 提供。规则支持显式 dev/test/prod 参数，不默认 dev。
bool `native_inventory_complete` 不是解析器：adapter 必须验证 schema、分页完成、错误 code、
exact identity 和查询范围后才能传 true；None 也只能表示已完成的原生 absence 查询，
不能表示日志缺失、AccessDenied、超时或未知响应。

新规则比旧一次性事故脚本更严格：captured node 使用精确 token，不接受 IID 子串；
Attachment/Association 空对象不算 absence；cluster suffix 必须与显式环境匹配。
SG permission 的 UserIdGroupPairs 是可选原生字段，存在时必须为有效 list；异常 schema
停止。完整性和跨 VPC reference 检查范围仍须由 adapter 固定服务 API 做好核验。

## attempt、race 与迁移边界

attempted 只是一份已读取日志的纯事实，本模块不实现 durable reservation。
未来 adapter 必须在 mutation 前独占写 marker/journal，并将每个失败/中断保持已消费；
调用规则两次传 false 不是一次性机制。completed receipt 同样必须来源于独立后置验证。
先重新核验 captured group ownership、ENI 身份及 references，再调用一次精确删除 API；
ENI 重新附着或 SG 新增引用等 race 由 API 拒绝时停止，不能 detach、修改规则或自动重试。
跨 VPC 和跨账户引用查询属于后续 adapter 的固定 observation 范围，本模块只检查传入
的完整 VPC group inventory；不得声称这些纯 fixtures 已穷尽真实云资源引用。

本包没有修改 `.7.7.1` 核心、历史 live executors、evidence、state、Fleet 分类或
`.gitleaksignore`。当前28项回归验证 ordering/ownership/once-only decisions；真实 API、
durable AttemptJournal、精确 saved-plan dependency gate 和 versioned adapters 仍需迁移。
下一批实现 exact plan-scope gate 与 attempt-journal integration，再做 fake transport 的
新 dev/test/prod adapter 验证；任何 live 操作重新审核 main/account/state/release、预算和窗口。
