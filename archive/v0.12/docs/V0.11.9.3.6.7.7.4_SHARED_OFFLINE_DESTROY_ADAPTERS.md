# v0.11.9.3.6.7.7.4 三环境离线删除阶段 adapter

应用基线：`7f688e991ed6144fc29b762301741f8eb1813a5e`。
本包将前3批共同规则组合为 versioned `OfflineDestroyAdapter`，实现 EKS dependency
删除和 final 删除两个阶段，39项离线测试涵盖三环境 × 两阶段的6个成功组合。
历史 live 执行器与共同核心冻结；完整 live adapter 迁移尚未完成。

## 环境与阶段

| profile | managed module 范围 | 离线阶段 |
| --- | --- | --- |
| aws-dev | cnpg_backup、eks、external_secrets、karpenter、tls_dns、vpc、fis、github_actions_runtime_identity | eks-delete / final-delete |
| aws-test | 同 dev | eks-delete / final-delete |
| aws-prod | 共同6个 module；不含 fis / github_actions_runtime_identity | eks-delete / final-delete |

同一执行逻辑接受显式 environment、phase 和 exact main。profile 来自现有 Terraform
main.tf 的 module 名称，支持顶层数值 module index；未知/nested shape 停止并独立复核。
EKS阶段要求当前 EKS module 和所有 aws_eks_*资源均列入审核，其他dependency删除只允许
eks/cnpg_backup/external_secrets/karpenter/github_actions_runtime_identity 范围。哪些
非EKS依赖应删除仍由精确reviewed address/definition/ID列表提供，不根据整个module
或历史50项数量推定真实依赖图。final阶段必须覆盖当前全部managed state。

## 组合接口与数据

`OfflineDestroyAdapter(environment,phase,main,repository_root=...)` 的 `run` 接受：

| 输入 | 核验 |
| --- | --- |
| artifacts | inputs/scope/state/plan/binary/text/provider_lock 全部不可变bytes；严格JSON解析和逐项审核hash绑定。 |
| simulation approval | schema=offline-destroy-approval-v1，simulation_only=true；固定环境/phase/main、原始proof时间、所有hash、预算和journal绝对路径。 |
| confirmations | AWS_ENVIRONMENT显式；唯一该环境OFFLINE_DESTROY确认值为 simulate-reviewed-环境-phase-once，禁止其他CONFIRM或endpoint/TF覆盖。 |
| scope | 每条simulation confirmed receipt固定raw/hash/environment/step；有序前缀；精确reviewed managed records和native remote absence地址。 |
| ScenarioClock | 显式单调UTC samples，无系统时钟读取或缺失fallback。 |
| ScenarioTransport | 固定class的pre/immediate/post原始JSONbytes和fake apply结果，仅记录labels/hash，不能执行SDK/CLI。 |

module中没有 executable CLI 或真实transport注册。非精确fake class（含subclass）拒绝；
该type检查用于防止混用后端，不是抵御恶意Python代码的sandbox。simulation approval是
fixture契约，不是真实云端批准；其hash也不是人类签名或云权限。native身份/inventory/
absence均为脚本化test facts，不是实际AWS响应解析器。

inputs要求us-east-1、显式account/cluster/environment、Terraform version和default
workspace、正数预算。proof最多900秒、窗口最多8小时且启动至少剩余60秒；observation
TTL为60秒。original proof creation、expiry和审核hash固定，不能改created续期。
Binary/JSON/text/provider lock分别pin hash，plan version和fresh version/workspace facts
一致。本包不运行Terraform show，也不证明任意binary与JSON的真实语义对应关系；这些
native解析与执行职责留给后续live adapter。预算估算只是fixture allowance，没有查价
或读取账单，不宣称真实预算保证。

## 固定顺序和失败边界

1. 校验local批准/hash/确认值/时钟/预算、profile、receipt prefix与精确plan gate。
2. fake pre observation验证身份、inventory完整、时效、fresh artifact/version/workspace、
   reviewed remote absence及共同cleanup prerequisite。
3. 在approval固定的持久私有journal路径reserve；不能改路径或覆盖已有marker。
4. fake immediate observation重复范围核验；再次校验原始hash、clock、plan与freshness。
5. before intent barrier完成fsync；落盘后再次校验proof/window及该observation的年龄。
6. 仅调用一次fake saved-plan apply；没有plan、retry、reset、repair或其他API选项。
7. fake post observation独立核验exact absence地址、剩余state地址/definition/ID、
   EKS或final cloud absence和预算；执行deadline仍适用。
8. 只有postconditions全通过，才记录success和精确operation集合的completion。

前置失败不调用fake apply；reserve后的失败保留已消费marker。before写入失败、落盘期间
过期或freshness过期均不会调用fake backend。明确fake failure写terminal outcome；
调用结果不确定、post失败或deadline超时保留pending并停止，不能按return code补回执。
完成写入失败同样不产生success report，不重跑fake call。二次运行保留原日志，最多再次
只读pre observation，reserve拒绝已有marker；pending和success都不能变成新一次调用。

EKS post要求未选中managed definitions/IDs及data地址保持一致，selected全被确认不存在；
final要求managed为空，剩余data只允许原已知地址/类型。原生资源再次出现或其他retained
ID变化的fixture会失败。private returned journal hashes可用于review，公开report不带
account、cluster、address、resource ID、私有路径或原始错误内容。

journal目录必须预先创建0700、位于仓库及已知ephemeral roots之外。测试在仓库外临时
synthetic directory做真实Linux fsync/flock/O_EXCL，结束后只删除synthetic fixture；
没有访问或清理用户host evidence。实际adapter必须选择持久home路径、固定operation
集合和reviewed scope。新建目录不能自动续期旧授权；本包按传入approve path强制一致，
并继承前批每directory/tag的一次性及hash chain/head完整性边界。

## 未迁移部分与后续

只实现两个destroy阶段的offline composition。ESO drain/RBAC保留与namespace对象生命周期、
runtime删除、captured ENI/SG续接、backup/container永久删除和所有真实API执行均未接入。
这些前置receipt来自审核fixture，而不是本包自己执行过的阶段。下一批组合ESO/runtime
依赖drain和ENI/SG离线adapter，再明确规划新的live adapter；旧事故脚本保持冻结。
三环境离线矩阵通过不等于prod live演练、qualification或新云端执行授权。
test teardown/scoped audit保持已收口，不复用旧窗口、批准或marker。
