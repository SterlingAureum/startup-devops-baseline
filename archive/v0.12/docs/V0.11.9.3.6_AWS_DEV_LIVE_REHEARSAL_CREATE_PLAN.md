# v0.11.9.3.6 aws-dev live-rehearsal create plan

## Purpose and status

This checkpoint implements an offline validator for the private, billable
aws-dev creation plan. Applying and validating it executes no AWS, Terraform,
Kubernetes or Argo CD command and creates no environment. A valid plan returns:

```json
"execution_authorized": false
```

The implementation baseline is protected-main commit:

```text
05270a186fcf8aa5b82ff4d1e44ea467f4a1498d
```

The successful `.3.5.1` read-only result justifies preparing this capability,
but it does not authorize creation.

## Why a fresh preflight is required

This increment changes the control-plane commit. After it is reviewed and
merged, capture that new full main SHA and run the `.3.5` read-only preflight
again with a newly populated private plan. The creation plan records distinct
SHA-256 fingerprints for that fresh plan and result.

The earlier fingerprints remain historical evidence:

```text
plan      56eef1a83217d9d5b2287ac295dcc0fa915313b3d23f3f494d20ab56b151a66b
preflight ad91ef09cd481b9d32efbfb2fbe91ca8e552827bda369f063bf9e02fc499e068
```

Do not edit or overwrite those earlier private files. Do not reuse their
fingerprints as the fresh result.

## Create the private plan

After `.3.6` reaches protected main, copy the template outside the repository:

```bash
PLAN_PARENT="$(mktemp -d /tmp/v011936-aws-dev.XXXXXX)"
chmod 700 "$PLAN_PARENT"

CREATE_PLAN="$PLAN_PARENT/create-plan.json"
cp delivery/examples/v0.11.9.3.6-aws-dev-live-rehearsal-create-plan.json \
  "$CREATE_PLAN"
chmod 600 "$CREATE_PLAN"
```

Replace every placeholder. The populated plan is private because it includes
the intended AWS account, operator, owners, schedule and evidence location.
Never commit or upload it.

Validate it offline:

```bash
python3 scripts/check-v0.11.9.3.6-aws-dev-live-rehearsal-create-plan.py \
  --plan "$CREATE_PLAN"
```

The repository template intentionally fails. A populated plan can pass only
when it remains bound to the post-implementation protected-main commit, exact
candidate and fresh preflight fingerprints.

## Cost and time boundary

Record a current, reviewed pricing estimate rather than copying a stale price
from repository documentation. The plan requires:

- USD estimate and review reference;
- a positive hourly estimate;
- an explicit session budget sufficient for eight estimated hours and no more
  than USD 50;
- one active rehearsal EKS environment maximum;
- a UTC start and teardown-review deadline no more than eight hours apart.

The budget and deadline are operator guards, not an implemented AWS Budget or
automatic shutdown. Reaching the deadline stops qualification and requires
review. It does not authorize an unreviewed destroy.

## Planned creation and GitOps sequence

The separately reviewed execution will use this order:

1. Run a fresh read-only preflight on exact main.
2. Obtain the separate live-create approval.
3. Invoke `scripts/apply-aws-dev.sh` with the expected account and environment
   confirmation.
4. Review the generated Terraform plan and stop if it includes destroy or
   replacement actions; type `apply-aws-dev` only for the accepted create plan.
5. Wait for EKS and Kubernetes API readiness.
6. Run `scripts/bootstrap-eks-argocd.sh`.
7. Prepare required runtime-only secrets and run
   `scripts/deploy-aws-dev-root-app.sh` at the exact main revision.
8. Collect fresh aws-dev runtime and observability evidence.
9. Preserve private evidence before a separate teardown review.
10. Destroy through `scripts/destroy-aws-dev.sh`, then require
    `scripts/validate-aws-cost-cleanup.sh` to pass.

The existing create entrypoint has two confirmations: the
`CONFIRM_AWS_DEV_APPLY=create-ephemeral-aws-dev` environment guard and the
interactive `apply-aws-dev` Terraform-plan confirmation.

## Failure-stop rules

Stop without interpreting uncertainty as absence when:

- AWS account, region, Git main or preflight identity differs;
- any rehearsal cluster is active;
- dev state is nonempty or partial;
- Terraform discovery fails;
- the plan includes destroy or replacement actions;
- the workstation endpoint or Kubernetes API cannot be verified;
- the reviewed deadline is reached.

Preserve Terraform state and private evidence after failure. Do not delete
state to force a clean create, do not automatically destroy, and do not replay
the local-only fault in AWS.
