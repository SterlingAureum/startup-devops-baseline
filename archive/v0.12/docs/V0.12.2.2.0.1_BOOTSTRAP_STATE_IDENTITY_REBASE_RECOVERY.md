# v0.12.2.2.0.1 Bootstrap State Identity-Rebase Recovery

## Outcome

The approved v0.12.2.2 `terraform init -migrate-state -force-copy` completed,
configured the S3 backend and copied the exact reviewed resources and outputs.
Terraform represented that copied state with a new lineage, serial `1`, and a
reserialized `check_results` list. The original v0.12.2.2 postcondition required
the local lineage and non-regressing serial, so it stopped before `state list`
and S3 object-version validation. That fail-closed stop was correct.

This recovery accepts only the exact observed identity rebase. It does not
generalize lineage replacement and it never repeats `terraform init` or state
migration.

## Authority boundary

Applying this repository increment is offline. It runs no AWS or Terraform
command and grants no live authority.

The executor has two phases:

1. `verify` is command-free. It binds protected main, the exact migration
   request and incident output, all three preserved state copies, the empty
   post-migration working state, the existing backend metadata and the exact
   reviewed identity rebase.
2. `execute` requires a new, separate approval window. It reuses the existing
   backend metadata to run only AWS identity, `terraform state pull`,
   `terraform state list`, S3 `head-object`, and S3 `list-object-versions`
   reads.

The recovery cannot run Terraform init, plan or apply; cannot migrate, push or
destroy state; cannot attach IAM policies; and cannot retry or roll back. Do
not rerun the v0.12.2.2 migration executor.

## Prepare a fresh request

After this increment is merged and the worktree is clean, copy
`delivery/examples/v0.12.2.2.0.1-bootstrap-state-recovery-request.example.json`
to a new owner-only file outside the repository. Replace only the documented
placeholders and private paths. The recovery output directory must not already
exist.

Use absolute paths. If a shell variable might contain a relative path, resolve
it before invoking the executor:

```bash
RECOVERY_REQUEST_01="$(realpath --canonicalize-existing "$RECOVERY_REQUEST_01")"
chmod 600 "$RECOVERY_REQUEST_01"
```

Set `expectedRecoveryMainCommit` to the clean, synchronized protected-main
commit containing this increment. The approval interval must be active, no
longer than one hour, and retain at least 15 minutes when either phase starts.
