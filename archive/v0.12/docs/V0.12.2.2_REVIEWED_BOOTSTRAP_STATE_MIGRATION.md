# v0.12.2.2 Reviewed Bootstrap State Migration

v0.12.2.2 adds the separately approved executor for the exact bootstrap-state
migration reviewed in v0.12.2.1. Applying this repository increment does not
read private evidence, run AWS or Terraform, or migrate state.

The canonical contract is
`delivery/contracts/v0.12.2.2-reviewed-bootstrap-state-migration.json`.

## Frozen preflight

The executor accepts only the completed and human-reviewed v0.12.2.1 private
preflight. The private request, result, state inventory, source manifest,
command plan, immutable backup, resource-identity digest and live validation
are pinned by their published SHA-256 values. The source contains exactly 13
managed addresses and the remote bootstrap state key was empty.

The preflight window does not authorize migration and may expire. v0.12.2.2
requires a new private request, new output directory and new approval window.

## Command-free verification

Create an owner-only request from
`delivery/examples/v0.12.2.2-bootstrap-state-migration-request.example.json`,
then run:

```bash
python3 scripts/execute-v0.12.2.2-bootstrap-state-migration.py verify \
  --private-migration-request "$MIGRATION_REQUEST"
```

`verify` executes no operational command and writes nothing. It revalidates
protected main, the prior private request chain, every preflight artifact, the
three preserved state copies, current source, private backend config and exact
reviewed command. Its output never authorizes execution.

## Separately approved migration

Only after human review of the fresh verification output may the exact
confirmation be set in an isolated shell:

```bash
export CONFIRM_STATE_BOOTSTRAP_MIGRATION=migrate-reviewed-bootstrap-state-to-s3
python3 scripts/execute-v0.12.2.2-bootstrap-state-migration.py execute \
  --private-migration-request "$MIGRATION_REQUEST"
unset CONFIRM_STATE_BOOTSTRAP_MIGRATION
```

Execution repeats all verification, checks the AWS account and revalidates the
still-empty S3/KMS/IAM foundation. It then executes exactly once:

```text
terraform -chdir=PRIVATE_REVIEWED_SOURCE init -input=false -migrate-state -force-copy -backend-config=PRIVATE_REVIEWED_CONFIG
```

No reconfigure, plan, apply, state push, destroy, IAM attachment, retry or
automatic rollback is allowed.

After a successful init, the executor privately pulls and lists remote state,
requires matching lineage, non-regressing serial, exact address inventory,
resource identity and outputs, and verifies one current SSE-KMS state-object
version with no delete marker. The original plan-bundle state, preserved apply
copy and immutable preflight backup must remain unchanged.

## Failure boundary

Any failure after migration begins is potentially ambiguous. Do not rerun the
executor, delete evidence, roll back the backend, delete an S3 object version
or use `terraform state push`. Preserve the complete private migration output
and all earlier evidence for a separately designed recovery.

## Handoff

A successful v0.12.2.2 result proves migration and state identity, but it does
not complete the migration program. v0.12.2.3 separately owns lock-contention
proof, a reviewed zero-change saved plan, controlled object-version recovery
and redacted terminal evidence. It requires another approval window.

## Offline validation

```bash
bash scripts/validate-v0.12.2.2-reviewed-bootstrap-state-migration.sh
```

The repository validator and injected tests perform no live migration.
