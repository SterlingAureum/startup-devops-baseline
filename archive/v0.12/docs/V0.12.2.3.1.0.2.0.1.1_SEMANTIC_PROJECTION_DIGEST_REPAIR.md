# v0.12.2.3.1.0.2.0.1.1 Semantic-Projection Digest Repair

The first v0.12.2.3.1.0.2.0.1 command-free verification stopped before any
AWS or Terraform command because the published semantic-projection digest did
not use the executor's actual projection and encoding definition.

The executor had already proved that the exact observed state digest matched,
the top-level key set was unchanged, `check_results` was the only changed
value, and every value outside `check_results` was equal. The failure was
therefore an offline contract defect rather than new Terraform state or AWS
infrastructure drift.

## Exact correction

The semantic projection contains these six state keys:

- `lineage`;
- `outputs`;
- `resources`;
- `serial`;
- `terraform_version`;
- `version`.

It excludes only `check_results`. The projection is encoded as sorted compact
JSON followed by exactly one LF byte. The corrected SHA-256 is:

```text
1d21a9edbfe82d1d1496b312c8a31996c20f9f4bf8505604a277cbdede2f8d15
```

This repair changes only the bound digest in the executor, request example,
contract and offline validators. It does not accept another state digest,
another changed key or semantic inequality, and it does not add any live
execution authority.

## Post-merge workflow

After merging this repair, create a fresh private request from the corrected
v0.12.2.3.1.0.2.0.1 example. Bind the new protected-main commit, select a new
private output directory and create a new approval interval. Do not reuse the
failed request or its expired window.

Run command-free verification first. Live execution remains subject to a new,
separate approval bound to the post-merge request SHA-256.

## Offline validation

