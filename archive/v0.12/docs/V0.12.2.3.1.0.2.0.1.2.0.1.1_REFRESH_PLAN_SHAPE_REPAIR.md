The first post-apply recovery request stopped during command-free verification.
The reviewed refresh-only plan contained seven exact `resource_drift` entries,
but Terraform omitted the optional `resource_changes` member because the plan
contained no remote resource operation. The validator incorrectly required an
explicit empty array.

This repair treats a missing member and an explicit empty array as the same
zero-change representation. It rejects non-list and non-empty values, retains
all seven reviewed drift, persisted-state, caller-session, address, lineage,
serial, state-history and lock-history gates, and does not change any evidence
digest.

The failed request SHA-256
`995d38ad01aff1ebd47dda93e39b43ab22d3cc84e2336aeafe486f544d91a47f`
executed no operational command and must not be reused. After this repair is
merged, create a fresh request from the existing example with:

- a new private output directory, such as an `attempt-02` directory;

authorize only the existing recovery executor's AWS identity, Terraform state

state push, destroy, force-unlock, direct S3 mutation, retry and rollback remain
forbidden.
