# v0.12.2.3.1.0.2.0.1 State-Pull `check_results` Normalization Repair

The first reviewed state-reconciliation attempt stopped before apply because
the state returned by `terraform state pull` was not byte-identical to the
earlier remote-state evidence. The stopped attempt produced no apply stdout or
stderr. Its only completed operational commands were the AWS identity read and
the pre-apply state pull.

Offline comparison proves that only the top-level `check_results` value was
normalized. State format, Terraform version, lineage, serial, resources,
outputs, 13 managed addresses, nine data addresses and every other top-level
value remained exactly equal. This repair accepts only that exact observed
state digest and exact `check_results` transformation. It does not establish a
general semantic-equality exception.

## Command-free verification

The new request binds the failed request and its four exact private artifacts:
identity stdout/stderr and state-pull stdout/stderr. Verification reconstructs
the complete reviewed saved-plan and recovery chain, requires the failed apply
artifacts and reconciliation result to be absent, and validates the exact
normalization without running AWS or Terraform.

Use a fresh output directory and an approval window of at most one hour:

```bash
python3 scripts/execute-v0.12.2.3.1.0.2.0.1-state-pull-check-results-normalization.py verify \
  --private-repair-request "$NORMALIZATION_REPAIR_REQUEST_01"
```

The verify result grants no execution authority. A separate approval must bind
the new protected-main commit and the new private request SHA-256.

## Exact execution boundary

After separate approval, execute from an isolated subshell with all earlier
confirmations unset and only this confirmation set:

```bash
export CONFIRM_REFRESH_ONLY_STATE_RECONCILIATION_NORMALIZATION=apply-exact-reviewed-refresh-only-plan-after-validated-check-results-normalization
```

Execution repeats the read-only identity, state, state-address and S3
state/lock-history checks. The new pre-apply pull must equal the exact observed
normalized state. It then delegates to the already-reviewed reconciliation
executor and may apply only the same saved refresh-only binary plan once.

Terraform init, every new plan, unsaved apply, state push, destroy, IAM
attachment, direct S3 mutation, force unlock, retry and rollback remain
prohibited. Any different state byte, changed field beyond `check_results`,
history mismatch, apply failure or post-apply ambiguity stops execution and
preserves all private evidence without retry.

## Success gate

Success still requires zero remote resource actions, unchanged lineage and
addresses, serial advancement by exactly one, persisted values equal to the
reviewed plan, one new state-object version, no state delete marker, one lock
version and one lock delete marker, and an absent current lock object.

The result remains subject to human review before a new zero-change proof is
designed.
