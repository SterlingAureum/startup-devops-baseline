# v0.12.2.3.1.0.2 Reviewed Refresh-Only State Reconciliation

This increment applies the exact previously saved and human-reviewed
refresh-only plan once. It does not generate another plan. The reviewed plan
contains seven state refreshes, zero `resource_changes`, seven no-op outputs,
and no remote resource action.

Terraform saved-plan mode executes only the operations encoded in the plan.
Refresh-only application persists reviewed provider observations to state
without changing remote infrastructure.

## Bound evidence

Command-free verification reconstructs and binds:

- the successful v0.12.2.3.1.0.1.0.1 read-only recovery request, result and
  validation;
- the private S3 state-head and object-history snapshots from that recovery;
- the original failed refresh-plan request and output directory;
- the exact binary, JSON and text plan digests;
- the seven-entry drift digest and canonical pre-apply state bytes;
- the original plan, migration preflight, migration, identity recovery and
  remote-state proof chain;
- an explicit private human-review record preceding the apply window.

`verify` runs no AWS or Terraform command, writes no evidence and grants no
apply authority.

## Exact execution boundary

Execution requires a fresh protected-main-bound request and:

```bash
export CONFIRM_REFRESH_ONLY_STATE_RECONCILIATION=apply-exact-reviewed-refresh-only-plan-once
```

Before the apply, the executor requires byte-identical canonical state, the
exact 22-address inventory, unchanged S3 state and lock histories, and an
absent current lock object. It then runs exactly one saved-plan command:

```text
terraform apply -input=false -lock=true -lock-timeout=60s -no-color <exact-reviewed-binary-plan>
```

Terraform init, every Terraform plan, any unsaved apply, state push, destroy,
IAM attachment, direct S3 mutation, force unlock, retry and rollback are
prohibited.

## Success and failure gates

Success requires all of the following:

- exit code zero and the zero-resource-action apply summary;
- state lineage unchanged and serial advanced exactly once;
- 13 managed and nine data addresses unchanged;
- `terraform show -json` current-state values exactly equal the reviewed
  plan's `planned_values`;
- exactly one new S3 state-object version and no state delete marker;
- exactly one new lock version and one lock delete marker;
- no current lock object.

If apply or any post-apply validation fails, the executor stops, preserves all
private evidence and any state already written, and forbids automatic retry or
rollback. A failure after the apply must be treated as an incident, not as
permission to run the plan again.

## Private request workflow

Copy the example request to the owner-readable private root. Bind the new main
commit, account, evidence-recovery request/output, refresh-plan request/output,
and SHA-256 digests of the private recovery state-head and object-history
artifacts. Record the completed human review, select a new output directory and
create an active approval interval of no more than one hour.

```bash
python3 scripts/execute-v0.12.2.3.1.0.2-refresh-only-state-reconciliation.py verify \
  --private-apply-request "$REFRESH_STATE_RECONCILIATION_REQUEST_01"
```

After separate approval, execute from an isolated subshell with all previous
confirmations unset. Exact commands are supplied only after command-free
verification and explicit approval.

Successful execution still requires human review before a new ordinary
zero-change proof is designed. This increment does not authorize that proof.
