# v0.12.3.1 CI Change-impact Routing

## Outcome

The measured v0.12.2.4.2 full local gate completed in 302 seconds. Of that,
267 seconds were spent in the retained v0.11 historical suite. This increment
keeps that full suite for core and unknown changes while adding two bounded
routes that do not need to replay repository history.

The existing `validate / quality-gates` job identity and workflow triggers are
preserved. Routing happens inside the reusable job after checkout, so a
required check is never omitted merely because a path filter did not start a
workflow.

## Modes

| Mode | Selection | Required validation |
| --- | --- | --- |
| `full` | core, script, contract, workflow, Terraform, GitOps, mixed, unknown, ambiguous or manual execution | secret scan, Helm setup, complete repository gate and Trivy configuration scan |
| `documentation` | every changed path is under `docs/` or is an allowlisted root documentation file, and no changed path is referenced by a tracked historical validator | secret scan, independent classifier recheck, `git diff --check` and routing structure validation |
| `image` | explicit call from the reviewed demo-api image-publish workflow | secret scan, Helm setup, routing structure validation, supply-chain validation, demo-api unit/runtime security validation and Trivy configuration scan |

Renames are evaluated with Git rename detection disabled. A move from a core
path into `docs/` is therefore observed as a core deletion plus a documentation
addition and cannot enter the documentation-only route.

Documentation paths referenced by any tracked `scripts/validate-*.sh` file are
routed to `full`. This prevents a lightweight documentation change from
silently breaking an existing contract marker. A validator-source read error
also resolves to `full`.

Any missing commit, zero SHA, empty diff, unsupported event, invalid mode,
unavailable Git object or classifier ambiguity resolves to `full`.

## Deliberate boundary

This increment removes the second full historical replay from the demo-api
image-publish workflow. The publish job still depends on its targeted quality
gate and retains build, vulnerability scan, SBOM, provenance and attestation
controls.

It does not skip the full gate on a core `main` push merely because a pull
request previously passed. The repository has no merge-queue or exact
prospective-merge-tree attestation proving that the pushed tree is identical to
the reviewed tree. Reusing that result without such evidence would be
fail-open. Exact merge-result reuse remains future work.

## Local validation

Run the routing and topology checks without replaying history:

```bash
bash scripts/validate-v0.12.3.1-ci-change-impact-routing.sh --structure-only
```

Run the normal full repository gate:

```bash
bash scripts/validate-ci-quality-gates.sh
```

No AWS, Kubernetes, Terraform plan/apply, state mutation or paused state
recovery authority is introduced.
