## Closed feedback path

The converged design retains one stable required quality-gate result while
selecting a fail-closed path from the actual changed files:

- unbound documentation-only changes use the bounded documentation route;
- an exact single demo-api release-file change uses the bounded release route;
- scripts, contracts, workflows, Terraform, GitOps, mixed, unknown and
  ambiguous changes use the full route;
- demo-api image publication uses targeted supply-chain, application, Helm and
  hardened-runtime checks instead of replaying the complete repository gate;
- current v0.12 structure and routing validators remain active; and
- the 112 frozen v0.11 entrypoints are proven by Git tree, manifest, mode and
  release-digest attestation without executing their historical runtime.

The historical proof does not create a detached worktree and does not replay a
v0.11 validator. A future GitHub runner may have different timing, but it must
retain the same routing and fail-closed safety properties.
