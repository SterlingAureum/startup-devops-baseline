# v0.12.4.1.1 Platform Supportedness Repair Design

## Outcome

This increment closes the chart-to-application identity gaps found by
v0.12.4.1 and defines the fail-closed order for repairing platform
supportedness. It is an offline design only: repository version pins remain
unchanged and no live cluster operation is authorized.

The review separates three questions that must not be collapsed into one:

1. which application is actually delivered by the pinned Helm chart;
2. whether that application can be qualified on the current Kubernetes 1.36
   baseline; and
3. whether its release line still receives maintainer support and security
   fixes.

Chart metadata resolution is not upgrade authorization. Compatibility and
maintainer support are separate decisions, and "latest" is not an
automatically acceptable target.

| kube-prometheus-stack chart `88.5.0` | Prometheus Operator `v0.93.0` | chart declares Kubernetes `>=1.25.0-0`; explicit CRD proof remains required |

These resolutions remove the generic "unknown chart application version"
block. They do not assert that every current pin is the preferred supported
maintenance target, and they do not replace a rendered manifest, CRD or live
qualification.

## External Secrets is the first repair track

External Secrets `2.8.0` remains compatible with Kubernetes 1.36 but reached
end of life on 2026-08-07. It is the only current component with a confirmed
hard support-lifecycle defect, so it is repaired before selecting an EKS
control-plane target or bundling unrelated controller changes.

The reviewed line sequence remains `2.8 -> 2.9 -> 2.10 -> 2.11`. Each minor
transition is a separate reviewed change. Exact patch versions and immutable
chart digests are deliberately not selected here.

Every hop must produce all of the following evidence before a GitOps pin can
advance:

- publisher-controlled chart metadata, exact version and digest;
- release-note and breaking-change review;
- repository API and ExternalSecret, SecretStore, ClusterSecretStore and
  PushSecret inventory;
- Helm render and CRD diff;
- server-side dry-run in a disposable environment;
- secret refresh and rotation qualification;
- Argo CD sync/health plus logs, metrics and alert qualification; and
- an explicit rollback-or-forward-fix decision.

The repair must not share a window with an EKS control-plane upgrade or any
other controller upgrade. No automatic retry or automatic rollback is allowed.

## Controller-specific qualification

All controller candidates require an exact version and digest, release notes,
rendered manifest comparison, CRD comparison when applicable, and a fresh
approval for live qualification. One controller is changed per window.

AWS Load Balancer Controller requires an IAM policy diff, CRD and
TargetGroupBinding diff, and qualification of the repository's ALB ingress and
NLB service paths.

Argo Rollouts must not be upgraded while a rollout or promotion is active. Its
qualification covers Rollout, AnalysisTemplate and related CRDs plus pause,
promote and abort behavior.

kube-prometheus-stack requires explicit Prometheus Operator CRD handling;
Helm 3 does not make CRD lifecycle safety implicit. PrometheusRule,
ServiceMonitor, alert, dashboard and scrape-target continuity must be proved.

The Barman Cloud plugin requires an explicit CloudNativePG/plugin compatibility
decision, an ObjectStore and Cluster reference diff, and a successful backup
and restore rehearsal. A successful chart render alone is insufficient.

## Remaining blocks and next checkpoint

The mapping defect is closed, but the platform upgrade gate remains blocked:

1. External Secrets `2.8.0` is still pinned and end-of-life.
2. Exact repair candidates and immutable digests have not been selected.
3. Installed and target-compatible EKS managed add-on versions still require a
   fresh live inventory.
4. EKS `1.37` remains provisional and unselected.

This increment changes no Helm, Terraform or GitOps version declaration and
authorizes no AWS, Kubernetes, Terraform, EKS, add-on or controller operation.
The next checkpoint is
`v0.12.4.1.2-external-secrets-supportedness-repair-plan`.
