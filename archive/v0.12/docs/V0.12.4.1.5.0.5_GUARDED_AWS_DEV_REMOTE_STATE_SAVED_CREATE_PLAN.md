# v0.12.4.1.5.0.5 guarded AWS dev remote-state saved create plan

## Outcome

This checkpoint produces one private saved Terraform create plan for the absent
`aws-dev` environment. It consumes the successful, human-reviewed `.0.4`
clean-room preflight, an exact private S3 backend configuration, the quarantined
private `terraform.tfvars`, and a manifest-bound copy of tracked AWS Terraform
source. It does not apply the plan or create the environment.

The command-free `verify` phase binds every private input, protected main and a
currently active approval window. The separately approved `execute` phase may
copy the already reviewed staged source, run `terraform init -reconfigure`, run
one saved create plan, and render that exact binary plan as private JSON and
text for human review.

## Time windows

Plan generation may use a window of up to two hours. The saved plan may remain
eligible for review for up to eight hours so PR review and the subsequent apply
checkpoint do not consume a one-hour operational window. The future exact-plan
apply receives a new approval window of up to three hours. Post-apply health
validation receives another approval; it is not folded into the apply window.

Expiry never grants retry authority. An expired request or plan requires a new
request and new output directories. A failed or ambiguous Terraform command
preserves all private evidence and stops without automatic retry or rollback.

## Exact input chain

The request binds the `.0.4` private request, result, evidence, source manifest,
staged source directory and backend config by SHA-256. It also binds the
quarantined private `terraform.tfvars` by SHA-256. All private inputs remain
outside the repository with files at mode `0600` and parent directories at
mode `0700`.

The plan executor copies only manifest-listed tracked source into a new private
plan-source directory. Backend configuration and tfvars are copied into the
new private plan-output directory before use. Terraform plugin data is isolated
under that output directory. The preflight staging directory remains unchanged.

## Live boundary

Immediately before Terraform initialization, the executor revalidates the AWS
account, expected EKS `ResourceNotFoundException`, and empty exact state/lock
object history. Initialization uses `-reconfigure`, never `-migrate-state`.
The plan must contain managed `create` actions only; data resources may be
`read` or `no-op`. Resource drift, update, delete, replacement and import are
rejected. At least one managed create and the expected EKS cluster create must
be present.

After planning, the executor proves the remote state key is still empty and
the native `.tflock` object is absent. Versioned temporary lock-object evidence
may exist, but direct S3 writes/deletes are prohibited. The executor emits only
counts and digests publicly; raw addresses, ARNs, values and object-version IDs
remain private.

## Human review and successor

Success produces a binary plan, machine-readable plan, human-readable plan,
action/address inventory, object-history evidence and a plan record. Human
review must confirm expected resources, configuration, cost, stderr and the
absence of update/delete/replace/import before `.0.6` can be designed.

This checkpoint does not authorize Terraform apply, state push, migration,
destroy, IAM attachment, Kubernetes, Argo CD, Helm, secret-value reads, the
External Secrets preflight retry, automatic retry or automatic rollback.
