# v0.12.4.1.5.0.7.1.5 AWS dev EKS-SG/VPC cleanup

VPC-only read-only recovery proved that Terraform state contains only the
parent VPC and that its sole non-default dependency is one EKS-created cluster
security group. That group belongs to the target account and VPC, matches the
security group formerly attached to the deleted orphan ENI, has no remaining
ENI, ingress rule, self-reference or cross-group reference, and has only one
ordinary CIDR egress rule.

This checkpoint uses two separate approvals. `prepare` revalidates the exact
private security-group evidence, deletes only that bound orphan EKS security
group, proves its absence, and creates a saved destroy plan that must contain
exactly `module.vpc.aws_vpc.this`. It does not apply Terraform. The operator
then reviews the private text and JSON plan and creates a separately approved
final request bound to every artifact digest.

`final` applies only that reviewed binary plan. Success requires exactly one
destroyed resource, empty Terraform state, no state delete marker, a clean lock
lifecycle, and VPC absence. No init, replacement plan, unsaved destroy, retry,
rollback, force-unlock, state push, direct S3 mutation or unrelated AWS
mutation is allowed.
