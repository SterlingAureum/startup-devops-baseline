# v0.12.4.1.5.0.7.1.6.11 shared dev/test offline process chain

## Delivered capability

This checkpoint exercises the complete shared teardown sequence for `aws-dev`
and `aws-test`. Each of the eight ordered phases runs through a fresh Python
process and the exact `.6.10` fixed-fake command, producing 16 child processes
and 98 deterministic fake backend calls in total.

Each phase receives a distinct approval store, execution store, request
directory and binding directory. Short-lived synthetic receipts and approvals
are chained by predecessor receipt SHA-256 within one environment. Every child
must create a durable claim and terminal outcome before the next phase starts.

## Process and failure boundary

The harness derives the repository root from its own installed location and
accepts only one exact confirmation. It invokes one fixed absolute script path,
without a shell, with a fixed 30-second timeout and a minimal replacement
environment. Host credentials, Terraform variables, Kubernetes configuration
and caller-specific environment variables are not forwarded.

Any timeout, nonzero exit, stderr output, malformed result, missing durable
record or digest mismatch stops the chain at that phase. There is no automatic
retry, repair or rollback. Terminal output contains no private path, request,
binding, resource identity or child error payload. All disposable private
stores are removed on success and failure.

## Authority boundary

This is a synthetic fixed-fake process exercise, not an infrastructure
executor. It loads no historical private evidence and exposes no AWS,
Terraform, Kubernetes, S3, state, endpoint, credential, raw-command, failure
injection, retry or live switch. It grants no live or backend-retirement
authority.

The next checkpoint should freeze this offline chain and record the explicit
live-adapter readiness gap. Building or invoking a live adapter remains outside
this checkpoint.
