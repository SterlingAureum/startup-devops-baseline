# v0.12.4.1.5.0.7.1.6.3 shared dev/test two-wave teardown private preflight

## Delivered capability

This checkpoint connects the command-free request adapter to strictly scoped
local private evidence. A local-only preflight reads exactly `request.json` and
`evidence.json`, verifies their caller-supplied SHA-256 values, confirms that
the request binds the evidence, applies the phase-specific evidence gate and
returns a redacted receipt plus its SHA-256.

It does not inspect AWS, Terraform, Kubernetes or S3. It does not persist the
receipt, invoke a subprocess, mutate state or expose an infrastructure
executor.

## Private bundle boundary

The bundle directory must be absolute, owned by the current user and mode
`0700`. It must contain exactly two owned, regular, single-link files named
`request.json` and `evidence.json`, each mode `0600` and no larger than one
MiB. Symlinks, hard links, additional entries, non-canonical JSON, replacement
during read and caller-digest drift fail closed.

No private path or raw resource identity is included in the result. Evidence
shapes accept only hashes, counts, booleans, approved category names and the
already public environment/control-plane fields.

## Phase evidence

All eight lifecycle phases bind the environment, state key, phase,
control-plane commit and managed-state inventory. Evidence must be observed no
more than fifteen minutes before request creation and cannot be future-dated.

Additional gates are phase-specific:

- controller cleanup binds controller inventory and explicit disposable-backup
  cleanup intent;
- first-wave plan binds state, backend history, source and both state counts;
- each apply binds the exact reviewed binary plan, plan record and delete
  count, plus separate text and JSON plan hashes;
- post-first-wave inventory requires EKS absence and network-only state;
- safe-residue cleanup binds the exact category and SHA-only identity and
  rejects an already attempted deletion;
- second-wave plan requires zero safe, unknown and controller-owned
  dependencies;
- final audit requires empty managed state and preservation of the shared
  backend/runtime-identity foundation.

## Receipt and authority

The receipt contains only redacted bindings, time boundaries and the authority
that a later approval would need. Its SHA-256 can be used as the exact
`predecessorReceiptSha256` of a future request. The preflight does not persist
that receipt, so persistence and review remain a separate checkpoint.

Every execution and mutation authority remains false. The `verify` entrypoint
reads one host UTC value and the two private local files only. Historical
private evidence remains outside required CI. This checkpoint grants no live
read, controller mutation, Terraform plan/apply, direct AWS deletion, retry,
rollback, state push or backend-retirement authority.
