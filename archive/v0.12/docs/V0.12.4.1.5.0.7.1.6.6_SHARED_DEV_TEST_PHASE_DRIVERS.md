# v0.12.4.1.5.0.7.1.6.6 shared dev/test phase drivers

## Delivered capability

This checkpoint defines one closed, reviewable driver specification for every
phase in the shared dev/test two-wave teardown. Each spec binds environment,
state key, Terraform root declaration, requested authority, effect class,
ordered operation IDs and required private digest names.

It intentionally provides no shell command template, subprocess, SDK,
credential reader or live backend. The operation protocol is exercised only
through an exact fixed fake.

## Closed phase specifications

Both `aws-dev` and `aws-test` receive the same eight phase shapes while keeping
separate state keys, Terraform roots and backend declarations. `aws-prod`
remains rejected. Across the eight phases, 49 ordered operation IDs cover:

- controller-owned cleanup through Kubernetes controllers;
- first-wave non-network saved plan and exact-plan apply;
- post-EKS dependency inventory and protected-foundation checks;
- one exact allowlisted residue deletion when separately approved;
- fresh network-only saved plan and exact-plan apply; and
- empty-state, absence, backend-history and residual-cost audit.

The complete canonical spec is SHA-256 bound by the private execution request.
Changing an operation, order, environment, root, authority or safety flag
changes the digest and stops before the claim.

## Lease integration

The predecessor receipt, approval and execution request are revalidated before
use. The execution-spec SHA must equal the canonical reviewed phase spec. An
exclusive durable claim is then written before the first operation dispatch.
Each operation is dispatched exactly once and in order.

The fixed fake returns a canonical digest-bound response. A failure stops at
that operation and records a terminal failure outcome when possible. Claim-only,
failure, success and outcome-write uncertainty all consume the approval and
forbid retry or repair.

## Next boundary

The next checkpoint may map these reviewed operation IDs to one live command
adapter. That adapter must not accept raw shell, dynamic command templates,
credential or endpoint overrides, reordered operations or unknown IDs. Live
acceptance remains separately approved; this checkpoint executes no AWS,
Terraform, Kubernetes, S3 or state command.
