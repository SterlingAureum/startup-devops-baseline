# v0.12.4.1.5.0.7.1.6.7 shared dev/test command-adapter registry

## Delivered capability

This checkpoint closes the command boundary beneath the shared dev/test phase
drivers. The 49 phase calls resolve to exactly 37 unique reviewed operation
IDs. Every ID has one immutable adapter identity, transport kind, effect class,
timeout, output policy and set of required private binding names.

No operation accepts a raw command, dynamic command template, credential or
endpoint override, environment fallback, retry or repair switch.

## Phase manifests

Each dev/test phase receives a canonical command manifest bound to:

- the complete predecessor phase-driver spec SHA-256;
- the complete command-registry SHA-256;
- the environment state key, Terraform root and backend declaration;
- the exact ordered operation IDs and every adapter-entry SHA-256; and
- claim-before-command, one-call, stop-at-first-failure and no-retry rules.

An operation request is accepted only at its reviewed phase index. Moving an
otherwise valid operation into another phase or position, changing the call
count, authority, environment or driver-spec digest fails closed.

## Implementation boundary

This checkpoint implements selection and validation only. It contains no
subprocess, SDK, credential reader, shell command, live backend or executable
phase entrypoint. Consequently none of the five mutation-class entries can run.

The next checkpoint may connect these exact adapter IDs to a reviewed runner.
That runner must retain the existing durable claim, consume one approval only,
accept no free-form command or endpoint input, and stop without automatic retry
after the first failed or uncertain command.
