# v0.12.4.1.5.0.7.1.6.8 shared dev/test claimed registry runner

## Delivered capability

This checkpoint adds the offline runner between the durable phase claim and
the closed command-adapter registry. Before its first backend call, the runner
validates the complete claim digest and active window, exact phase manifest,
all ordered operation requests, and every required private SHA-256 binding.
The receipt, approval and execution-request bindings must equal the durable
claim. Each operation receives only the binding subset declared by its exact
registry entry.

All 16 dev/test environment-phase combinations and 98 calls are exercised in
the fixed fake. Unknown, missing, reordered, cross-phase and mutated inputs
stop before dispatch. A failed or malformed response stops at that operation;
there is no automatic retry, repair or rollback.

## Replay boundary

This module is a lower-level post-claim component, not a standalone execution
entrypoint. It verifies an already persisted claim but does not read or write
the lease store and cannot independently prove that a claim has not previously
been dispatched. The durable lease remains the replay authority. A future
composition must invoke this runner inside that single-use lease lifecycle;
exposing it directly as a live command would break the contract.

The fixed fake object is single-use as an additional local invariant. That
object-level rule is not represented as durable replay protection.

## Implementation boundary

The runner accepts only the exact fixed fake backend. It has no subprocess,
SDK, credential or endpoint reader, filesystem writer, shell command, live
backend or CLI entrypoint. No AWS, Terraform, Kubernetes, S3 or state action is
available, and no execution authority is granted.

The next checkpoint should compose this runner inside the existing durable
single-use lease before any separately reviewed live backend is considered.
