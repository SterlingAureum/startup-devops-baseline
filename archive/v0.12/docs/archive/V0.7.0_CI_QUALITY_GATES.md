# v0.7.0 CI Quality Gates

## Goal

Create one repeatable validation contract shared by pull requests, local
development, and GHCR image publishing.

This increment closes the first v0.7 delivery gap: the image publish job must
not run independently of the repository's application and manifest checks.

## Delivered

- reusable `.github/workflows/reusable-quality-gates.yaml` workflow;
- explicit `quality-gates` dependency in the image publish workflow;
- one local `scripts/validate-ci-quality-gates.sh` entry point;
- Bash syntax checks for repository scripts;
- local and aws-dev Helm lint and rendering;
- isolated demo-api unit tests;
- Docker test and runtime stages;
- bounded CI job timeouts and read-only validation permissions;
- removal of the completed v0.4 feature branch from Terraform triggers.

## Unit-Test Coverage

The test suite covers:

- process health;
- root service identity;
- readiness with the database disabled;
- readiness with a healthy database;
- sanitized `503` behavior when the database is unavailable;
- Prometheus response content;
- accepted database enablement values;
- missing database URL handling;
- bounded retry after a transient operating-system error.

Tests mock the database boundary. They do not read Kubernetes Secrets, contact
PostgreSQL, or output a connection string.

## Validation

Run from the repository root:

```bash
chmod +x scripts/validate-ci-quality-gates.sh
./scripts/validate-ci-quality-gates.sh
```

Expected final output:

```text
CI quality gates passed.
```

The command requires Bash, Docker, and Helm. It does not require AWS
credentials, a Kubernetes cluster, or Terraform state.

## GitHub Validation

After pushing the branch:

1. Confirm the `validate` workflow calls `reusable quality gates`.
2. Confirm all quality-gate checks pass.
3. Trigger `demo-api image publish`.
4. Confirm `build-and-push` starts only after `quality-gates` succeeds.
5. Confirm the immutable `sha-<short-commit>` image exists in GHCR.

Do not update the aws-dev image tag as part of this increment. Automated,
reviewable GitOps promotion belongs to v0.7.2.

## Version Boundary

v0.7.0 does not introduce image digests, artifact attestations, promotion pull
requests, Argo CD Image Updater, cluster credentials in GitHub Actions, or
production security controls.
