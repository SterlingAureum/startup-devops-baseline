# v0.7.1 Immutable Image Identity

## Goal

Bind every published demo-api image to an immutable OCI digest, its source
commit, and verifiable GitHub build provenance before automating environment
promotion.

## Delivered

- digest-aware Helm image rendering;
- digest format validation in Helm and release scripts;
- tag-to-digest registry verification;
- structured image metadata artifact;
- build provenance attestation attached to GHCR;
- digest rendering checks for local Rollout and aws-dev Deployment;
- retained tag-only local kind fallback.

## Image Contract

The readable and immutable identifiers serve different purposes:

```text
tag:     sha-<short-source-commit>
digest:  sha256:<immutable-OCI-content-identity>
runtime: repository@sha256:<digest>
version: sha-<short-source-commit>
```

GitOps values store both tag and digest. Kubernetes pulls by digest, while
`/version` continues to expose the readable source tag.

## Local Validation

Run:

```bash
./scripts/validate-ci-quality-gates.sh
```

The gate must prove:

- tag-only local and aws-dev rendering still works;
- digest-pinned local Rollout rendering works;
- digest-pinned aws-dev Deployment rendering works;
- malformed digest values fail Helm rendering;
- image identity JSON contains the expected digest, reference, and source
  commit;
- all v0.7.0 shell, Helm, unit-test, and runtime-image checks still pass.

## GitHub Validation

Push the feature branch and merge after the reusable quality gate passes. The
main-branch image workflow must then:

1. complete `quality-gates`;
2. build and push the SHA-tagged image;
3. report a `sha256:` digest;
4. upload `demo-api-image-metadata-<full-commit-sha>`;
5. create build provenance;
6. show the tag, digest, and source commit in the run summary.

Verify the exact identity:

```bash
IMAGE_TAG="sha-<short-commit>" \
IMAGE_DIGEST="sha256:<64-character-digest>" \
./scripts/check-ghcr-demo-api-image.sh
```

## Manual aws-dev Promotion

Promotion remains explicit in this increment:

```bash
VALUES_FILE=apps/demo-api/helm/values-aws-dev.yaml \
IMAGE_TAG="sha-<short-commit>" \
IMAGE_DIGEST="sha256:<64-character-digest>" \
./scripts/set-demo-api-image.sh
```

Commit the resulting tag, digest, and `APP_VERSION` change, allow Argo CD to
sync, and confirm the Deployment is healthy.

## Version Boundary

v0.7.1 does not create branches or pull requests, write directly to `main`,
merge release changes, or access the EKS API from GitHub Actions. The metadata
artifact is the input boundary for the reviewable promotion automation planned
in v0.7.2.
