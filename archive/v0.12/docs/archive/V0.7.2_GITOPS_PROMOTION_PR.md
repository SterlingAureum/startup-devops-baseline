# v0.7.2 GitOps Promotion Pull Request

## Goal

Close the manual gap between a validated immutable demo-api image and a
reviewable aws-dev desired-state change without bypassing Git, human approval,
or Argo CD.

## Delivered

- artifact-driven promotion from the exact image build job;
- repository, source commit, SHA tag, digest, and reference validation;
- deterministic `values-aws-dev.yaml` update;
- idempotent `release/demo-api-sha-*` branch creation;
- automatic promotion pull-request creation or reuse;
- per-job write permissions limited to the promotion job;
- Node.js 24 Action upgrades for every reported deprecation warning;
- image path filters that exclude values-only promotion commits.

## Delivery Flow

```text
quality gates
  -> build and push image
  -> record tag, digest, and source metadata
  -> download and verify metadata
  -> update aws-dev values on a release branch
  -> create promotion PR
  -> human review and merge
  -> Argo CD reconciliation
```

GitHub Actions does not merge the PR and does not call the EKS API.

## One-Time Repository Setting

Under **Settings → Actions → General → Workflow permissions**, allow GitHub
Actions to create pull requests. Organization policy must also permit the
workflow's declared `contents: write` and `pull-requests: write` permissions.

## Local Validation

Run:

```bash
./scripts/validate-ci-quality-gates.sh
```

The gate verifies the metadata contract, prepares a temporary aws-dev values
file through `promote-demo-api-image.sh`, renders the digest-pinned Deployment,
and proves that metadata for a different source commit is rejected.

## Feature-Branch Validation

Dispatch `demo-api image publish` on:

```text
feature/v0.7-cicd-gitops-promotion
```

with:

```text
create_promotion_pr = true
promotion_base_branch = feature/v0.7-cicd-gitops-promotion
```

Expected result:

1. `quality-gates` passes;
2. `build-and-push` publishes and attests the image;
3. `promote-aws-dev` creates `release/demo-api-sha-<short-commit>`;
4. a PR targets the feature branch and changes only
   `apps/demo-api/helm/values-aws-dev.yaml`;
5. rerunning the same workflow reuses the branch and PR.

## Version Boundary

v0.7.2 automates promotion preparation only. v0.7.3 adds end-to-end
traceability across desired Git state, Argo CD revision, Kubernetes Pod image
ID, and the demo-api application version.
