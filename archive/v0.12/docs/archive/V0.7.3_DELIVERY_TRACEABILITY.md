# v0.7.3 Delivery Traceability

## Goal

Correlate the release identity from source and image build through reviewed Git
desired state, Argo CD reconciliation, Kubernetes runtime identity, and the
application-reported version.

## Delivered

- full source commit and workflow run ID retained by Promotion PRs;
- image and build identity rendered as workload and Pod annotations;
- runtime version reflected in the standard application version label;
- values-only promotion commit validation;
- exact Argo CD revision comparison;
- Deployment image and application-version validation;
- every Pod's digest-backed container `imageID` validation;
- every Pod's `/version` identity validation.

## Boundary

The validator is read-only. GitHub Actions still builds the artifact and
prepares the Promotion PR, a human still approves promotion, Git still stores
desired state, and Argo CD still performs deployment.

The v0.7 feature branch validates metadata and rendering. The live trace runs
after the metadata-aware promotion commit reaches `main`, which is the branch
currently tracked by aws-dev.

## Next

v0.7.4 adds Git-based rollback and uses the trace validator for the final
end-to-end delivery exercise.
