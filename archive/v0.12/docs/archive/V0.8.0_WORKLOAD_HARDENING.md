# v0.8.0 Workload Hardening

## Scope

This increment establishes the runtime-hardening half of the v0.8.0 security
baseline for `demo-api`.

It does not introduce namespace admission controls, network policies, external
secrets, credential rotation, or TLS. Those capabilities remain assigned to
later v0.8 increments.

## Implemented controls

- The runtime image uses fixed UID/GID `10001:10001`.
- The Pod and container require non-root execution.
- The root filesystem is read-only.
- All Linux capabilities are dropped.
- Privilege escalation is disabled.
- The Pod uses the `RuntimeDefault` seccomp profile.
- Kubernetes ServiceAccount token automounting is disabled.
- A memory-backed, size-limited `/tmp` volume is the only explicitly writable
  runtime path.

## Validation

Run:

```bash
./scripts/validate-demo-api-workload-security.sh
```

The validation:

1. lints and renders both local and `aws-dev` Helm releases;
2. verifies the required workload security settings;
3. runs the application unit tests in the image test stage;
4. verifies the final image user is `10001:10001`;
5. confirms that the root filesystem rejects writes while `/tmp` remains
   writable; and
6. starts the restricted container and checks `/health`.

The existing CI quality-gate script invokes this validation automatically.

## Expected result

```text
demo-api workload security validation passed.
```
