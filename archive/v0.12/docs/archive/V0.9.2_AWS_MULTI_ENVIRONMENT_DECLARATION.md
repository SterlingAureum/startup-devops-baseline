# v0.9.2 AWS Multi-Environment Declaration

Status: Static implementation complete; no aws-test or aws-prod resources applied

## Objective

Declare three isolated AWS environments without copying three complete GitOps
trees or requiring three continuously running EKS clusters.

```text
aws-dev  -> first cloud integration environment
aws-test -> ephemeral pre-production environment
aws-prod -> persistent production governance target
```

This increment changes repository desired state only. It does not run
`terraform apply`, create a new cluster, copy a Secret, or promote an image.

## GitOps Layout

```text
clusters/aws/
├── base/
│   ├── platform/
│   ├── data-platform/
│   └── security/
└── overlays/
    ├── dev/
    ├── test/
    └── prod/
```

The base contains one copy of shared Argo CD Applications, operators,
Karpenter policies, CloudNativePG resources, External Secrets resources, and
NetworkPolicies. Overlays own cluster names, discovery tags, release values
paths, environment-local Secret keys, and network CIDRs.

The active aws-dev root now tracks `clusters/aws/overlays/dev`. Its rendered
resource names, Helm values, Karpenter identities, Secret key, and NetworkPolicy
CIDRs remain equivalent to the previous `clusters/aws-dev` tree.

## Terraform Layout

```text
infra/terraform/aws/environments/
├── dev/
├── test/
└── prod/
```

Each directory is an independent root with its own local state. Shared AWS
implementation remains in `infra/terraform/aws/modules`; Terraform CLI
workspaces are not used as the environment boundary.

| Contract | dev | test | prod |
|---|---|---|---|
| Cluster | `startup-devops-baseline-dev` | `startup-devops-baseline-test` | `startup-devops-baseline-prod` |
| VPC | `10.20.0.0/16` | `10.30.0.0/16` | `10.40.0.0/16` |
| Service CIDR | `172.20.0.0/16` | `172.21.0.0/16` | `172.22.0.0/16` |
| DNS | `demo.dev.aureumstack.com` | `demo.test.aureumstack.com` | `demo.prod.aureumstack.com` |
| Log retention | 14 days | 30 days | 90 days minimum |
| NAT | Single | Single | One per AZ |
| Backup force destroy | `true` | `true` | rejected |
| Secret recovery | 0 days | 7 days | 30 days required |

The environment suffix also isolates IAM roles, the Secrets Manager Secret,
the CloudNativePG backup bucket, Karpenter queues and discovery tags, and ACM
certificate identity. Secret values and database data remain environment-local.

## Production Safety Boundary

The production Terraform root rejects:

- `environment` values other than `prod`;
- `single_nat_gateway = true`;
- `cnpg_backup_force_destroy = true`;
- EKS control-plane log retention below 90 days;
- a Secrets Manager recovery window other than 30 days.

The production declarations also omit AWS FIS infrastructure and remove the
FIS-only EC2NodeClass and NodePool from the rendered overlay.

## Validation

Required local checks:

```bash
./scripts/validate-aws-environment-declarations.sh
./scripts/validate-terraform.sh
./scripts/validate-ci-quality-gates.sh
```

The first command renders the platform, PostgreSQL, External Secrets, and both
NetworkPolicy overlays for dev, test, and prod. Terraform validation runs
`fmt`, `init -backend=false`, and `validate` for all three independent roots.
