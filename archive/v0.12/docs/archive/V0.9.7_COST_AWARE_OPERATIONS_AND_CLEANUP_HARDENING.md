# v0.9.7 Cost-Aware Operations and Cleanup Hardening

## Status

Implementation complete. Static validation is part of the reusable quality
gate. No cluster rebuild is required solely for this increment; verify the
runtime profile switch during the next temporary aws-dev or aws-test session.

## Purpose

Close two operational gaps found during the v0.9 live acceptance:

1. production-grade control-plane logging should remain available without
   charging every disposable development session for audit ingestion; and
2. post-destroy auditing must distinguish billable EC2 Fleet capacity from
   terminal Instant Fleet history retained by AWS APIs.

This increment does not add v0.10 delivery orchestration.

## Logging profiles

| Environment | Default profile | Enabled types | Retention |
|---|---|---|---:|
| aws-dev | `off` | none | 14 days |
| aws-test | `off` | none | 30 days |
| aws-prod | `production-parity` | all five EKS types | 90 days minimum |

The Terraform-managed log group remains present when ingestion is off, so
retention and ownership do not drift. Turning ingestion off does not delete
existing events or reverse CloudWatch usage already recorded for the month.

Before a formal production-parity validation:

```bash
AWS_ENVIRONMENT=aws-dev \
EKS_CONTROL_PLANE_LOGGING_PROFILE=production-parity \
CONFIRM_EKS_LOGGING_PROFILE=apply-eks-logging-profile \
  ./scripts/apply-eks-control-plane-logging-profile.sh

AWS_ENVIRONMENT=aws-dev \
  ./scripts/validate-tls-dns-security-aws.sh
```

After evidence collection, return a disposable environment to the no-ingestion
profile:

```bash
AWS_ENVIRONMENT=aws-dev \
EKS_CONTROL_PLANE_LOGGING_PROFILE=off \
CONFIRM_EKS_LOGGING_PROFILE=apply-eks-logging-profile \
  ./scripts/apply-eks-control-plane-logging-profile.sh
```

Use `AWS_ENVIRONMENT=aws-test` for the temporary test cluster. The aws-prod
Terraform root and guarded script both refuse the `off` profile.

The management-IP updater now preserves the live log types by default. An IP
change therefore cannot silently switch a cost profile:

```bash
AWS_ENVIRONMENT=aws-dev \
CONFIRM_EKS_API_CIDR_UPDATE=restrict-current-ip \
  ./scripts/apply-eks-api-access-cidr.sh
```

## EC2 Fleet terminal-state audit

The Resource Groups Tagging API can continue returning Karpenter-created
Instant Fleet ARNs after instances and other billable resources are gone. The
cleanup audit now calls `DescribeFleets` for only those tagged Fleet ARNs and
uses the following policy:

| Fleet result | Audit result | Operator action |
|---|---|---|
| `deleted` | accepted terminal history | none |
| `deleted_terminating` | accepted asynchronous terminal history | wait; do not repeat deletion |
| `InvalidFleetId.NotFound` | accepted expired history | none |
| `active`, `submitted`, `modifying`, `deleted_running`, or unknown | failure | inspect Fleet and associated instances |
| lookup denied or otherwise fails | failure | restore read permission and rerun |

The audit deliberately does not use `DescribeFleetInstances`: the observed
Karpenter records are Instant Fleet, for which that lookup is not a valid
cleanup dependency. Exact EC2 instance checks remain authoritative for
continuing compute capacity.

Run the audit normally after destroy:

```bash
AWS_ENVIRONMENT=aws-dev \
  ./scripts/validate-aws-cost-cleanup.sh

AWS_ENVIRONMENT=aws-test \
  ./scripts/validate-aws-cost-cleanup.sh
```

Terminal Fleet history may be printed as accepted context, but it no longer
causes a false cost-residual failure. Every non-terminal or unrelated tagged
resource still fails closed.

## Validation

```bash
./scripts/validate-eks-control-plane-logging-profiles.sh
./scripts/validate-v0.9-lifecycle-contracts.sh
./scripts/validate-ci-quality-gates.sh
./scripts/validate-terraform.sh
```

The first three checks are local and do not create AWS resources. Terraform
validation initializes providers with backend access disabled and does not
apply infrastructure.

## Boundary

v0.9.7 hardens cost-aware operations discovered during v0.9 acceptance. It
does not automate image publication, evidence chaining, environment promotion,
PR merge, infrastructure creation, or production approval. Those mechanical
delivery steps belong to v0.10; production risk decisions remain human gated.
