# v0.9.8 Manual Multi-Environment Release Runbook

## Status

Implementation complete. This documentation-only increment requires the
normal repository quality gate but no AWS cluster creation or live release
repetition.

## Purpose

The v0.9 release model was implemented and live-tested across aws-dev and
aws-test, with a governed static aws-test-to-aws-prod Promotion. Its operator
instructions were distributed across workflow definitions, governance
documents, progressive-delivery guidance, and the clean-room lifecycle.

v0.9.8 creates one canonical procedure that a future operator can execute or
audit without reconstructing commands from repository internals.

## Delivered documentation

`docs/MULTI_ENVIRONMENT_RELEASE_RUNBOOK.md` now covers:

- one-time GitHub Actions, Environment, branch-protection, and CODEOWNERS
  configuration;
- local authentication, clean-main, EKS endpoint, and static preflight checks;
- immutable image publication and aws-dev release PR review;
- explicit local runtime-evidence IDs and GitHub qualification workflow run
  IDs;
- evidence-only branch, PR, review, and merge requirements;
- exact dev-to-test and test-to-prod workflow inputs;
- temporary aws-test creation, bootstrap, reviewed Rollout completion,
  AnalysisRun checks, and runtime qualification;
- safe cluster destruction before static production Promotion;
- evidence freshness, source-release binding, and rebuild criteria;
- common failure recovery and an end-to-end acceptance checklist.

The Runbook explicitly uses the actual workflow input:

```text
evidence_run_id
```

and removes the obsolete documentation-only name:

```text
release_evidence_run_id
```

## Governance boundary

The procedures preserve the v0.9 controls:

```text
mechanical preparation by GitHub Actions
-> reviewed evidence PRs
-> target GitHub Environment approval
-> CODEOWNERS-protected release-only PR
-> Argo CD reconciliation only after merge
```

They also distinguish portfolio and production reviewer models. A solo
portfolio maintainer must not combine self-review prevention with no eligible
second reviewer. A real production environment should require a distinct
reviewer and prevent the workflow initiator from approving their own run.

## Validation

```bash
git diff --check
rg -n 'release_evidence_run_id' docs README.md CHANGELOG.md
./scripts/validate-ci-quality-gates.sh
```

The `rg` command may find the obsolete identifier only in historical or
explanatory text that warns against it. Active command examples and workflow
inputs must use `evidence_run_id`.

## Boundary

v0.9.8 does not modify workflow behavior, evidence schemas, release files,
cluster declarations, or Terraform. It does not automate PR merging or create
aws-prod. End-to-end orchestration, resumption, automatic evidence chaining,
and retained production approval remain v0.10 scope.
