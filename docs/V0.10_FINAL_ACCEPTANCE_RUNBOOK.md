# v0.10 Final Clean-Room Acceptance Runbook

This is the canonical v0.10.8 operator procedure. It validates the complete
resumable release path on protected `main`, records interruption and recovery
behavior, destroys the disposable AWS environments, and closes v0.10 with one
append-only evidence record.

The accepted path is:

```text
protected main
  -> immutable image
  -> reviewed aws-dev release
  -> reviewed aws-dev Qualification Bundle
  -> reviewed aws-test release
  -> manually completed aws-test Canary
  -> reviewed aws-test Qualification Bundle
  -> aws-prod Environment approval
  -> reviewed aws-prod release-only PR
  -> prod-static closure
```

`prod-static` is a hard boundary. This runbook does not create an aws-prod EKS
cluster, run production qualification, obtain production runtime credentials,
write Kubernetes, merge automatically, or roll back automatically.

## 1. Closure rule

v0.10.8 has two phases but one final version:

1. merge the v0.10.8 contracts, scripts, and this Runbook into `main`;
2. run live acceptance from that protected `main`, merge the evidence-only PR,
   then create tag `v0.10.8` on the evidence merge commit.

Do not generate a success record on the feature branch. Do not pre-populate
run IDs, PR numbers, cleanup timestamps, or Qualification Bundle paths. Do not
tag before the final evidence PR is merged.

## 3. One-time GitHub governance

In **Settings -> Actions -> General -> Workflow permissions**, retain:

- **Read and write permissions**;
- **Allow GitHub Actions to create and approve pull requests** enabled.

The repository setting permits PR creation; job-level permissions remain
narrower. No workflow calls a PR approval or merge command.

Create or verify these GitHub Environments:

| Environment | Purpose | Required setting |
| --- | --- | --- |
| `aws-dev` | reviewed dev rollback PR boundary | `main` only |
| `aws-test` | test Promotion/rollback PR boundary | `main` only |
| `aws-prod` | production static Promotion | designated human reviewer, `main` only |
| `aws-dev-runtime` | trusted dev qualification | `main` only; runtime role variables |
| `aws-test-runtime` | trusted test qualification | `main` only; runtime role variables |

Set these variables in each runtime Environment from the persistent
`infra/terraform/aws/runtime-identities` Terraform output described in section
7:

```text
AWS_RUNTIME_ROLE_ARN=<environment-specific github_actions_runtime_role_arn>
AWS_REGION=us-east-1
```

For a team repository, protect `main` with an independent PR approval,
CODEOWNERS approval, current-branch enforcement, and these exact required
checks:

```text
validate / quality-gates
validate / demo-api release currentness
```

GitHub does not allow a PR author to approve the same PR. For a
single-maintainer portfolio repository, retain the PR boundary, current-branch
enforcement, required checks, and conversation resolution, but configure zero
required approvals and do not require CODEOWNERS approval. Inspect every diff
before the manual merge and record that this is not independent review. Restore
at least one independent approval and CODEOWNERS approval when another trusted
maintainer exists. For the `aws-prod` Environment, do not combine **Prevent
self-review** with the maintainer as the only eligible reviewer. These
portfolio exceptions must never replace real team production policy.

## 6. Prove Release supersede

Keep all four activation variables false. This checkpoint creates two source
PRs and two automatically generated release PRs; do not confuse the two types:

1. Create source branch A from current `main`, make one legitimate change under
   `apps/demo-api/src/` or `apps/demo-api/tests/`, open its source PR, wait for
   validation, and merge it.
2. Wait for image publish to create aws-dev Release PR A. Record its PR number,
   but do not merge it.
3. Pull the new `main`, create source branch B from that revision, make a second
   legitimate change in the same allowed source/test scope, open its source PR,
   wait for validation, and merge it. B must descend from A.
4. Wait for image publish to create the newer aws-dev Release PR B. Record its
   PR number, but do not merge it yet.

Release PRs created by `github-actions[bot]` can display **Action required**.
After both release PRs exist, open each pending `validate` run and select
**Approve and run**. Release A must pass quality gates but fail `demo-api
release currentness`; Release B must pass both checks. If A was approved before
B existed, its currentness check can initially pass, so re-run A's `validate`
after B exists and retain the expected failure.

Derive both deterministic Release IDs from the generated release PR revisions,
not from a branch name or the seven-character image tag:

```bash
export RELEASE_A_PR=<old-aws-dev-release-pr-number>
export RELEASE_B_PR=<new-aws-dev-release-pr-number>

git fetch --force --no-tags origin \
  "pull/${RELEASE_A_PR}/head:refs/remotes/origin/v010-release-a"
git fetch --force --no-tags origin \
  "pull/${RELEASE_B_PR}/head:refs/remotes/origin/v010-release-b"

git show \
  refs/remotes/origin/v010-release-a:apps/demo-api/helm/values/releases/aws-dev.yaml \
  > /tmp/demo-api-release-a.yaml
git show \
  refs/remotes/origin/v010-release-b:apps/demo-api/helm/values/releases/aws-dev.yaml \
  > /tmp/demo-api-release-b.yaml

export RELEASE_A_ID="$(
  ./scripts/derive-demo-api-release-id.py \
    --release-file /tmp/demo-api-release-a.yaml
)"
export RELEASE_B_ID="$(
  ./scripts/derive-demo-api-release-id.py \
    --release-file /tmp/demo-api-release-b.yaml
)"

printf 'Release A: PR #%s %s\n' "${RELEASE_A_PR}" "${RELEASE_A_ID}"
printf 'Release B: PR #%s %s\n' "${RELEASE_B_PR}" "${RELEASE_B_ID}"
```

Run read-only status for Release A:

```bash
gh workflow run demo-api-release-orchestrator.yaml \
  --ref main \
  -f operation=status \
  -f release_id="${RELEASE_A_ID}" \
  -f policy=reviewed
```

Find and watch the new top-level orchestrator run, then record both checkpoint
identities explicitly:

```bash
gh run list \
  --workflow demo-api-release-orchestrator.yaml \
  --event workflow_dispatch \
  --limit 5

export SUPERSEDE_STATUS_RUN_ID=<new-status-run-id>
export SUPERSEDED_RELEASE_PR="${RELEASE_A_PR}"

gh run watch "${SUPERSEDE_STATUS_RUN_ID}"
printf 'github.runs.supersedeStatus=%s\n' "${SUPERSEDE_STATUS_RUN_ID}"
printf 'github.pullRequests.supersededRelease=%s\n' "${SUPERSEDED_RELEASE_PR}"
```

The run summary must report:

```text
status: superseded
reason: newer-release-active
recommendedAction: review-and-close-superseded-pr
dispatchAuthorized: false
```

Confirm the old release PR currentness check failed, review it, and close it
manually. The workflow must not close it. Review and merge only Release B's
release-only aws-dev PR. The final evidence input later stores the
`supersedeStatus` run ID under `github.runs.supersedeStatus` and Release PR A
under `github.pullRequests.supersededRelease`. `supersededRelease` always means
the stale, human-closed **PR A**, never the selected and merged PR B. PR B has
no separate final-input field; its Release identity is derived later from the
three merged environment Release files and the reviewed Qualification Bundles.

## 9. Interrupted run and idempotent recovery

This checkpoint proves recovery at a deterministic durability boundary. The
trusted runtime Job completes first; the acceptance-only checkpoint then holds
the GitHub-hosted control path before any Qualification Bundle branch or PR is
created. Cancel during that hold rather than racing the runtime collector.

`run ID` identifies a workflow execution. `runner_id` identifies the registered
self-hosted runner that accepted the trusted Job. Merely restarting `run.sh`
does not create a new registration. Follow the clean-directory `--ephemeral`
procedure in `TRUSTED_RUNTIME_EXECUTOR.md`.

### 9.1 Establish a legitimate requalification condition

Do not delete, edit, or revert an already merged append-only Bundle. Continue
only when the planner reports aws-dev qualification is required because the
current Bundle is missing, expired, scope-drifted, or release-drifted. For an
already merged but procedurally unacceptable Bundle, inspect its natural
expiry and wait until it is expired:

```bash
export CURRENT_DEV_BUNDLE="$(
  find "evidence/demo-api/qualification/aws-dev/${RELEASE_B_ID}" \
    -maxdepth 1 -type f -name '*.json' -print \
    | sort \
    | tail -n 1
)"

jq -r '{path: input_filename, recordedAt, expiresAt}' \
  "${CURRENT_DEV_BUNDLE}"
```

Do not keep a second Qualification Bundle PR open. If a prior attempt created
an unmerged PR, close it before the new pair. A previously merged Bundle stays
in Git as historical append-only evidence but must not be selected in the
final input when its runner isolation was not proven.

Stop the earlier persistent runner and remove its registration from
**Settings -> Actions -> Runners** before registering runner A. If it remains
eligible, GitHub may schedule the next trusted Job onto that old `runner_id`
even while a new runner is online.

### 9.2 Create the interrupted run

Configure runner A from a clean runner distribution directory using a new
registration token, `--ephemeral`, and the labels:

```text
self-hosted, linux, x64, trusted-runtime, aws-dev
```

Dispatch an explicitly armed reviewed resume:

```bash
gh workflow run demo-api-release-orchestrator.yaml \
  --ref main \
  -f operation=resume \
  -f release_id="${RELEASE_B_ID}" \
  -f acceptance_interrupt_checkpoint=armed \
  -f policy=reviewed
```

Record the run ID. Wait until this Job is running:

```text
Gate durable Qualification Bundle creation
  -> Hold after runtime qualification for deterministic cancellation
```

The summary must say that runtime qualification completed and no Bundle branch
or PR exists. Cancel the entire workflow:

```bash
export INTERRUPTED_RUN_ID=<armed-run-id>
gh run cancel "${INTERRUPTED_RUN_ID}"
gh run watch "${INTERRUPTED_RUN_ID}"
```

The overall conclusion must be `cancelled`. The hold fails closed after nine
minutes if it is not cancelled. Confirm no new Qualification Bundle PR was
created, and confirm runner A has automatically unregistered before proceeding.

### 9.3 Resume on a different registration

Configure runner B from another clean directory and a new registration token.
Its later Jobs API `runner_id` must differ from runner A. Run the same reviewed
resume with the checkpoint explicitly disabled:

```bash

  --ref main \

  -f release_id="${RELEASE_B_ID}" \
  -f acceptance_interrupt_checkpoint=disabled \
  -f policy=reviewed
```

Allow it to finish and record:

```bash

```


The validator must report two different positive `runnerId` values and
`automaticUnregistrationVerified: true`. Only this validated pair may populate
the final `interrupted`, `resumed`, and `github.runnerIsolation` fields.

If the same `runner_id` handled both Jobs, do not retry only the final resume
against a fresh Bundle: it will skip qualification. Preserve the merged Bundle,
wait for a legitimate missing/expired/drifted state, and repeat both sections
9.2 and 9.3.

## 14. Validate the governed rollback boundary

This checkpoint does **not** roll back aws-test. It proves that a selected
historical immutable Release can be restored only through a workflow-proven,
single-file, human-reviewed PR. The PR is closed without merge, so `main`,
Argo CD, and the qualified aws-test workload remain on Release B.

The automatic resolver normally selects the most recent previous distinct
target-release-only commit. The manual workflow can accept an older historical
commit, but only when that commit belongs to `main`, changed exactly the target
Release file, and carries a complete immutable delivery identity.

### 14.1 Refresh main and run the deterministic gate

Start from the main revision that contains the merged section 13 aws-test
Qualification Bundle:

```bash
git switch main
git pull --ff-only origin main
test -z "$(git status --short)"
```

Run the offline recovery/currentness fixtures:

```bash
./scripts/validate-demo-api-orchestration-recovery.sh
```

The final line must be:

```text
Retry, Attempt, supersede, expiry policy, and governed rollback handoff tests passed.
```

This gate uses temporary Git repositories. It does not call GitHub, AWS, EKS,
or Argo CD and does not modify the checked-out repository. It verifies both
that a stale ordinary Promotion PR is rejected and that a workflow-proven
historical rollback PR passes the same required currentness check. A branch
named `rollback/*` without matching history, metadata, and workflow-run
provenance remains rejected.

### 14.2 Derive the current Release and historical candidate

Re-derive Release B from the merged aws-test Release file instead of reusing an
unverified shell value:

```bash
export RELEASE_B_ID="$(
  ./scripts/derive-demo-api-release-id.py \
    --release-file apps/demo-api/helm/values/releases/aws-test.yaml
)"
```

Copy the input template outside the repository and replace every placeholder


| --- | --- |

```bash

  --arg main_sha "${ACCEPTED_MAIN_SHA}" \
```

```bash
    (.validatedControlPlaneSha | test("^[0-9a-f]{40}$")) and
```

The writer derives the final Release identity, release-file hashes, Bundle
hashes, acceptance contract hash, and deterministic control-plane Scope from
the repository. It refuses a dirty worktree, a different checked-out SHA,
missing evidence, unsafe production claims, incomplete cleanup, or placeholder
run/PR identities.


## 19. Failure recovery

| Failure | Required continuation |
| --- | --- |
| Orchestrator cancelled | Fix no durable state; run a new `resume` from current facts. |
| Exact safe Attempt failed | Use `retry` with its run ID, run attempt, and Release ID. |
| Environment absent | Restore it manually, start a fresh runner, then `resume`. |
| Main advanced | Pull current `main`; recompute instead of reusing the stale plan. |
| Bundle expired or drifted | Generate a new same-run static/runtime Qualification Bundle; never edit JSON. |
| Interrupted/resumed Jobs share one `runner_id` | Preserve merged evidence, establish a legitimate requalification condition, then repeat both interruption and resume with two clean ephemeral registrations. |
| Release superseded | Review and close the stale PR manually; continue with the newer Release. |
| Rollback PR prepared | Review it as a separate human decision; the orchestrator never dispatches or merges it. |
| Cleanup residual found | Remove the exact owned residual and rerun the audit; never delete state to hide it. |
| Final evidence rejected | Correct the underlying fact; never change a `false` production boundary to claim success. |
