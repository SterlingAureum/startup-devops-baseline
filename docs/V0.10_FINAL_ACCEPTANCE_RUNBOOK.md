# v0.10 Final Clean-Room Acceptance Runbook

This is the canonical v0.10.8 operator procedure. It validates the complete
resumable release path on protected `main`, records interruption and recovery
behavior, destroys the disposable AWS environments, and closes v0.10 with one
append-only evidence record.

The accepted path is:

```text
protected main
  -> immutable image
  -> reviewed aws-dev release
  -> reviewed aws-dev Qualification Bundle
  -> reviewed aws-test release
  -> manually completed aws-test Canary
  -> reviewed aws-test Qualification Bundle
  -> aws-prod Environment approval
  -> reviewed aws-prod release-only PR
  -> prod-static closure
```

`prod-static` is a hard boundary. This runbook does not create an aws-prod EKS
cluster, run production qualification, obtain production runtime credentials,
write Kubernetes, merge automatically, or roll back automatically.

## 1. Closure rule

v0.10.8 has two phases but one final version:

1. merge the v0.10.8 contracts, scripts, and this Runbook into `main`;
2. run live acceptance from that protected `main`, merge the evidence-only PR,
   then create tag `v0.10.8` on the evidence merge commit.

Do not generate a success record on the feature branch. Do not pre-populate
run IDs, PR numbers, cleanup timestamps, or Qualification Bundle paths. Do not
tag before the final evidence PR is merged.

## 2. Apply and validate the tooling increment

Apply the v0.10.8 increment to the locally validated v0.10.7 branch. Before
commit, run:

```bash
./scripts/validate-v0.10-final-acceptance.sh
./scripts/validate-demo-api-release-orchestrator.sh
./scripts/validate-demo-api-qualification-bundle.sh
./scripts/validate-trusted-runtime-executor.sh
./scripts/validate-ci-quality-gates.sh
terraform fmt -check -recursive
./scripts/validate-aws-environment-declarations.sh
git diff --check
```

Review and merge the feature PR. The real workflows are accepted only after
they exist on `main`.

## 3. One-time GitHub governance

In **Settings -> Actions -> General -> Workflow permissions**, retain:

- **Read and write permissions**;
- **Allow GitHub Actions to create and approve pull requests** enabled.

The repository setting permits PR creation; job-level permissions remain
narrower. No workflow calls a PR approval or merge command.

Create or verify these GitHub Environments:

| Environment | Purpose | Required setting |
| --- | --- | --- |
| `aws-dev` | reviewed dev rollback PR boundary | `main` only |
| `aws-test` | test Promotion/rollback PR boundary | `main` only |
| `aws-prod` | production static Promotion | designated human reviewer, `main` only |
| `aws-dev-runtime` | trusted dev qualification | `main` only; runtime role variables |
| `aws-test-runtime` | trusted test qualification | `main` only; runtime role variables |

Set these variables in each runtime Environment from its matching Terraform
output:

```text
AWS_RUNTIME_ROLE_ARN=<environment-specific github_actions_runtime_role_arn>
AWS_REGION=us-east-1
```

Protect `main` with PR review, CODEOWNERS review, current-branch enforcement,
and these exact required checks:

```text
validate / quality-gates
validate / demo-api release currentness
```

For a single-maintainer portfolio repository, do not combine **Prevent
self-review** with the maintainer as the only eligible reviewer. Record that
portfolio limitation; do not bypass a real team production policy.

## 4. Initialize repository switches

The four stage switches are repository variables. Start disabled:

```bash
for variable in \
  DEMO_API_AWS_DEV_QUALIFICATION_ENABLED \
  DEMO_API_AWS_TEST_PROMOTION_ENABLED \
  DEMO_API_AWS_TEST_QUALIFICATION_ENABLED \
  DEMO_API_AWS_PROD_PROMOTION_ENABLED; do
  gh variable set "${variable}" --body false
done
```

Authenticate and prove that local `main` is exact and clean:

```bash
gh auth status
aws sts get-caller-identity

git switch main
git pull --ff-only origin main
test -z "$(git status --short)"
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"
export ACCEPTED_MAIN_SHA="$(git rev-parse HEAD)"
```

Run the final static readiness gate:

```bash
./scripts/validate-v0.10-final-acceptance.sh
./scripts/validate-ci-quality-gates.sh
./scripts/validate-aws-environment-declarations.sh
```

## 5. Prove `status` is read-only

Temporarily set every switch true so the result proves the operation boundary,
not merely a disabled switch:

```bash
for variable in \
  DEMO_API_AWS_DEV_QUALIFICATION_ENABLED \
  DEMO_API_AWS_TEST_PROMOTION_ENABLED \
  DEMO_API_AWS_TEST_QUALIFICATION_ENABLED \
  DEMO_API_AWS_PROD_PROMOTION_ENABLED; do
  gh variable set "${variable}" --body true
done

gh workflow run demo-api-release-orchestrator.yaml \
  --ref main \
  -f operation=status \
  -f policy=reviewed
```

Record the new run as `statusReadOnly`. Its summary and Attempt artifact must
show `dispatchAuthorized=false`, `outcome=no_action`, and
`reason=read-only-status`. No qualification or Promotion stage may succeed.

Disable the four switches again before continuing.

## 6. Prove Release supersede

Use two legitimate, reviewed changes under `apps/demo-api/src/` or
`apps/demo-api/tests/`. Let source change A publish an image and create its
aws-dev release PR, but do not merge that release PR. Merge source change B to
`main` and let it create the newer aws-dev release PR.

Resolve Release A from its release values and run:

```bash
gh workflow run demo-api-release-orchestrator.yaml \
  --ref main \
  -f operation=status \
  -f release_id="${RELEASE_A_ID}" \
  -f policy=reviewed
```

Record the run as `supersedeStatus`. It must report:

```text
status: superseded
reason: newer-release-active
recommendedAction: review-and-close-superseded-pr
dispatchAuthorized: false
```

Confirm the old release PR currentness check fails, review it, and close it
manually. The workflow must not close it. Continue only with Release B and
merge its release-only aws-dev PR.

## 7. Environment-absent resume

Keep aws-dev absent but start a correctly labelled single-job ephemeral runner
outside the target EKS cluster:

```text
self-hosted, linux, x64, trusted-runtime, aws-dev
```

Enable only dev qualification and resume Release B:

```bash
gh variable set DEMO_API_AWS_DEV_QUALIFICATION_ENABLED --body true

gh workflow run demo-api-release-orchestrator.yaml \
  --ref main \
  -f operation=resume \
  -f release_id="${RELEASE_B_ID}" \
  -f policy=reviewed
```

Record the run as `environmentAbsent`. The trusted result must be
`blocked / environment_absent`; it must not run Terraform or create EKS.

## 8. Rebuild aws-dev from reviewed main

Use the existing local, untracked dev `terraform.tfvars`. Never copy a state,
Secret, backup, or runtime evidence from another environment.

```bash
terraform -chdir=infra/terraform/aws/environments/dev init
terraform -chdir=infra/terraform/aws/environments/dev plan -out=tfplan
terraform -chdir=infra/terraform/aws/environments/dev show tfplan
terraform -chdir=infra/terraform/aws/environments/dev apply tfplan

./scripts/bootstrap-eks-argocd.sh
./scripts/deploy-aws-dev-root-app.sh
```

The dev Terraform input must enable the GitHub Actions runtime identity and use
the account-level GitHub OIDC provider described in
`TRUSTED_RUNTIME_EXECUTOR.md`. Update the `aws-dev-runtime` role variable from
the resulting Terraform output and allow the dev runtime RBAC Application to
sync.

If the current public egress address changed:

```bash
AWS_ENVIRONMENT=aws-dev \
CONFIRM_EKS_API_CIDR_UPDATE=restrict-current-ip \
  ./scripts/apply-eks-api-access-cidr.sh
```

Never commit the `/32` and never widen the endpoint to `0.0.0.0/0`.

## 9. Interrupted run and idempotent recovery

Start a fresh `aws-dev` ephemeral runner and resume Release B. While the
trusted runtime job is passively waiting for the exact Argo/workload revision,
cancel the orchestrator run from GitHub. Record it as `interrupted`.

After the cluster and Application are healthy, start another single-job runner
and run the same resume command. Record it as `resumed`.

The recovery run must derive facts again and must not create a second release
PR or duplicate Qualification Bundle PR. If a matching PR already exists, the
orchestrator must reuse it.

## 10. Complete aws-dev qualification

Continue `resume` until the orchestrator creates one reviewed aws-dev
Qualification Bundle PR. Record the successful run as `devQualification` and
the PR number as `devQualification`.

Review that the PR adds exactly one file beneath:

```text
evidence/demo-api/qualification/aws-dev/<release-id>/<run>-<attempt>.json
```

Merge it, update local `main`, and save the exact path for final evidence.

The exact `retry` lineage and Bundle `expiring/expired/scope_drift/
release_drift` transitions are deterministic acceptance checkpoints:

```bash
./scripts/validate-demo-api-orchestration-recovery.sh
./scripts/validate-demo-api-qualification-bundle.sh
```

This intentionally uses a controlled clock for expiry rather than keeping a
billable EKS cluster alive merely to wait 24 hours. The live dev and test
Qualification runs prove the real requalification path.

## 11. Prepare and bootstrap aws-test

Create the clean-room test environment from the current reviewed `main`:

```bash
CONFIRM_AWS_TEST_APPLY=apply-ephemeral-aws-test \
  ./scripts/apply-aws-test.sh

CONFIRM_AWS_TEST_BOOTSTRAP=bootstrap-ephemeral-aws-test \
  ./scripts/bootstrap-aws-test.sh
```

If apply was interrupted after resources entered state, inspect the state and
resume it. Do not delete state or start a replacement environment:

```bash
AWS_TEST_APPLY_MODE=resume \
CONFIRM_AWS_TEST_APPLY=apply-ephemeral-aws-test \
  ./scripts/apply-aws-test.sh
```

Configure `aws-test-runtime` from the test runtime-role output. Start an
ephemeral runner with:

```text
self-hosted, linux, x64, trusted-runtime, aws-test
```

## 14. Validate the governed rollback boundary

The deterministic gate proves that only eligible dev/test failures produce a
read-only handoff and that the resolver never dispatches the workflow:

```bash
./scripts/validate-demo-api-orchestration-recovery.sh
```

For the live workflow boundary, use a real historical target-release-only
revision for `aws-test` and dispatch the manual rollback workflow with the
current Release ID:

```bash
gh workflow run demo-api-rollback.yaml \
  --ref main \
  -f target_environment=aws-test \
  -f rollback_to_revision="${HISTORICAL_TEST_RELEASE_REVISION}" \
  -f expected_current_release_id="${RELEASE_B_ID}"
```

Record the run as `rollbackBoundary`. Review that the generated PR changes only
the aws-test release file and restores an existing immutable GHCR identity.
Close the PR without merging it. This accepts the manual PR boundary without
changing the qualified release or claiming that a synthetic live failure
occurred.

## 15. Complete prod-static Promotion

Enable the production Promotion switch and resume:

```bash
gh variable set DEMO_API_AWS_PROD_PROMOTION_ENABLED --body true

gh workflow run demo-api-release-orchestrator.yaml \
  --ref main \
  -f operation=resume \
  -f release_id="${RELEASE_B_ID}" \
  -f test_rollout_gate=reviewed-and-completed \
  -f policy=reviewed
```

Record the run as `prodPromotion`. A designated human approves the protected
`aws-prod` Environment. The resulting PR must change only:

```text
apps/demo-api/helm/values/releases/aws-prod.yaml
```

Review and merge it. Confirm all three release identities match:

```bash
diff -u \
  apps/demo-api/helm/values/releases/aws-dev.yaml \
  apps/demo-api/helm/values/releases/aws-test.yaml

diff -u \
  apps/demo-api/helm/values/releases/aws-test.yaml \
  apps/demo-api/helm/values/releases/aws-prod.yaml
```

No aws-prod kubeconfig, cluster, runtime runner, runtime Bundle, `kubectl`, or
Terraform apply belongs in this phase.

## 16. Destroy disposable environments and prove cleanup

Stop and unregister both ephemeral runners. Disable every activation variable:

```bash
for variable in \
  DEMO_API_AWS_DEV_QUALIFICATION_ENABLED \
  DEMO_API_AWS_TEST_PROMOTION_ENABLED \
  DEMO_API_AWS_TEST_QUALIFICATION_ENABLED \
  DEMO_API_AWS_PROD_PROMOTION_ENABLED; do
  gh variable set "${variable}" --body false
done
```

Destroy test first, then dev:

```bash
CONFIRM_AWS_ENVIRONMENT_DESTROY=destroy-aws-test-with-backups \
  ./scripts/destroy-aws-test.sh

AWS_ENVIRONMENT=aws-test \
  ./scripts/validate-aws-cost-cleanup.sh

CONFIRM_AWS_ENVIRONMENT_DESTROY=destroy-with-backups \
  ./scripts/destroy-aws-dev.sh

AWS_ENVIRONMENT=aws-dev \
  ./scripts/validate-aws-cost-cleanup.sh
```

Record the actual UTC completion timestamp after each cleanup audit passes.
Do not mark closure while the audit reports an active residual. Shared Route 53
domain/account-level OIDC resources are not disposable environment claims;
environment-owned EKS, VPC, NAT, ALB, EIP, EBS, Secret, log group, bucket, and
active fleet capacity must satisfy the existing exact audit.

## 17. Write the final evidence-only PR

Return to exact clean `main` after the production PR merge:

```bash
git switch main
git pull --ff-only origin main
test -z "$(git status --short)"
export ACCEPTED_MAIN_SHA="$(git rev-parse HEAD)"
```

Copy the input template outside the repository and replace every placeholder
with the recorded run IDs, PR numbers, Bundle paths, and UTC timestamps:

```bash
cp delivery/contracts/examples/v0.10-final-evidence-input.example.json \
  /tmp/v0.10-final-evidence-input.json
```

Set `validatedControlPlaneSha` to `${ACCEPTED_MAIN_SHA}`. Then write and
validate the append-only record:

```bash
export FINAL_EVIDENCE_ID="$(date -u +%Y%m%d%H%M%S)"

./scripts/write-v0.10-final-evidence.py \
  --input /tmp/v0.10-final-evidence-input.json \
  --output "evidence/v0.10/final/${FINAL_EVIDENCE_ID}.json"

./scripts/validate-v0.10-final-evidence.py \
  --evidence "evidence/v0.10/final/${FINAL_EVIDENCE_ID}.json"
```

The writer derives the final Release identity, release-file hashes, Bundle
hashes, acceptance contract hash, and deterministic control-plane Scope from
the repository. It refuses a dirty worktree, a different checked-out SHA,
missing evidence, unsafe production claims, incomplete cleanup, or placeholder
run/PR identities.

Create an evidence-only branch and PR:

```bash
git switch -c "evidence/v0.10-final-${FINAL_EVIDENCE_ID}"
git add "evidence/v0.10/final/${FINAL_EVIDENCE_ID}.json"
test "$(git diff --cached --name-only | wc -l)" -eq 1
git diff --cached
git commit -m "evidence: close v0.10 clean-room acceptance"
git push -u origin HEAD
gh pr create --base main --fill
```

Review and merge. The final evidence references the validated pre-evidence
`main` SHA while the acceptance Scope deliberately excludes the append-only
final record, so the evidence-only commit does not invalidate its own hash.

## 18. Final tag and closure checks

After the evidence PR is merged:

```bash
git switch main
git pull --ff-only origin main

FINAL_EVIDENCE_FILE="$(find evidence/v0.10/final -type f -name '*.json' | sort | tail -n1)"
./scripts/validate-v0.10-final-evidence.py --evidence "${FINAL_EVIDENCE_FILE}"
./scripts/validate-v0.10-final-acceptance.sh
./scripts/validate-ci-quality-gates.sh
git status --short

git tag -a v0.10.8 -m "v0.10 release orchestration final acceptance"
git push origin v0.10.8
```

The v0.10 line is closed only when the evidence record validates, both AWS
cleanup audits passed, the temporary runners stopped, activation variables are
disabled, and no production runtime claim was made.

## 19. Failure recovery

| Failure | Required continuation |
| --- | --- |
| Orchestrator cancelled | Fix no durable state; run a new `resume` from current facts. |
| Exact safe Attempt failed | Use `retry` with its run ID, run attempt, and Release ID. |
| Environment absent | Restore it manually, start a fresh runner, then `resume`. |
| Main advanced | Pull current `main`; recompute instead of reusing the stale plan. |
| Bundle expired or drifted | Generate a new same-run static/runtime Qualification Bundle; never edit JSON. |
| Release superseded | Review and close the stale PR manually; continue with the newer Release. |
| Rollback PR prepared | Review it as a separate human decision; the orchestrator never dispatches or merges it. |
| Cleanup residual found | Remove the exact owned residual and rerun the audit; never delete state to hide it. |
| Final evidence rejected | Correct the underlying fact; never change a `false` production boundary to claim success. |
