# v0.11.3.2 Prometheus No-Data Hardening

## Purpose

The v0.11.3.1 clean replay created Rollout revision 22 and
`AnalysisRun/demo-api-5b98fb8f59-22-2`. The correct Prometheus query returned an
empty vector while the newly created ServiceMonitor and Canary target were
still converging. The condition `result[0] >= 1` indexed that empty vector and
produced five consecutive `reflect: slice index out of range` errors. Argo
Rollouts aborted the revision.

This is a cold-start race in the analysis expression, not a repository URL,
Prometheus address, Service, or ServiceMonitor omission.

## Fail-Closed Repair

The Prometheus query and metric identity remain unchanged:

```promql
sum(up{job="demo-api-canary"})
```

The metric now delays its first measurement and checks the vector length before
indexing it:

```yaml
initialDelay: 60s
successCondition: len(result) > 0 && result[0] >= 1
```

An empty vector is therefore a failed measurement, never an expression Error
and never a successful gate. The existing 60-second Rollout pause remains, so
the clean local path has a bounded warm-up period before the first measurement.
The Chart patch version is `0.5.1`; the application version and metric schema do
not change.

## What Does Not Change

- The stable and Canary Services and their Rollouts-managed selectors.
- The application-owned ServiceMonitor and `job` relabeling.
- The Prometheus Service address or query.
- The two required successful measurements and failure limit.
- The six-step Canary sequence and indefinite human-controlled pause.
- Any AWS declaration, production permission, release orchestration, Promotion,
  or rollback workflow.

## Current Cluster Recovery

Keep revision 22 and its AnalysisRun as failure evidence. Do not use
`promote --full`. If Prometheus later returns a non-empty
`up{job="demo-api-canary"}` vector, a normal Rollout retry may restore the
working feature state:

```bash
kubectl argo rollouts retry rollout demo-api -n startup-apps
```

That retry is operational recovery only. It does not accept v0.11.3.2.
