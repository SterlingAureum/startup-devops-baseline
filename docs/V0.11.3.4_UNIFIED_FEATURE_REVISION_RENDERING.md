# v0.11.3.4 Unified Feature Revision Rendering

## Outcome

Local feature acceptance now has one Git revision input and one declarative
owner. The operator supplies `TARGET_REVISION`; the workflow resolves the
remote branch once to a full commit SHA, verifies that the local checkout is
that exact commit, and passes the SHA through the Root App-of-Apps to every
same-repository child Application.

The local-image values used by `demo-api` are also rendered by the Root. The
workflow no longer patches child revisions or Helm parameters with
`argocd app set` and `argocd app unset`.

## Revision and Version Boundaries

`TARGET_REVISION` means a pushed Git branch name or a full commit SHA. It is
deliberately not called `TARGET_VERSION`: the external Applications use the
same Argo CD `targetRevision` field for Helm Chart versions.

| Application | Source type | Feature behavior |
| --- | --- | --- |
| `startup-devops-root` | this Git repository | resolved feature SHA |
| `namespace-guardrails` | this Git repository | same resolved SHA |
| `demo-api` | this Git repository | same resolved SHA |
| `argo-rollouts` | external Helm repository | Chart `2.41.0` |
| `ingress-nginx` | external Helm repository | Chart `4.11.3` |
| `monitoring` | external Helm repository | Chart `88.5.0` |

The shared parameter therefore applies only to the three same-repository
Applications. It cannot overwrite external Chart versions.

## App-of-Apps Model

`clusters/local/platform` is a small Helm Chart:

```text
clusters/local/platform/
├── Chart.yaml
├── values.yaml
└── templates/
    ├── argo-rollouts.yaml
    ├── demo-api.yaml
    ├── ingress-nginx.yaml
    ├── monitoring.yaml
    └── namespace-guardrails.yaml
```

Stable values declare:

```yaml
git:
  repoURL: https://github.com/SterlingAureum/startup-devops-baseline.git
  targetRevision: HEAD

demoApi:
  localImage:
    enabled: false
```

The Root Application carries seven explicit Helm parameters: repository URL,
same-repository revision, local-image enablement, repository, tag, pull policy,
and application version. Stable mode sets `HEAD` and disables the local image.
Feature mode sets the resolved SHA and enables the four exact `demo-api` image
parameters.

## Immutable Feature Flow

```text
TARGET_REVISION branch
        |
        v
remote refs/heads lookup
        |
        v
one full commit SHA
        |
        +--> Root source revision
        +--> namespace-guardrails source revision
        +--> demo-api source revision
```

The workflow fails before Kubernetes mutation when:

- the remote feature branch does not exist;
- the remote result is ambiguous or is not a full SHA;
- the local checkout is not that remote SHA;
- tracked local changes remain uncommitted.

This prevents a branch update during acceptance from producing mixed source
commits.

## Root Ownership Semantics

Feature mode keeps Root automation disabled, but the Root is expected to be
`Synced`. Its rendered desired state already contains the exact child revision
and local-image parameters. A Root resync is therefore safe and no longer
resets children to `HEAD`.

The earlier `OutOfSync / Healthy` state was a bounded workaround for live child
overrides. It is superseded by this declarative model.

During a retained manual Canary pause, health may be `Suspended`; that does not
change the requirement that Root and children remain `Synced` and resolve the
same commit.

## Restoration Boundary Repaired by v0.11.3.5

The original v0.11.3.4 design assumed the Helm App-of-Apps migration had
already reached remote HEAD. A pre-merge replay disproved that assumption:
the Helm-shaped live Root targeted an older directory-only HEAD and Argo CD
could not find `Chart.yaml`.

Before merge, v0.11.3.5 uses
`restore-local-feature-baseline.sh` to render the Root with:

```text
Root revision:              resolved feature SHA
git.targetRevision:         resolved feature SHA
demoApi.localImage.enabled: false
```

The stable `demo-api` Application explicitly renders `parameters: []`, so Root
owns removal of feature image overrides. Restoration does not individually
patch child automation, revision, or Helm parameters. Root automation is
restored only after Root and same-repository children synchronize.

After merge, `restore-local-gitops-head.sh` retains the original HEAD result,
but a remote content preflight first requires HEAD to contain the platform
Chart. See `docs/V0.11.3.5_PRE_MERGE_BASELINE_RESTORATION.md`.

## Offline Validation

```bash
bash -n scripts/*.sh scripts/lib/*.sh
./scripts/validate-v0.11.3.4-unified-feature-revision-rendering.sh
./scripts/validate-active-gitops-revisions.sh
```

Where Helm is available, the v0.11.3.4 validator also lints and renders stable
and feature modes, then verifies:

- exactly five child Applications are rendered;
- only `namespace-guardrails` and `demo-api` receive the feature SHA;
- `demo-api` receives exactly four local-image parameters in feature mode;
- stable `demo-api` parameters are empty;
- external Chart versions remain unchanged.

The full Docker/Helm quality gate and GitHub `validate` workflow remain
required.

## Live Acceptance

After committing and pushing the exact source:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
  ./scripts/restore-local-feature-baseline.sh

IMAGE_TAG=v0.11.3-local \
  ./scripts/build-load-demo-api-image.sh

TARGET_REVISION=feature/v0.11-observability-sre-baseline \
IMAGE_TAG=v0.11.3-local \
  ./scripts/deploy-local-feature-gitops.sh
```

Required feature state:

- Root and both same-repository children declare the same full SHA;
- all three `.status.sync.revision` values equal that SHA;
- Root is manual and `Synced`;
- `demo-api` has exactly four Root-rendered image parameters;
- Chart `demo-api-0.5.1`, ServiceMonitor, Prometheus address, no-data guard,
  Canary analysis, runtime checks, and monitoring checks pass.

Before merge, finally run:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
  ./scripts/restore-local-feature-baseline.sh
```

Root and the two children must remain on the same feature SHA, `demo-api`
parameters must be empty, Root automation must be restored, and no Application
operation may remain `Running`. After merge, run
`./scripts/restore-local-gitops-head.sh` and require all three declarations to
return to `HEAD`.

## Boundary

This increment changes no `demo-api` Chart or image, telemetry, ServiceMonitor,
Prometheus query, Canary strategy, external Chart version, AWS declaration,
release orchestrator, or production automation.
