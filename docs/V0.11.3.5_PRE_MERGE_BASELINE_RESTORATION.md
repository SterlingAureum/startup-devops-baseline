# v0.11.3.5 Pre-Merge Baseline Restoration

> Successor note: v0.11.3.6 aligns the historical namespace and local
> admission-policy validators with the Helm App-of-Apps layout. Apply both
> uncommitted increments before committing and running the live recovery.

## Incident

The v0.11.3.4 Root Application changed `clusters/local/platform` from a raw
directory source to a Helm source. Before that change reached `main`, the HEAD
restoration workflow rendered the new Helm-shaped Root while `HEAD` still
resolved to the old directory-only commit. Argo CD correctly failed with:

```text
ComparisonError: clusters/local/platform/Chart.yaml: no such file or directory
```

The five child Applications then appeared with `requiresPruning: true` because
the Root could not generate a desired manifest set. Those prune indicators were
secondary evidence, not permission to prune. No cluster rebuild was required.

## Invariant

A Root source mode and its selected Git revision must be schema-compatible.
Before `kubectl apply`, Root deployment now:

1. resolves the requested remote revision to a full commit SHA;
2. fetches the selected remote revision;
3. verifies that the commit contains
   `clusters/local/platform/Chart.yaml`;
4. exits without contacting Kubernetes when the path is absent.

Clearing Argo CD cache cannot repair a revision that genuinely lacks the
required path.

## Restoration Modes

### Before Merge

Use the pushed feature revision. The script resolves it once, requires the
local checkout to match the remote commit, requires a clean tracked worktree,
and restores Root plus same-repository children to that immutable SHA with
local-image overrides disabled:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
  ./scripts/restore-local-feature-baseline.sh
```

This is a clean pre-merge baseline, not the stable main baseline. Root
automation is restored only after Root and children are comparison-ready and
synchronized.

### After Merge

Use HEAD restoration only after the platform Helm Chart has reached remote
HEAD:

```bash
./scripts/restore-local-gitops-head.sh
```

The wrapper remains intentionally fixed to `HEAD`. The shared Root preflight
rejects the operation before Kubernetes mutation if remote HEAD lacks the
Chart.

## Comparison Safety

The shared restoration workflow performs a bounded hard refresh and checks for
`ComparisonError` before each sync. A comparison error prevents sync from
starting. No restoration script issues a prune command or directly mutates a
child revision with `argocd app set` or `argocd app unset`.

If a comparison error is observed, preserve diagnostics and correct the Git
source/revision relationship. Do not prune the child Applications and do not
rebuild the cluster merely to clear the status.

## Recovery From the Observed State

After this increment is committed and pushed to the feature branch:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
  ./scripts/restore-local-feature-baseline.sh
```

Then verify source identity:

```bash
kubectl -n argocd get applications \
  startup-devops-root namespace-guardrails demo-api \
  -o custom-columns='NAME:.metadata.name,TARGET:.spec.source.targetRevision,RESOLVED:.status.sync.revision,SYNC:.status.sync.status,HEALTH:.status.health.status'
```

All three target revisions must equal the same full feature commit SHA. All
three sync revisions must resolve to that SHA, Root must be `Synced`, local
image parameters must be empty, and the earlier `ComparisonError` must be gone.

## Acceptance

Run:

```bash
./scripts/validate-v0.11.3.5-pre-merge-baseline-restoration.sh
./scripts/validate-active-gitops-revisions.sh
```

The complete Docker/Helm quality gate, real recovery against kind/Argo CD, a
clean feature acceptance replay, and post-merge HEAD restoration remain
required before v0.11.3.5 is closed.
