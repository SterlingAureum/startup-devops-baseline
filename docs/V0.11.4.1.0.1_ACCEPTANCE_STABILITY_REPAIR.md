# v0.11.4.1.0.1 Acceptance Stability Repair

## Goal

Make local acceptance deterministic after GitOps reconciliation without
changing the deployed observability architecture.

## Incident summary

`scripts/validate.sh` previously performed one silent Pod list before its
Ready wait. A transient Kubernetes API error or an initially empty selector
therefore produced an immediate `pods not found` failure. A repeated complete
validation could pass after the query recovered.

`scripts/check-observability-views.sh` also combined an exact ConfigMap name
with a label selector. Kubernetes rejects that command shape with `name cannot
be provided when a selector is specified`, so the script stopped before its
Prometheus and Grafana API checks.

## Repair

- Labeled Pod discovery retries for up to 30 seconds by default.
- Empty successful list results and transient list errors are both retried.
- A persistent Kubernetes API error is reported separately from an empty
  selector result.
- The normal Kubernetes Ready wait starts only after at least one Pod is
  discovered.
- The Dashboard ConfigMap is fetched by exact name and its
  `grafana_dashboard=1` label is asserted independently.

The discovery window may be adjusted for a slow local control plane:

```bash
POD_DISCOVERY_TIMEOUT_SECONDS=60 ./scripts/validate.sh
```

## Baseline restoration semantics

Before merge, this command restores a neutral feature baseline:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
  ./scripts/restore-local-feature-baseline.sh
```

The wrapper resolves the remote feature branch to one immutable commit. The
Root and same-repository child Applications use that commit, local demo-api
image overrides are removed, Git-declared image values apply, and Root prune
and self-heal automation is enabled again. It does not switch the cluster to
`main` and it does not delete the cluster.

After the increment reaches remote HEAD, restore the stable declaration with:

```bash
./scripts/restore-local-gitops-head.sh
```

## Acceptance

Run the focused offline validator:

```bash
./scripts/validate-v0.11.4.1.0.1-acceptance-stability-repair.sh
```

Then run the complete local checks after Argo CD Applications are Synced and
Healthy:

```bash
./scripts/validate.sh
./scripts/check-monitoring.sh
./scripts/check-observability-views.sh
PROFILE=local ./scripts/check-controller-metrics.sh
```

The repair is accepted when every command succeeds on its first complete run.
If `validate.sh` exhausts the discovery window, use its differentiated error
to investigate either a persistent Kubernetes API failure or a genuinely
missing labeled workload instead of repeating the whole script blindly.

## Boundary

This repair changes validation behavior and documentation only. It changes no
Kubernetes resource, Helm Chart, component version, metric, recording rule,
Dashboard, alert, AWS desired state, or production automation.
