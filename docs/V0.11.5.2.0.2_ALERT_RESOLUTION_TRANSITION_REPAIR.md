# v0.11.5.2.0.2 Alert Resolution Transition Repair

## Outcome

The first guarded v0.11.5.2.0 drill proved warning firing, route selection,
Alertmanager-to-sink connectivity, and the firing webhook payload. Phase 1
then timed out waiting for a resolved webhook because the script deleted the
entire temporary PrometheusRule before Prometheus evaluated the same alert as
inactive.

Deleting a rule is cleanup, not a reliable alert-state transition. This repair
keeps each temporary rule and alert identity loaded while changing its
expression from firing to an empty result. It waits for Prometheus to clear the
alert and for Alertmanager to deliver the resolved webhook before deleting the
rule.

## Correct lifecycle

Each notifying phase now follows this order:

```text
apply vector(1)
observe Prometheus firing
observe Alertmanager route state
observe firing webhook
apply vector(0) == 1 with the same alert name and labels
observe Prometheus ALERTS series disappear
observe resolved webhook
observe no current drill alert in Alertmanager
delete the temporary PrometheusRule
```

`vector(0)` is intentionally not used as the inactive expression. Prometheus
alert rules are active when their expression returns a series; a returned
numeric zero is still a returned series. `vector(0) == 1` returns an empty
vector and therefore creates the explicit inactive transition.

The warning and critical single-alert phases use the full sequence. The
positive inhibition phase transitions both synthetic rules to inactive,
requires the notified critical alert to resolve, and then performs cleanup.
The suppressed warning is not required to emit a resolved notification because
it did not emit a firing notification. The negative isolation phase requires
resolved delivery from both severity paths before cleanup.

## Stale-run protection

The EXIT trap from the failed run removes labeled Kubernetes resources, but an
already firing Alertmanager alert may remain active until its refresh expires.
The repaired preflight rejects every active alert carrying `drill="true"`,
regardless of its previous `drill_id`. The final state performs the same global
check. This prevents evidence from an earlier failed run from being ignored by
a new unique drill ID.

## Unchanged runtime

This repair changes the live drill script, contracts, and documentation only.
It changes no monitoring Application, Alertmanager configuration, route,
receiver, NetworkPolicy, PrometheusRule in Git, webhook sink implementation,
formal alert, Chart, application image, AWS resource, or release workflow.

No monitoring redeployment or image rebuild is required.

The repaired live rerun completed all four phases. Its immediate final check
