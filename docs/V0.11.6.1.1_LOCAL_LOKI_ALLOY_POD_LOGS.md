# v0.11.6.1.1 Local Loki and Alloy Pod Logs

## Outcome

This increment makes the accepted v0.11.6.1.0 demo-api JSON logs queryable in
the local kind profile. It deploys one environment-local Loki backend and one
Alloy collector per Kubernetes node. It does not add Kubernetes Events,
Grafana log navigation, tracing, or an AWS logging runtime.

## Runtime Topology

```text
Pod stdout/stderr
  -> Kubernetes API pods/log
  -> node-local Alloy DaemonSet
  -> observability-logs-gateway ClusterIP
  -> Loki Monolithic StatefulSet
  -> 2 GiB disposable emptyDir
```

The Root Application creates two external-chart child Applications:

| Application | Sync wave | Chart | Version | Runtime |
| --- | ---: | --- | --- | --- |
| `logging-loki` | 7 | community `loki` | `18.11.3` | Loki `3.7.6` |
| `logging-alloy` | 8 | Grafana `alloy` | `1.11.0` | Alloy `1.18.0` |

The versions are explicit GitOps inputs. Argo CD does not follow an unbounded
chart range.

## Local Loki Profile

Loki uses Monolithic mode, one replica, TSDB v13, and filesystem object
storage. Persistence is deliberately disabled for the local kind profile. A
2 GiB `emptyDir` size limit and explicit ephemeral-storage resources bound the
node impact.

Retention is 24 hours. Loki's compactor retention implementation does not
support a shorter retention period, so the earlier six-hour design target is
not represented as a false runtime claim. Recreating the Loki Pod or kind
cluster may remove logs immediately because the volume is disposable.

The gateway is a private ClusterIP. There is no Ingress, LoadBalancer,
NodePort, MinIO, canary, chunks cache, results cache, or distributed Loki
component. Authentication is disabled only inside this isolated local
profile; the NetworkPolicy is the access boundary.

## Alloy Collection

Alloy is a DaemonSet. Each instance selects Pods scheduled to its own node and
reads `startup-apps` logs with `loki.source.kubernetes`. The application scope
was added by v0.11.6.1.1.5 after cluster-wide Kubernetes API readers exhausted
fsnotify watchers on the dense one-node kind profile. This avoids host
`/var/log` and container-runtime mounts and does not require privilege, host
networking, host PID access, or host sysctl mutation.

RBAC is restricted to read-only `get`, `list`, and `watch` access for
Namespaces, Pods, and `pods/log`. Egress is restricted to cluster DNS, the
local kind Kubernetes Service IP `10.96.0.1/32` on TCP 443, and the Loki
gateway. The Alloy service and Ingress are disabled. The fixed API address is
part of the repository's local kind profile and must not be copied unchanged
to an arbitrary Kubernetes service CIDR.

The JSON stage extracts `severity` when present but preserves malformed and
non-JSON lines from the selected application namespace. Cluster-wide platform
log expansion requires a separate capacity-qualified design.

## Cardinality Contract

Exactly these six values may become indexed Loki labels:

- `environment`
- `cluster`
- `namespace`
- `application`
- `container`
- `severity`

Pod name and UID are structured metadata. Release ID, source commit, image
digest, request ID, trace ID, and span ID remain fields in the JSON record.
They must not become indexed labels. Loki automatic `service_name` discovery
is disabled so it cannot silently create a seventh indexed label.

## Deployment

No demo-api rebuild is required. Commit and push this increment to
`feature/v0.11-observability-sre-baseline`, then reconcile the local Root
Application using the already accepted local image parameters:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
IMAGE_TAG=<accepted-v0.11.6.1.0-local-tag> \
APPLICATION_VERSION=<accepted-v0.11.6.1.0-application-version> \
  ./scripts/deploy-local-feature-gitops.sh
```

Do not run `restore-local-gitops-head.sh` before the feature branch is merged.
That script restores the stable `HEAD` GitOps declaration and is not part of
pre-merge feature acceptance.

## Acceptance

Run the offline gates before deployment:

```bash
./scripts/validate-v0.11.6.1.1-local-loki-alloy-pod-logs.sh
./scripts/validate-ci-quality-gates.sh
```

After Argo CD reconciliation, run:

```bash
./scripts/validate.sh
./scripts/check-local-logging-runtime.sh
```

The focused live checker waits for both Applications and all three workload
controllers, generates one `/version` request inside the selected demo-api
Pod, and queries Loki through a temporary local port-forward. It reads Pod
identity from returned structured metadata, checks actual indexed labels with
the Loki Series API, rejects new fsnotify watcher exhaustion, replaces that
demo-api Pod, and proves the pre-replacement record is still queryable.

The Pod replacement is intentional and bounded. The Argo Rollout or Deployment
must create a Ready replacement. No Loki resource is deleted by the checker.

Acceptance is complete only when:

1. both logging Applications are `Synced` and `Healthy`;
2. Loki, its gateway, and every Alloy DaemonSet Pod are Ready;
3. every logging Service is private and both NetworkPolicies exist;
4. the expected demo-api `/version` JSON record is returned by Loki;
5. the Loki Series API returns exactly the six allowed indexed labels;
6. the old Pod record remains queryable after demo-api Pod replacement;
7. the complete repository quality gate passes.

## Troubleshooting

Inspect Argo CD and workload state first:

```bash
kubectl -n argocd get application logging-loki logging-alloy
kubectl -n observability get statefulset,deployment,daemonset,pod,service,networkpolicy
kubectl -n argocd describe application logging-loki
kubectl -n argocd describe application logging-alloy
kubectl -n observability logs daemonset/observability-logs-collector --all-containers --tail=200
kubectl -n observability logs statefulset/observability-logs --all-containers --tail=200
```

If no demo-api record appears, confirm the selected Pod still uses the
accepted v0.11.6.1.0 structured-log image and that its release annotation is
present. The watcher-exhaustion error requires the v0.11.6.1.1.5 application
scope repair; do not raise mutable host sysctl limits as a repository
substitute. If Series API labels exceed the contract, inspect the Alloy
pipeline and Loki automatic label configuration.
