# v0.11.6.1.2.2 Kubernetes Event MicroTime Acceptance Repair

## Incident

The repaired `logging-alloy-events` Application was `Synced/Healthy`, its
singleton Deployment rolled out, the position PVC and security/network checks
passed, and Grafana reached the provisioned Loki data source. The live checker
then attempted to create its first deterministic `events.k8s.io/v1` Event and
the API server rejected `eventTime`:

```text
parsing time "2026-08-28T14:41:49.874409241Z" as
"2006-01-02T15:04:05.000000Z07:00": cannot parse "241Z" as "Z07:00"
```

The previous command used GNU `date` with `%N`, which emits nine fractional
digits. Kubernetes represents `Event.eventTime` as `metav1.MicroTime`; the API
decoder expected six fractional digits for this field.

The failure occurred before the Event create request succeeded. The script
registers a temporary Event for cleanup only after successful creation, so this
incident left no acceptance Event to delete.

## Repair

The live checker now uses its existing Python dependency to generate an aware
UTC timestamp:

```python
datetime.now(timezone.utc).isoformat(timespec="microseconds").replace("+00:00", "Z")
```

The result has the required shape:

```text
2026-08-28T14:41:49.874409Z
```

The repair explicitly fixes all of these properties:

- UTC rather than local time;
- exactly six fractional digits;
- a trailing `Z` offset marker;
- no dependence on GNU `date %N`; and
- cleanup registration only after API creation succeeds.

The Event API version, `eventTime` field, reason, action, reporting identity,
regarding object, note marker, and cleanup behavior otherwise remain unchanged.

## Boundary

This is a live-acceptance-only repair. It changes no Kubernetes manifest,
local platform Chart, image, Events collector, PVC, StorageClass, Alloy or Loki
configuration, Grafana data source, RBAC, NetworkPolicy, indexed label, AWS
state, GitHub workflow, credential, public endpoint, production automation, or
tracing runtime.

The existing logging runtime is already healthy. Do not reconcile the Root,
restart Alloy or Loki, rebuild demo-api, or delete the position PVC for this
repair.
