# v0.11.6.1.2 Kubernetes Events and Grafana Loki Integration

## Purpose

This increment completes the queryable local logging surface that follows the
accepted demo-api JSON, Alloy Pod-log, and Loki runtime. It adds one independent
Kubernetes Event reader and provisions the existing Grafana instance with a
private Loki data source. It does not introduce tracing or change the demo-api
image.

## Runtime Topology

The existing `logging-alloy` DaemonSet remains responsible only for Pod logs.
The new `logging-alloy-events` Argo CD Application installs Alloy Chart `1.11.0`
as a one-replica Deployment. Repair `v0.11.6.1.2.1` places this Application
and its `WaitForFirstConsumer` position claim together at sync wave `8`:

```text
Kubernetes Events API -> Alloy singleton -> Loki gateway -> local Loki
                                                    |
Grafana Explore -------- provisioned Loki data source
```

Separating the collectors prevents every node-local Pod-log collector from
watching and duplicating the same cluster-level Event stream.

The original cross-wave declaration could not converge on the local
`WaitForFirstConsumer` StorageClass. Its diagnosis and recovery procedure are
recorded in
`V0.11.6.1.2.1_EVENTS_PVC_SYNC_WAVE_TROUBLESHOOTING.md`.

## Event Position Durability

`loki.source.kubernetes_events` stores read positions below the Alloy storage
path. The event Deployment mounts the local
`observability-events-collector-storage` ReadWriteOnce claim at
`/var/lib/alloy`. The 256Mi claim survives collector Pod replacement but remains
part of the disposable local kind profile. Rebuilding the kind cluster does not
promise Event retention.

This bounded persistence prevents a routine Deployment restart from replaying
the entire Kubernetes Event TTL window. The live acceptance creates one unique
Event, restarts the collector, proves that the original Event was not duplicated,
then creates a second Event to prove that collection resumed.

## Labels and Event Content

The Event source emits JSON lines. Loki index labels remain exactly:

```text
environment
cluster
namespace
application
container
severity
```

Event streams use fixed values `application=kubernetes-events`,
`container=events`, and `severity=INFO`. Event reason, message, object name, UID,
and other changing fields remain in the JSON line and are not promoted to index
labels. The source-provided `job` and `instance` labels are removed by the final
label allowlist.

## Permissions and Network Boundary

The event collector can only `get`, `list`, and `watch` core Kubernetes Event
resources. It cannot read Pods, Secrets, ConfigMaps, or workload logs. It uses
the in-cluster ServiceAccount, has no hostPath, privilege, host network, public
Service, Ingress, or LoadBalancer, and can only reach DNS, the local Kubernetes
API Service IP, and the private Loki gateway.

## Grafana Provisioning

Grafana remains owned by `kube-prometheus-stack`. The local monitoring values
add one non-default, non-editable data source:

```text
name: Loki
uid: loki
access: proxy
url: http://observability-logs-gateway.observability.svc.cluster.local
```

Grafana's cluster-only NetworkPolicy permits port `8080` to the observability
namespace for this server-side query path. No browser or public network can
reach Loki directly.

## Acceptance

Run the offline validator and complete quality gate:

```bash
./scripts/validate-v0.11.6.1.2-kubernetes-events-grafana-loki.sh
./scripts/validate-ci-quality-gates.sh
```

After committing, pushing, and reconciling the feature revision, run:

```bash
./scripts/validate.sh
./scripts/check-local-logging-runtime.sh
./scripts/check-local-events-grafana.sh
```

The final check intentionally restarts only the singleton Event collector. It
does not rebuild or redeploy demo-api and does not restart Loki.

Repair `v0.11.6.1.2.2` makes the temporary `events.k8s.io/v1` acceptance
record's `eventTime` compatible with Kubernetes `MicroTime` by emitting UTC
with exactly six fractional digits. See
`V0.11.6.1.2.2_KUBERNETES_EVENT_MICROTIME_ACCEPTANCE_REPAIR.md`.

Closure `v0.11.6.1.3` retains this runtime and composes both logging checks
under `check-local-logging-end-to-end.sh`. Successful Event acceptance now
strictly deletes its temporary Kubernetes objects and proves the corresponding
Loki records remain exactly once after source cleanup.

## Deferred Scope

This increment adds no logging Dashboard, alert rule, OpenTelemetry SDK,
Collector, Tempo, trace-derived field, AWS logging runtime, object storage,
external credential, or public endpoint. Structured-logging replay and cleanup
closure is completed by v0.11.6.1.3; tracing begins in v0.11.6.2.
