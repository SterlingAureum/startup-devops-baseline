# v0.11.6.1.3 Local Logging End-to-End Acceptance and Closure

## Purpose

This increment closes the local structured-logging runtime by composing the
already accepted platform, Pod-log, Kubernetes Event, Loki, and Grafana checks
into one repeatable operator entrypoint. It adds no deployed component and
changes no application image or logging configuration.

## Accepted Path

The closure command executes these stages in order:

1. the repository's normal local platform validation;
2. the existing demo-api Pod-log and Loki runtime acceptance;
3. the existing singleton Kubernetes Events and Grafana Loki acceptance; and
4. final Application, PVC, and temporary-resource assertions.

The Pod-log stage emits one `/version` record, checks release identity and the
exact six-label index, replaces its source Pod, and proves the earlier record
remains queryable. The Events stage creates unique API Events using Kubernetes
`MicroTime`, verifies Grafana's server-side Loki path, restarts only the
singleton Event collector, rejects replay, and proves collection resumes.

## Cleanup Semantics

Normal successful execution strictly deletes both temporary Kubernetes Events
and verifies that neither object remains. Failure to delete either object is a
test failure. The exit trap remains best-effort so cleanup cannot replace the
original diagnostic when an earlier stage fails.

Deleting the Kubernetes source objects must not erase accepted Loki history.
After strict source cleanup, both unique Event markers must still be queryable
exactly once. The final stage also rejects any `v011612-` acceptance Event
residue in `startup-apps`.

The script never deletes Loki data, the Event-position PVC, or the local
StorageClass.

## Failure Diagnostics

Every composed stage has a stable name and its own temporary log. A failed
stage prints the status of the Root and observability Applications, the
observability Pods and PVCs, and a bounded tail of the Event collector log.
Diagnostics do not print the Grafana Secret or any credential value.

The `WaitForFirstConsumer` deadlock discovered during v0.11.6.1.2 remains a
version-specific incident record:

```text
docs/V0.11.6.1.2.1_EVENTS_PVC_SYNC_WAVE_TROUBLESHOOTING.md
```

Closure verifies the repaired live invariant without deleting the claim or
changing the StorageClass to reproduce the historical fault.

## Live Acceptance

No Root reconciliation, image rebuild, external component restart, PVC
recreation, or StorageClass change is required. Execute the closure command
twice consecutively:

```bash
./scripts/check-local-logging-end-to-end.sh
./scripts/check-local-logging-end-to-end.sh
```

Both runs must end with:

```text
v0.11.6.1 local structured logs, Pod collection, Kubernetes Events, Loki persistence, Grafana query, strict cleanup, and repeatable end-to-end acceptance passed.
```

## Boundary and Next Increment

This checkpoint adds no Dashboard, alert rule, public endpoint, AWS logging,
object storage, OpenTelemetry SDK, OTLP Collector, Tempo, trace identifier, or
automated production action. A successful two-run acceptance closes
v0.11.6.1. The next increment is v0.11.6.2 minimal extensible tracing.
