# v0.11.6.2.2 Real demo-api Trace and Log Correlation

## Outcome

This increment joins the independently accepted application and backend halves
of the local tracing path. The local App-of-Apps enables the existing demo-api
OTLP/HTTP exporter, a real `GET /version` request creates one bounded SERVER
span, the existing Alloy and Loki path retains the correlated JSON log, and
Tempo returns the same trace. Grafana receives one private Tempo data source
and the existing Loki data source receives one `TraceID` derived field.

The demo-api base Chart remains disabled by default. This is a local GitOps
override, not an AWS or production default, and it reuses the already accepted
OpenTelemetry 1.44.0 application image without changing application code.

## Runtime path

```text
real HTTP request
  -> demo-api W3C SERVER span and JSON request log
  -> private OTel Collector OTLP/HTTP endpoint
  -> private Tempo 3.0.3

demo-api stdout
  -> Alloy
  -> Loki
  -> Grafana Loki derived field
  -> Tempo trace by the same trace_id
```

`trace_id` and `span_id` remain JSON fields. They are deliberately excluded
from Loki's six-label index contract. The derived field extracts the
32-character trace identifier from the log line at query time, so correlation
does not create an unbounded index.

## Configuration boundary

- `clusters/local/platform` advances to Chart `0.8.0` and application version
  `v0.11.6.2.2`.
- Only the local demo-api Application sets `telemetry.tracing.enabled=true`.
- The endpoint remains the private Collector ClusterIP DNS name and the only
  accepted protocol remains `http/protobuf`.
- Grafana provisions Tempo with UID `tempo`, proxy access, private port `3200`,
  `isDefault=false`, and `editable=false`.
- Grafana's NetworkPolicy adds only egress TCP/3200 inside `observability`.
- No database enablement or PostgreSQL live-trace claim is required.

## Acceptance

Run the offline contract first:

```bash
./scripts/validate-v0.11.6.2.2-real-demo-api-trace-log-correlation.sh
```

Reconcile the committed feature revision while reusing the unique tracing-
capable local image that was accepted in v0.11.6.2.0. Then execute the live
checker twice consecutively:

```bash
./scripts/check-local-demo-api-trace-correlation.sh
./scripts/check-local-demo-api-trace-correlation.sh
```

Each run supplies a new W3C `traceparent`, invokes the real `/version` route,
waits for the correlated JSON record in Loki, rejects trace identifiers in the
Loki label set, queries that identifier from Tempo, and checks both provisioned
Grafana data sources and their health endpoints.

## Deferred

Service graphs, span metrics, tail sampling, exemplars, tracing dashboards,
cross-cluster tracing, object storage, high availability, AWS X-Ray, and public
OTLP ingress remain outside this increment. v0.11.6.2.3 will close the local
minimal tracing phase with one ordered repeatable acceptance entrypoint.
