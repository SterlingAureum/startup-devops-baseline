# v0.11.6.2.3.1 Demo API Runtime Artifact Preflight Repair

## Incident

The v0.11.6.2.3 closure observed a Synced and Healthy demo-api Rollout, sent a
successful `GET /version`, and queried a healthy Loki API. Loki scanned the
demo-api stream but never found the generated W3C trace ID. Pod diagnostics
showed historical Uvicorn access lines instead of the accepted structured JSON
request log.

The Rollout was still running the neutral replay image `sha-3e50802`. That
image is sufficient to restore the GitOps baseline, but it predates the active
structured-logging and tracing implementation. Argo CD and Argo Rollouts
correctly reported the declared workload as healthy; neither controller proves
that a historical artifact contains capabilities introduced by later source.

This is a runtime artifact provenance drift and an acceptance-path omission,
not a Loki, Gateway, DNS, Tempo, or security vulnerability.

## Repair

The tracing closure now fails before querying Loki unless:

- the Rollout does not use the known neutral replay tag;
- every selected Pod is Running and Ready;
- all selected Pods report one identical runtime `imageID`;
- every ready Pod contains the accepted logging and tracing modules;
- the server entrypoint configures both systems;
- tracing is enabled and points to the private local Collector Service.

The check inspects all ready replicas because the stable Service may route a
request to any one of them. It does not extend the Loki timeout or accept plain
access logs as correlation evidence.

## Required recovery

Build the exact committed feature source under a unique local tag:

```bash
IMAGE_REPOSITORY="startup-devops-baseline/demo-api"
IMAGE_TAG="v0.11.6.2.3.1-$(git rev-parse --short=12 HEAD)-local"

IMAGE_NAME="${IMAGE_REPOSITORY}" \
IMAGE_TAG="${IMAGE_TAG}" \
  ./scripts/build-load-demo-api-image.sh
```

Deploy the same tag through the feature revision:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
IMAGE_REPOSITORY="${IMAGE_REPOSITORY}" \
IMAGE_TAG="${IMAGE_TAG}" \
APPLICATION_VERSION="${IMAGE_TAG}" \
  ./scripts/deploy-local-feature-gitops.sh
```

Complete an intentional Canary pause if one exists, then run:

```bash
./scripts/check-local-tracing-end-to-end.sh
```

The preflight must print the non-neutral image reference before the two real
correlation runs begin.

## Production lesson

Production releases should use an immutable digest and bind source commit,
build evidence, release metadata, Pod `imageID`, and application-reported
version into one qualification record. Controller health is necessary but is
not binary provenance evidence.
