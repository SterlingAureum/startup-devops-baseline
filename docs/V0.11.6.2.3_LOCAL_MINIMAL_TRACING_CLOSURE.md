# v0.11.6.2.3 Local minimal tracing closure

## Outcome

This increment closes the local minimal tracing phase without adding runtime
components. One ordered read-only entrypoint proves that the declared GitOps
Applications and demo-api Rollout are healthy, Collector, Tempo, Loki, Gateway,
and Grafana remain private, and two independent real requests produce matching
Loki logs and Tempo traces.

```text
real GET /version
  -> demo-api SERVER span -> private OTel Collector -> private Tempo
  -> demo-api JSON log    -> Alloy -> Loki -> Grafana TraceID derived field
```

## Accepted history

- v0.11.6.2.0 introduced the disabled-by-default application SDK contract.
- v0.11.6.2.1 and .2.1.1 accepted private Collector-to-Tempo ingest and
  hexadecimal OTLP/JSON diagnostics.
- v0.11.6.2.2 accepted real application export and log correlation.
- v0.11.6.2.2.4 repaired stale Loki Gateway upstream recovery and normalized
  Tempo protobuf-JSON identifiers for comparison.

The closure entrypoint does not rerun the destructive Collector replacement
drill from v0.11.6.2.1.1. That drill remains independently available and
accepted; closure protects its offline contract without deleting a live Pod.

## Ordered live acceptance

After the committed feature revision is reconciled and the demo-api Rollout is
Healthy, run:

```bash
./scripts/check-local-tracing-end-to-end.sh
```

The entrypoint checks:

1. the active Kubernetes context;
2. six required Argo CD Applications are Synced and Healthy;
3. the demo-api Rollout has all desired replicas Ready, Available, and Updated;
4. five tracing/correlation Services are private ClusterIP Services;
5. Collector, Tempo, Loki, and Grafana NetworkPolicies exist;
6. Collector and Tempo are not Ingress backends;
7. two consecutive real trace-log correlation runs each use a unique W3C trace.

The script is read-only. It does not patch Applications, promote Rollouts,
restart workloads, delete Pods, or replace Helm parameters. Failures point to
the relevant component diagnostics. For the classic healthy-resource/HTTP-502
case, use
`V0.11.6.2.2.4_LOKI_GATEWAY_STALE_UPSTREAM_TROUBLESHOOTING.md`.

## Default and environment boundary

The base demo-api Chart keeps tracing disabled. Only the local App-of-Apps
enables the accepted exporter endpoint. AWS dev, test, and prod declarations
remain unchanged. Collector and Tempo have no NodePort, LoadBalancer, Ingress,
or public OTLP endpoint.

Trace and span identifiers remain structured JSON fields and are rejected as
Loki labels. PostgreSQL is not required by closure. Service graph, span metrics,
tail sampling, exemplars, object storage, high availability, dynamic Gateway
DNS, cross-cluster tracing, X-Ray, and a dedicated tracing dashboard remain
deferred production extensions.

## Cleanup and repeatability

Each correlation child allocates independent local ports, generates a new trace
identifier, uses a bounded query window, and cleans its port-forward processes
and temporary directory on success or failure. Running closure again does not
reuse the prior proof and does not mutate declarative state.
