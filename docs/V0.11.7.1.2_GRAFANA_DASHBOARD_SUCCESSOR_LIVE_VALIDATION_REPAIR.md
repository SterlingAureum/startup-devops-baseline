# v0.11.7.1.2 Grafana Dashboard Successor Live-validation Repair

## Symptom

`check-local-slo-burn-rate-alerts.sh` reaches Grafana and then reports that the
immutable SLO Dashboard was not provisioned, even though GitOps resources and
the Grafana API are reachable.

## Cause

The retained v0.11.7.0 live checker required exactly four panels. v0.11.7.1
correctly added two burn-rate panels, but only the offline validator was made
successor-aware. A correctly provisioned six-panel Dashboard was therefore
misclassified as missing.

## Repair

The live checker now expects four panels before the burn-rate contract and six
when that contract exists. It captures the Grafana API response and reports
HTTP, UID, editability, and expected/actual panel-count failures separately.

Fixture mode covers both accepted generations and rejects an incorrect count.
The desired Dashboard and all runtime resources remain unchanged.

## Acceptance

```bash
./scripts/validate-v0.11.7.1.2-grafana-dashboard-successor-live-validation-repair.sh
./scripts/check-local-slo-burn-rate-alerts.sh
```

No Root advance or reconciliation is required. The live rerun resumes the
previously interrupted acceptance path.
