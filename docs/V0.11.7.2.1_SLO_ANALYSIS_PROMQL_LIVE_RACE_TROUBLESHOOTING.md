# v0.11.7.2.1 SLO Analysis PromQL and Live Race Troubleshooting

## Symptoms

The original v0.11.7.2 live attempt exposed three distinct signals:

1. `deploy-local-feature-gitops.sh` rejected a missing `TARGET_REVISION`.
2. Using the application version as `TARGET_REVISION` failed remote Git
   revision resolution.
3. The AnalysisRun reported empty candidate vectors and Prometheus rejected
   `stable-availability-error-budget-remaining` with `unexpected ","`.

## Root causes

`TARGET_REVISION` and `APPLICATION_VERSION` are separate identities. The first
must name a pushed Git branch or revision; the second becomes the workload's
release identity. The package Apply guide omitted the required Git input.

The stable availability expression also had one excess closing parenthesis.
Helm accepts PromQL as an opaque string, so lint/render could not detect the
provider-side parse failure.

Finally, a local cluster has no organic production traffic. The AnalysisRun
started its measurements 60 seconds after creation, while the operator still
had to notice the canary and start the traffic checker. Fail-closed empty-vector
behavior was correct, but the manual sequence was racy.

## Repaired procedure

Choose one literal version and use it in both terminals. Start terminal 2 first:

```bash
EXPECTED_APPLICATION_VERSION=v0.11.7.2.1-<unique-UTC-suffix> \
  ./scripts/check-local-slo-aware-rollout-analysis.sh
```

The checker waits without accepting the previous Rollout. In terminal 1:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
IMAGE_TAG=<accepted-demo-api-image-tag> \
APPLICATION_VERSION=v0.11.7.2.1-<same-unique-UTC-suffix> \
  ./scripts/deploy-local-feature-gitops.sh
```

After the first six-metric AnalysisRun succeeds and the Rollout reaches the
50% human pause:

```bash
kubectl argo rollouts get rollout demo-api -n startup-apps
kubectl argo rollouts promote demo-api -n startup-apps
MINIMUM_MATCHING_ANALYSIS_RUNS=2 \
EXPECTED_APPLICATION_VERSION=v0.11.7.2.1-<same-unique-UTC-suffix> \
  ./scripts/check-local-slo-aware-rollout-analysis.sh
kubectl argo rollouts status demo-api -n startup-apps
```

`status` and `promote` receive the Rollout name `demo-api`, not
`rollout/demo-api`.

## Diagnostic distinction

- `remote Git revision not found`: wrong or unpushed `TARGET_REVISION`.
- candidate metric value `[]`: no matching release-ID series was scraped in
  the measurement window.
- Prometheus `bad_data` or parse error: query syntax, independent of traffic.
- AnalysisRun `Failed`: do not promote; inspect all six metric results first.

The repair does not weaken no-data handling. Missing release traffic remains a
failure after the coordinated checker has had the opportunity to generate it.
