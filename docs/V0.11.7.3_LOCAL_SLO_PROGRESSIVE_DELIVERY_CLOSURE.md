# v0.11.7.3 Local SLO and Progressive Delivery Closure

## Purpose

This increment closes the local v0.11.7 path without adding another SLO
algorithm. One entry point covers four explicit lifecycle phases while keeping
the 50% decision human-owned.

| Phase | Evidence | Mutation |
| --- | --- | --- |
| `first-analysis` | exact-release six-metric AnalysisRun 1 | bounded stable/canary traffic only |
| `human-review` | 50% pause and successful AnalysisRun 1 | none |
| `second-analysis` | exact-release six-metric AnalysisRun 2 | bounded stable/canary traffic only |
| `final` | Healthy Rollout, two analyses, SLO/Dashboard/rules/alerts | none |

The script never promotes, aborts, retries, patches, deletes, edits Git, or
removes AnalysisRun history.

## Policy choice

The local default remains `human-governed`: one indefinite pause at 50% after
the first automated gate. This is a safe demonstrator default, not a claim that
every small team needs manual approval. A fully automated profile is documented
but not enabled here; adopting it requires an explicit service-risk policy,
reliable traffic, rollback ownership, and on-call response.

## Fresh closure run

Choose and print one new version:

```bash
RELEASE_VERSION="v0.11.7.3-$(date -u +%Y%m%d%H%M%S)"
printf '%s\n' "${RELEASE_VERSION}"
```

Start terminal 2 before reconciliation:

```bash
CLOSURE_PHASE=first-analysis \
EXPECTED_APPLICATION_VERSION=<release-version> \
  ./scripts/check-local-slo-progressive-delivery-closure.sh
```

In terminal 1, reconcile the same literal version:

```bash
TARGET_REVISION=feature/v0.11-observability-sre-baseline \
IMAGE_TAG=v0.11.6.2.3.1-2375fd62244a-local \
APPLICATION_VERSION=<release-version> \
  ./scripts/deploy-local-feature-gitops.sh
```

After AnalysisRun 1 succeeds, validate but do not mutate the human checkpoint:

```bash
CLOSURE_PHASE=human-review \
EXPECTED_APPLICATION_VERSION=<release-version> \
  ./scripts/check-local-slo-progressive-delivery-closure.sh
```

Review the Rollout, AnalysisRun, SLO Dashboard, alerts, and rollback readiness.
Only then make the explicit decision:

```bash
kubectl argo rollouts promote demo-api -n startup-apps
```

Run the second gate immediately:

```bash
CLOSURE_PHASE=second-analysis \
EXPECTED_APPLICATION_VERSION=<release-version> \
  ./scripts/check-local-slo-progressive-delivery-closure.sh
```

After automatic advancement to 100%, run the complete final evidence check:

```bash
CLOSURE_PHASE=final \
EXPECTED_APPLICATION_VERSION=<release-version> \
  ./scripts/check-local-slo-progressive-delivery-closure.sh
```

## Negative evidence matrix

The retained validators reject insufficient candidate volume, availability or
latency burn excess, exhausted stable budgets, provider errors, no data,
release mismatch, stale Service selectors, unready Endpoints, and attempts to
reuse AnalysisRun 1 as AnalysisRun 2. Failures do not authorize promotion.

## Evidence retention and cleanup

The checkers remove only their own temporary directories and port-forward
processes. They do not delete AnalysisRuns, ReplicaSet history, Prometheus data,
Dashboard resources, alert state, PVCs, or cluster runtime. Preserved failed
AnalysisRuns are incident evidence and may be removed later only through an
explicit retention policy.

## Completion boundary

Passing all four phases closes local v0.11.7. AWS evidence remains v0.11.8;
production-scale traffic, resilience drills, disaster recovery, and complex
distributed backends remain production-readiness work rather than local SLO
closure requirements.
