## Independent capacity and credentials

The test Terraform defaults are not changed. The explicit, non-auto profile
`delivery/profiles/aws-test-observability-qualification.tfvars` proposes four
system nodes (min/desired/max 4/4/4), informed by the dev Pod-slot incident.
It is NOT automatically loaded by `apply-aws-test.sh`; do not assume applying
this package changes cloud capacity. Before enabling feature execution, the
entrypoint must pass this profile explicitly to the test Terraform root and
review a saved plan, account, region, cost and cleanup deadline. Four nodes
are a conservative starting point, not a production sizing guarantee.

Check actual node readiness, schedulable Pod slots and CPU/memory headroom.
An EC2/EKS desired count or a successful API call is not readiness. Preserve
the .8.1.5 distinction between current capacity and spec reconciliation.
Do not run dev-specific scaling helpers against test.

The future test cluster must independently create an `observability` Secret
named `observability-grafana-admin`, with `admin-user` and `admin-password`
keys, before monitoring sync. The same name in separate clusters is valid;
the credentials must not be copied from dev. Never store plaintext credentials
in Git, patch packages or evidence. A context/account/cluster guard and
create-only helper are prerequisites for the next live increment. The preview
only references the Secret: it does not create it.

## Offline acceptance now

Prerequisites: Bash, Git, Python 3 with PyYAML, and Kustomize or kubectl.
`kubectl kustomize` is a local renderer and does not contact a cluster.

```bash
./scripts/validate-v0.11.8.2.0-aws-test-qualification-prerequisites.sh
./scripts/check-aws-test-qualification-preview.sh
./scripts/check-aws-gitops-revision-boundary.sh
git diff --check
```

The validator runs positive/negative document fixtures. If neither renderer is
installed it explicitly reports SKIP; that is not a render pass. The standalone
preview checker fails without a renderer and must pass before local acceptance.
It compares complete rendered resource inventories, allowing only the intended
revision and Secret-reference changes. The existing boundary check still
requires dev=feature, stable test=main and prod=main.

Then run the complete `./scripts/validate-ci-quality-gates.sh` with the normal
project toolchain. Fixture success is not full quality-gate or live success.
