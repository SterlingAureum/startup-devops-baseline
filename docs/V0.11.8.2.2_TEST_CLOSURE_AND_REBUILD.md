## Case: Secret name blocked after teardown

Observed: EKS add-ons completed, but Terraform could not create
`startup-devops-baseline-test/demo-api/postgresql` because it was scheduled for
deletion. Local test tfvars used a seven-day recovery window. The partial
Terraform state included the new cluster but not the failed Secret resource.
The operator approved discarding old credentials, resolved the old Secret,
generated a fresh resume plan and later supplied the successful observation.

A pending Secret is distinct from a running old cluster. AWS deletion uses a
recovery window and asynchronous final deletion; a delete response does not
prove name availability. The current local tfvars alone does not prove which
options a previous deletion used. Inspect metadata rather than infer completion
from a timestamp. See [AWS DeleteSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DeleteSecret.html).

New preparation checks the exact test Secret metadata before Terraform init/plan,
after plan generation and before apply. `DeletedDate` stops the flow. Only an
explicit DescribeSecret ResourceNotFoundException is treated as absence;
permissions, expired sessions, malformed responses and network errors stop.
An active same-name Secret is allowed for normal managed resume, but a plan
trying to create it is rejected for separate state/ownership review.
The operator needs `secretsmanager:DescribeSecret`; no policy is auto-expanded.
This API returns metadata, not the credential value.
See [AWS DescribeSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DescribeSecret.html).

These are point-in-time checks, not a distributed lock or a complete resource
collision scanner. Concurrent changes can still fail apply; preserve partial
state. Existing clean-main scripts and the read-only observer are unchanged.

## Recovery decision and ordered continuation

1. Confirm the configured AWS account/region and the exact test Secret using
   read-only DescribeSecret. Never infer it from another shell's kube context.
2. If credentials must be retained, review cancellation of deletion and state
   adoption separately. Restoring alone does not put a Secret into Terraform
   state or establish that its old password matches the new database.
3. If the old credentials are explicitly approved for permanent disposal, an
   authorized operator may use DeleteSecret with ForceDeleteWithoutRecovery
   against the reviewed full ARN. All versions are irrecoverable. This package
   neither runs that command nor supplies a broad deletion loop.
4. Wait until DescribeSecret by the fixed NAME returns ResourceNotFoundException.
   A denied request is not absence. Do not re-delete a newly created Secret.
5. Preserve state. After partial apply, create a NEW bundle and resume plan:

```bash
export EXPECTED_CONTROL_PLANE_SHA="$(git rev-parse HEAD)"
: "${EXPECTED_AWS_ACCOUNT_ID:?Set the reviewed account in this shell}"
read -r -p 'Current globally routable management IPv4: ' TEST_MANAGEMENT_IP
export TEST_PLAN_DIR="/tmp/aws-test-plan-$(date -u +%Y%m%dT%H%M%SZ)"
./scripts/prepare-aws-test-feature.py plan \
  --mode resume --management-ip "$TEST_MANAGEMENT_IP" --bundle "$TEST_PLAN_DIR"
```

6. Stop unless plan succeeds and prints `Plan saved:`. Review resource changes;
   unexpected deletion/replacement must not be forced through. Then separately:

```bash
./scripts/prepare-aws-test-feature.py apply \
  --bundle "$TEST_PLAN_DIR" --confirm apply-reviewed-aws-test
```

7. Continue bootstrap/qualification in the main .8.2.1 runbook only as needed.
   Do not reapply an old partially executed plan, delete state or manually invent
   review.json. `create` is only for empty test state and an absent test cluster.
   Plan bundles contain sensitive data: keep outside Git and remove privately
   when no longer needed. Do not change the recovery window to zero globally.
