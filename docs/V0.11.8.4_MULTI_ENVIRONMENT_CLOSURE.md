## Local reviewed archive

`scripts/archive-observability-evidence.py` performs no network/subprocess/cloud
operation. It accepts the v0.11.8.0 evidence shape and validates explicit fields,
types, identity, timestamps and outcome/reference semantics. It is a dedicated
format validator, not a general JSON Schema engine or a runtime requalification.
Legacy local reports stay in their original form with reviewed documentation
references; do not wrap them in fabricated modern evidence merely to register.

| Kind | Meaning | Allowed use |
| --- | --- | --- |
| raw | Exact original bytes with original identity | Private historical archival; upstream live/promotion policy remains separate |
| redacted | Sharing copy; AWS account and context account must both be `***` | Historical review, never substitute for an original machine-validated identity |
| historical summary | Existing .8.2.2 record or status-table reference | Documentation only; not accepted as a runtime payload |

All generated index records have `promotion_eligible=false` and
`current_runtime_qualified=false`. These flags apply to the INDEX, not a rewrite
of the source's reported status. The tool retains failed/waiting evidence too.
It does not select a latest success or discard older failures. Image/mode are
extracted only when recorded under known check IDs; otherwise null/not-recorded.
It never invents missing release facts or associates a sharing copy with a raw
original that was not provided. Retain both separately if both are available.

### Register your existing evidence (optional, no live retest)

Use a dedicated persistent directory outside Git, not /tmp. Review the entire
file for sensitive material; the tool is NOT a redactor or secret scanner.
Raw evidence and diagnostic values can contain account or infrastructure data.
The archive should be private and backed up. New CLI-created files use umask 077;
existing parent permissions and backup access are your responsibility.

```bash
export OBS_ARCHIVE="$HOME/observability-evidence-v0.11/entries"
read -r -p 'Existing reviewed evidence JSON path: ' OBS_EVIDENCE
read -r -p 'Your review/ticket reference: ' OBS_REVIEW
./scripts/archive-observability-evidence.py register \
  --archive "$OBS_ARCHIVE" --evidence "$OBS_EVIDENCE" \
  --kind raw --review-reference "$OBS_REVIEW"
./scripts/archive-observability-evidence.py verify --archive "$OBS_ARCHIVE"
```

Use `--kind redacted` instead for the supplied account-redacted test copy.
The tool preserves bytes exactly and creates `<SHA256>/evidence.json` plus
`record.json`. Re-registering identical bytes refuses rather than overwrites;
verify the existing entry instead. A changed file creates a separate history
entry, even when it claims the same observation. It is not an endorsed correction.

### Retain a baseline to detect removed or modified history

```bash
./scripts/archive-observability-evidence.py snapshot \
  --archive "$OBS_ARCHIVE" \
  --output "$HOME/observability-evidence-v0.11/baseline-001.json"
```

After registering additional reviewed observations:

```bash
./scripts/archive-observability-evidence.py verify \
  --archive "$OBS_ARCHIVE" \
  --baseline "$HOME/observability-evidence-v0.11/baseline-001.json"
```

Snapshots are outside the entries directory and created exclusively; use a new
snapshot filename each time. Keep previous snapshots in separately controlled
backup/version history. With no retained baseline, validation detects corruption
of present entries but cannot detect deletion of whole directories. Hashes are
integrity checks, not signatures or WORM retention; someone able to rewrite the
archive AND baseline can forge history. Organizational review remains necessary.
An interrupted registration leaves an incomplete reserved directory: verification
stops. Preserve it for diagnosis; do not overwrite history or repair it silently.

No archive command dispatches qualification, promotion or cleanup.
