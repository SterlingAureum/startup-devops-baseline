# v0.11.9.2.2.1 Empty-digest GitOps convergence repair

## Incident

During the fault-capable image's disabled-mode baseline rollout, the first
AnalysisRun and human-review checks passed and the Rollout paused safely at 50%.
The Root Application nevertheless remained `OutOfSync`.

`argocd app diff startup-devops-root` showed only:

```diff
===== argoproj.io/Application argocd/demo-api ======
>         value: ""
```

The parent Helm Chart rendered an explicit empty
`rehearsalFault.tokenSha256` value into the child Application. Application CRD
normalization omitted that empty field from live state, creating a permanent
desired/live diff. Runtime fault mode remained disabled; this was a GitOps
convergence defect, not a candidate SLO failure.

## Repair

- Omit the child `rehearsalFault.tokenSha256` Helm parameter when the digest is
  empty. The demo-api Chart default remains empty and workload behavior is
  unchanged.
- Render the parameter when an armed rehearsal supplies a non-empty digest.
- Make the deploy script's exact parameter allowlist mode-aware.
- Replace the final immediate Root status assertion with a bounded wait for
  both `Synced` and the exact source revision.
- Treat a Kubernetes-omitted empty EnvVar `value` as the semantic empty string
  in failure/recovery evidence checks.
- Update real Helm, fake Helm and historical successor regressions. No broad
  `ignoreDifferences` rule is added.

Applying and validating this increment performs no cluster operation and does
not promote, retry, abort or generate traffic.
