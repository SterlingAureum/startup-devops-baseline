# v0.11.9.2.2 Local failure/recovery live qualification

## Status and authorization boundary

This checkpoint makes the reviewed local-only rejection/recovery rehearsal
operator-ready. Applying or validating this increment does not run the live
rehearsal. The operator starts each phase explicitly and owns both manual
Rollout decisions. Nothing here operates AWS or production.

Do not begin unless `v0.11.9.2.1` is committed and pushed, the fault-capable
image has already passed the successful-release rehearsal with fault mode
disabled, and there is enough uninterrupted time to finish recovery.

The phase runner never promotes, aborts or retries automatically. Stop on any
unexpected identity, stable request failure, provider Error/Inconclusive,
timeout or ambiguous state. Preserve the private bundle.

## Terminal layout

Use two terminals:

- **Terminal 1** runs one phase at a time and performs the reviewed manual
  abort/retry commands.
- **Terminal 2** displays bundle status, command logs and read-only Rollout,
  AnalysisRun and Pod state.

Both terminals must start in the repository root. Set context explicitly:

```bash
cd ~/startup-devops-baseline
export LOCAL_CONTEXT=kind-startup-devops
kubectl config get-contexts "$LOCAL_CONTEXT"
```

Replace `kind-startup-devops` only with the exact loopback kind context in use.

## 2. Create an exact plan without copying runtime IDs

Choose a fresh candidate application version. It identifies the fault-armed
candidate but reuses the exact healthy image reference and runtime imageID.

```bash
PLAN_PARENT=$(mktemp -d /tmp/local-failure-recovery-plan.XXXXXX)
PLAN_FILE="$PLAN_PARENT/plan.json"
REHEARSAL_DIR="$PLAN_PARENT/run"
REVIEW_REF="local-rejection-review-$(date -u +%Y%m%dT%H%M%SZ)"
CANDIDATE_VERSION="v0.11.9.2.2-reject-$(date -u +%Y%m%d%H%M%S)"

python3 scripts/prepare-local-failure-recovery-live-plan.py \
  --context "$LOCAL_CONTEXT" \
  --candidate-version "$CANDIDATE_VERSION" \
  --review "$REVIEW_REF" \
  --operator "$USER" \
  --recovery-owner "$USER" \
  --plan "$PLAN_FILE" \
  --bundle "$REHEARSAL_DIR" \
  --confirm observe-and-write-local-plan
```

Expected signal: JSON reports `status: live_plan_prepared`, the exact pushed
source SHA, `execution_started: false`, and `runtime_qualified: false`.
The command is read-only against Git and Kubernetes; it creates only the
private plan. Do not enter `REHEARSAL_DIR=/tmp/...` where a raw path is asked.

Review the plan before executing anything:

```bash
jq '{source_commit,context,review_reference,evidence_directory,
     baseline,candidate,fault,recovery,whole_rehearsal_max_seconds}' "$PLAN_FILE"
stat -c '%a %n' "$PLAN_FILE"
```

The mode must be `600`; baseline and candidate image reference/imageID must be
identical; baseline fault is `disabled`; candidate fault is
`availability-503`.

```bash
python3 scripts/local-failure-recovery-rehearsal.py recovery-approval \
  --bundle "$REHEARSAL_DIR" --review "$REVIEW_REF" \
  --confirm approve-reviewed-local-recovery

python3 scripts/local-failure-recovery-rehearsal.py restore \
  --bundle "$REHEARSAL_DIR" \
  --confirm restore-reviewed-local-baseline
```

Expected signal: both phases pass. `restore` changes desired GitOps state back
to the exact planned baseline and renders fault mode `disabled`; it does not
automatically retry an aborted Rollout.

Inspect before retrying:

```bash
kubectl --context "$LOCAL_CONTEXT" -n startup-apps \
  get rollout demo-api -o json | jq \
  '{version:.metadata.annotations["platform.startup.dev/application-version"],
    faultMode:(.spec.template.spec.containers[0].env[] |
      select(.name=="REHEARSAL_FAULT_MODE").value),
    faultDigest:(.spec.template.spec.containers[0].env[] |
      select(.name=="REHEARSAL_FAULT_TOKEN_SHA256").value),
    phase:.status.phase,abort:.status.abort}'
```

Expected signal: exact baseline version, `faultMode: disabled`, empty digest.
If `abort` remains `true`, and only after the recovery owner accepts those
values, perform the manual retry once:

```bash
kubectl argo rollouts retry rollout demo-api \
  -n startup-apps --context "$LOCAL_CONTEXT"
```

## 8. Wait for recovery and close qualification

Observe without mutation:

```bash
kubectl argo rollouts get rollout demo-api \
  -n startup-apps --context "$LOCAL_CONTEXT" --watch
```

After it is Healthy, stop the watch with `Ctrl-C`, then run:

```bash
python3 scripts/local-failure-recovery-rehearsal.py final \
  --bundle "$REHEARSAL_DIR" --confirm observe-local

jq . "$REHEARSAL_DIR/qualification.json"
python3 scripts/show-local-failure-recovery-status.py \
  --bundle "$REHEARSAL_DIR"
```

Expected signal: `final passed`, `runtime_qualified: true`, the exact failed
AnalysisRun UID is retained, Root and demo-api are synced to the source SHA,
the known-good runtime imageID is restored, and fault mode is disabled.

## Safe retry rule

- A phase with `*.passed.json` must never be replayed.
- If a read-only phase fails before its passed marker, inspect its newest
  `failure.json` and current runtime; rerun only that same phase after the
  cause is understood.
- Never rerun `arm` after `arm.started.json` exists.
- Never rerun bounded traffic after evidence shows it ran or after the expected
  failed AnalysisRun exists.
- A failed `restore` or `final` never authorizes another abort or candidate
  traffic. Keep moving only toward fault-disabled baseline recovery.
- Never delete bundle markers to force progress. Start a new rehearsal only
  after the current runtime is explicitly recovered and reviewed.

Use this diagnostic after any stop:

```bash
python3 scripts/show-local-failure-recovery-status.py --bundle "$REHEARSAL_DIR"
LATEST=$(find "$REHEARSAL_DIR" -mindepth 1 -maxdepth 1 -type d \
  -printf '%T@ %p\n' | sort -n | tail -1 | cut -d' ' -f2-)
find "$LATEST" -maxdepth 1 -type f -printf '%f\n' | sort
test ! -f "$LATEST/command.log" || tail -n 100 "$LATEST/command.log"
test ! -f "$LATEST/failure.json" || jq . "$LATEST/failure.json"
```

The private bundle may contain cluster state and the raw fault token. Keep it
outside the repository; do not commit, upload or paste it unredacted.
