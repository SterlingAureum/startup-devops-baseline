# v0.11.9.3.1 existing-image aws-dev promotion

## Purpose and execution boundary

This checkpoint implements the missing handoff from the already accepted
`sha-cf0a6bc` image to a reviewed aws-dev release pull request. It does not
rebuild or retag the image. Applying or validating this increment does not
dispatch GitHub Actions, change any release values, push a branch, create a pull
request, access AWS or Kubernetes, or merge `main`.

The workflow is intentionally unusable from feature or pull-request refs. It
must first be reviewed and merged into protected `main`, then manually
dispatched from `refs/heads/main`. No remote runtime credential is exposed to
the feature branch.

## Accepted identity

```text
repository: ghcr.io/sterlingaureum/startup-devops-baseline/demo-api
tag/application version: sha-cf0a6bc
digest: sha256:cdffd3d71763540976570da1f201661d24c641ec459be812b20f1517f3fd2623
source repository: SterlingAureum/startup-devops-baseline
source commit: cf0a6bcbc466b61f2018a0a92c961d7c03f128e8
workflow run: 34070524953
metadata artifact: demo-api-image-metadata-cf0a6bcbc466b61f2018a0a92c961d7c03f128e8
release ID: demo-api-cf0a6bcbc466-cdffd3d71763
```

The image source commit remains distinct from the later protected-main
control-plane commit. The source must be an ancestor of the captured `main`;
the two identities are not forced to be equal.

## Verification sequence

`.github/workflows/demo-api-promote-existing-image.yaml` accepts only:

- the original successful image workflow run ID; and
- the expected full source commit.

No manual digest input is accepted. The workflow derives the artifact name from
the commit, downloads that exact artifact from the selected run and validates:

1. the run belongs to this repository and the exact image-publish workflow
   path, allowing GitHub's recorded `@ref` suffix;
2. the run completed successfully at the expected source commit;
3. the metadata run, repository, source, tag, digest and reference agree;
4. the source commit is contained in the captured protected-main history;
5. the digest-addressed GHCR manifest resolves to the same digest;
6. SLSA provenance is signed by the image-publish workflow for that source;
7. an SPDX 2.3 SBOM attestation exists for the same subject digest.

An expired or missing artifact, missing attestation, unreadable digest,
non-ancestor source or moving `main` stops the run. It never falls back to a
rebuild because that would create a different candidate.

## Mutation and PR boundary

Only `apps/demo-api/helm/values/releases/aws-dev.yaml` may differ from the
captured main tree. Helm lint and render must pass before any branch push.

The target branch is `release/demo-api-sha-cf0a6bc`. If it already exists, its
tree must exactly equal the newly derived candidate; the workflow never force
pushes or overwrites a different branch. An existing matching open PR is
reused. The workflow cannot merge the PR, deploy an environment, access EKS or
invoke Argo CD.

## Offline validation

Before committing this increment, run:

```bash
bash scripts/validate-v0.11.9.3.1-existing-image-aws-dev-promotion.sh
bash scripts/validate-ci-quality-gates.sh
```

The focused validator uses only temporary local Git and JSON fixtures. It
exercises successful identity derivation plus failed-run, cross-run metadata
and non-ancestor rejection. It does not contact GitHub or GHCR.

## Deferred live use

Do not dispatch the workflow from the feature branch. After the next checkpoint
restores active AWS overlays to `main`, full validation passes, the feature is
reviewed and merged, and the exact current main SHA is captured, a separately
approved operator step may dispatch:

```text
workflow: demo-api-promote-existing-image.yaml
ref: main
source_run_id: 34070524953
expected_source_commit: cf0a6bcbc466b61f2018a0a92c961d7c03f128e8
```

Review and merge of the resulting aws-dev release-only PR remain separate human
decisions. Environment creation and runtime qualification remain later steps.
