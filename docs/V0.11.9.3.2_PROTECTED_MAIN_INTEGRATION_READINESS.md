# v0.11.9.3.2 protected-main integration readiness

## Purpose and boundary

This checkpoint removes the temporary aws-dev feature-revision override before
the final v0.11 feature is reviewed for protected-main integration. Applying or
validating it does not merge a pull request, dispatch GitHub Actions, access
AWS or Kubernetes, reconcile Argo CD, create an environment, change a demo-api
release file, rebuild an image or change the Healthy local revision 70.

The implementation baseline is:

```text
cf2c7cd37c114e875b731fb151a05aad9b9cddd6
```

## Active AWS revision restoration

`clusters/aws/overlays/dev/kustomization.yaml` previously replaced the source
revision for nine same-repository child Applications with the v0.11 feature
branch. That override was required for the historical pre-merge aws-dev
qualification but must not survive final integration.

The override is now removed. The aws-dev children inherit `main` from their
base Application declarations, matching the existing aws-dev Root and the
already stable aws-test/aws-prod declarations. External Helm Chart versions
remain independently pinned.

`scripts/check-aws-gitops-revision-boundary.sh` now expects `main` for dev,
test and prod by default. A caller can still supply explicit expected revisions
for isolated historical testing, but the repository's normal acceptance path
is protected-main only.

## Historical preview boundary

`clusters/aws/overlays/test-feature-qualification` is retained as exact
historical offline-preview evidence from v0.11.8.2. It is not one of the active
dev/test/prod overlays, has no automatic sync and must not be bootstrapped.

Historical documents, contracts and test fixtures may continue to name the
feature branch when they describe the earlier pre-merge qualification. They do
not define current active desired state. The `.8.1.2` validator is now
successor-aware: it preserves its original feature contract and verifies that
the later restoration required by that contract has been completed.

## Validation

Run the focused checkpoint followed by the complete quality gates:

```bash
bash scripts/validate-v0.11.9.3.2-protected-main-integration-readiness.sh
bash scripts/validate-ci-quality-gates.sh
```

With Kustomize or kubectl installed, also retain the standalone rendered
boundary result:

```bash
bash scripts/check-aws-gitops-revision-boundary.sh
```

All three active AWS overlays must render every same-repository Application at
`main`; external Charts must retain their reviewed versions. No AWS credentials
or cluster access are required.

## Deferred reviewed integration

After the increment is committed and pushed, create a feature-to-main pull
request and let protected branch checks and CODEOWNERS review complete. Merging
is a separate human decision. Do not dispatch the existing-image workflow from
the feature branch and do not start a remote runtime workflow before the merge.

After the reviewed merge, capture the exact main SHA from both local and remote
refs. That SHA becomes the control-plane identity for the next checkpoint; it
is intentionally different from the older image source commit.
