# v0.11.9.3.6.7.2 guarded aws-test Terraform plan executor

## Purpose and status

This checkpoint implements and offline-tests a two-phase executor for the
aws-test Terraform plan. It does not run the live preflight, access AWS,
initialize Terraform, create a plan, apply infrastructure or create aws-test
while the increment is applied or validated.

The implementation baseline is protected-main commit:

```text
a94b69c75210a98210a3b9da7d4d32b0e8cbf93d
```

The successful `.6.7` preflight on that commit is design evidence only and is
pinned by SHA-256:

```text
5f12981fc2720ff4ac9a03b11d5d3444f03bbb0408d0e87190643549e81e18c3
```

Merging this executor changes protected main again. Therefore the fingerprint
above cannot be used as the executor's live fresh preflight. A new `.6.7`
preflight and newly populated `.6.7.1` private plan are mandatory after merge.

## Two phases

The entrypoint is:

```text
scripts/execute-v0.11.9.3.6.7.2-aws-test-terraform-plan.py
```

`verify` checks only local files, Git identity, private modes, fingerprints,
the reviewed time window and the saved preflight semantics. It runs no AWS or
Terraform command, leaves the plan output directory absent and reports:

```text
terraform_plan_authorized=false
terraform_plan_executed=false
terraform_apply_executed=false
environment_creation_authorized=false
commands_executed=[]
```

`execute` repeats the same checks, requires a separate plan-only confirmation,
runs the `.6.7` read-only preflight immediately and requires byte equality with
the reviewed result. It can then check the fixed Secret metadata, initialize
Terraform and produce a saved private plan. It never runs `terraform apply`.

## Exact-main and private inputs

The populated `.6.7.1` private plan and fresh preflight result must both be
regular non-symlink `0600` files under owner-only directories. The plan must
bind a clean `main` where local HEAD and `origin/main` equal the new
post-`.6.7.2` protected-main SHA. At least 900 seconds must remain in its
reviewed session window.

The private plan also binds:

- exact candidate and release ID;
- expected AWS account and region;
- current globally routable management IPv4;
- committed four-node aws-test qualification profile;
- ignored local `terraform.tfvars` fingerprint and reviewed Owner tag;
- a new output directory beneath an existing owner-only parent;
- current pricing estimate, eight-hour maximum window and USD 50 ceiling.

The output directory must not exist during `verify`. This prevents accidental
reuse or overwrite of an earlier, partially reviewed bundle.

## Environment sanitization

Live subprocesses inherit only required system/proxy variables and AWS
authentication settings. AWS endpoint overrides and Terraform CLI/`TF_VAR_*`
injection are removed. The executor fixes:

```text
AWS_REGION=us-east-1
AWS_ENVIRONMENT=aws-test
TF_IN_AUTOMATION=1
TF_DATA_DIR=<private output>/terraform-data
```

The current management address is passed to Terraform only as a runtime
`/32`; it is never committed or emitted in the redacted result.

## Secret collision boundary

Before and after planning, the executor calls only `DescribeSecret` metadata
for the fixed aws-test PostgreSQL Secret name. Initial creation requires an
explicit `ResourceNotFoundException` both times.

An active Secret, a deletion tombstone, AccessDenied, timeout, malformed
response or any other error stops. The executor never reads credential values,
restores, deletes, imports or adopts a Secret. Raw stdout/stderr remains in the
private output bundle.

This check preserves the recovery lesson from the earlier aws-test rebuild,
where a scheduled-for-deletion name was discovered too late during apply.

## Terraform plan boundary

The plan-only phase may run:

```text
terraform init -input=false -lockfile=readonly
terraform plan -input=false -lock=true -out=<private saved plan>
terraform show -json <private saved plan>
terraform show -no-color <private saved plan>
```

Terraform data and all captured output are owner-only. The machine gate fixes
the test environment, region, four-node qualification capacity and current
management `/32`. It requires exactly one aws-test EKS cluster create and, if
enabled, only the exact account-scoped test runtime access entry.

Allowed action vectors are:

```text
[create]
[read]
[no-op]
```

At least one create must exist. Update, delete, both replacement orders,
unknown/combined actions, foreign-account ARNs, non-test environment tags and
an empty plan stop before any apply capability exists.

## Private output bundle

A successful execute phase preserves:

- saved binary plan;
- Terraform JSON and no-color text renderings;
- init/plan/show private stdout and stderr;
- Secret metadata lookup stdout and stderr;
- redacted plan-gate counts;
- private `plan-record.json` with the account, management CIDR, input and
  artifact fingerprints, creation time and expiration.

The directory is `0700`; files are `0600`. The redacted executor result emits
hashes, counts and the expiry timestamp but no account, management address,
private path or Terraform resource identity.

The review expires after one hour or at the earlier teardown-review deadline.
Expiration requires a new preflight, private plan and Terraform plan; do not
edit timestamps or replay an expired binary plan.

## Offline validation before merge

```bash
bash scripts/validate-v0.11.9.3.6.7.2-aws-test-terraform-plan-executor.sh
bash scripts/validate-ci-quality-gates.sh
git diff --check
```

The tests use temporary private directories and mocked Git, AWS and Terraform
runners. They cover exact variable and cluster identity, all destructive action
vectors, account/tag/runtime-role drift, file permissions, exact main,
preflight byte equality, time and input drift, Secret collision/error handling,
environment sanitization, private artifacts and the absence of apply.

## Post-merge live preparation

After `.6.7.2` reaches protected main:

1. Capture the new clean `HEAD == origin/main` SHA.
2. Run and review a new `.6.7` private preflight for that SHA.
3. Create a new owner-only parent and a not-yet-existing plan-output child.
4. Copy and populate the `.6.7.1` private plan template with that exact main,
   new preflight SHA, private account/current management IPv4, local tfvars
   SHA, current pricing review and active UTC window.
5. Validate the private plan using the `.6.7.1` checker.
6. Run only the executor `verify` phase and submit its redacted JSON plus the
   private-plan and fresh-preflight hashes.
7. Obtain a separate explicit approval before `execute`.

The zero-command verify form is:

```bash
python3 scripts/execute-v0.11.9.3.6.7.2-aws-test-terraform-plan.py verify \
  --private-plan "$AWS_TEST_PRIVATE_CREATE_PLAN" \
  --fresh-preflight-result "$AWS_TEST_FRESH_PREFLIGHT_JSON"
```

Do not run `execute` merely because the code is merged or `verify` passes.
Do not invoke `scripts/apply-aws-test.sh` or the historical feature planner.
