# v0.11.9.3.6.7.3 guarded aws-test Terraform apply executor

## Outcome

This checkpoint implements and offline-tests the final Terraform boundary for
creating aws-test. It does not run a live preflight, Terraform or AWS command,
does not authorize apply, and does not create an environment.

The executor applies only a newly produced, reviewed saved plan. The plan
recorded by `.7.2.1` expired at `2026-09-12T09:19:02Z` and is evidence only;
changing its timestamps or reusing any of its private bytes is prohibited.

## Required post-merge sequence

After this checkpoint merges, use its new exact protected-main SHA to:

1. Run one fresh `.7` private preflight.
2. Populate and validate a new `.7.1` private creation plan with the current
   account, management IPv4, pricing review and bounded session window.
3. Run `.7.2 verify`, obtain separate plan-only approval, and execute `.7.2`
   once to produce a new private saved plan.
4. Review the new JSON/text plan and its create/read/no-op inventory.
5. Run `.7.3 verify`. This is local-only and leaves apply unauthorized.
6. Obtain a separate approval bound to the exact main, preflight, private plan,
   plan record, saved binary plan and `.7.3 verify result.
7. Run `.7.3 execute` once. Never retry automatically.

## Apply invariants

Immediately before apply, the executor reruns `.7` and requires byte equality
with the reviewed preflight. It again requires empty local state, absent Secret
metadata, exact private artifact hashes, and byte-identical `terraform show
-json` output that passes the create/read/no-op gate.

The mutation is exactly:

```text
terraform apply -input=false -auto-approve <reviewed-saved-plan>
```

There is no `terraform plan`, destroy, legacy wrapper, `kubectl`, Argo CD,
GitOps bootstrap, traffic or qualification command in this phase.

After a successful apply, private checks require all planned create addresses
in local state, no unreviewed state address, an ACTIVE aws-test EKS cluster
with the reviewed `/32`, and Secret metadata presence without reading its
value. Public JSON contains aggregate status and hashes only.

## Failure handling

Any drift stops closed. If Terraform apply fails or post-apply state is
uncertain, preserve the owner-only output and local Terraform state and begin
manual review. Do not replan, retry apply or destroy automatically. GitOps and
all higher-layer activity remain separately reviewed later checkpoints.
