# v0.11.9.3.6.7.4.1.1 Gitleaks Evidence Field Repair

## Outcome

GitHub quality gates reported one `generic-api-key` finding in the newly added
GitOps bootstrap execution-evidence contract. The reported value is a SHA-256
fingerprint of a private, read-only metadata observation, not credential
material. The finding is therefore a scanner false positive.

This increment renames the digest property to
`metadataObservationSha256`. The digest and its evidentiary meaning are
unchanged. The predecessor validator now checks the complete stable-output
map, including the exact renamed property and digest.

## Scanner evidence

- Scanner: Gitleaks
- Rule: `generic-api-key`
- Finding count: one
- PR-head commit: `121d8328d36ace3c18e2b85a3bc47006432cd8ab`
- Reported contract line: 155
- Reported value: redacted by CI
- Classification: SHA-256 fingerprint false positive
- Credential material committed: no

## Repair boundary

The repair does not add a fingerprint exception, a path exception, an inline
suppression or any broader scanner bypass. `.gitleaksignore` remains
byte-identical. The prior evidence contract changes only the property name;
the recorded digest is preserved exactly.

Applying and validating this increment performs no AWS, Terraform or
Kubernetes operation. It does not repeat the GitOps bootstrap, deploy the Root
Application, generate traffic, qualify the environment, promote a release or
authorize teardown.

## Validation

Run:

```bash
bash scripts/validate-v0.11.9.3.6.7.4.1.1-gitleaks-evidence-field-repair.sh
```

The validator binds the pre-repair and repaired contract fingerprints,
strengthened predecessor validator, unchanged scanner allowlist, exact finding
classification and no-operation boundary. It then recursively runs the
predecessor evidence chain.

The GitHub secret-scanning quality gate remains authoritative for confirming
that the original finding is no longer detected on the committed repair.
