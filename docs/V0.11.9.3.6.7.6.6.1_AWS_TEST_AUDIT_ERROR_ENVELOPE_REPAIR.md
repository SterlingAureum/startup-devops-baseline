## Observed stop and root cause

The preflight started September 14 02:00:15Z and stopped at backup-bucket. STS and EKS inventory
had completed; the bucket command returned exit 254, empty stdout and NoSuchBucket.
The local redacted diagnostic identified the zero-retry annotation. A standard,
resource-free error fixture exactly matches the reported stderr size (142 bytes)
and SHA-256. The old strict parser omitted that optional annotation and therefore
rejected authoritative absence. This was an implementation false negative, not a
bucket residual finding. The original stopped preflight is preserved unchanged.
No full audit, AWS mutation or consumed audit attempt occurred in that phase.

## Narrow compatibility fix

The new entrypoint accepts one complete error line with exact allowed absence code
and matching API operation. It permits either the original envelope or exactly
`(reached max retries: 0)` before the colon. Zero is a formatter annotation, not an
executed retry. Positive counts, malformed/duplicated annotations, extra error lines,
wrong API operations and nonempty stdout fail closed. AccessDenied, ExpiredToken,
SlowDown and generic NotFound text never qualify as absence.

AWS_MAX_ATTEMPTS remains 1, including the initial request. No second command is
issued to interpret an error. See [AWS CLI retries](https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-retries.html).
The original `.6.6` executor, contract and tests remain frozen. This version copies
the audited read-only implementation and changes only its contract binding and
absence parser. All original command scopes, input/state bindings, private-file
checks, proof TTLs, exclusive execute marker and no-retry behavior remain intact.
