## Root cause and AWS semantics

The September 14 02:40:44Z audit reached tag-classification-0 and stopped at
02:45:11Z. Its first tag sweep had five records; only the first was classified.
DescribeFleets returned one Type=instant, FleetState=active, ActivityStatus=fulfilled
record, with fulfilled and On-Demand capacities 1.0 and no unhealthy replacement.
These are user-restated public fields. The producer did not read private raw logs
and does not claim a hash-exact replay of their 3940-byte contents.

AWS documents instant as a synchronous one-time request. For instant, fulfilled
means requests have been placed even when target capacity is not met. Its Instances
list identifies instances that were launched, not their current native state.
Fleet state/capacity metadata alone is therefore insufficient to assert live compute
or native absence. See [Fleet request types](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-fleet-request-type.html)
and [FleetData](https://docs.aws.amazon.com/AWSEC2/latest/APIReference/API_FleetData.html).
DescribeFleetInstances is unsupported for instant; the implementation continues
using exact-ID DescribeFleets plus native DescribeInstances. See [CLI API support](https://docs.aws.amazon.com/cli/latest/reference/ec2/describe-fleet-instances.html).

## Narrow classification change

The new reusable pure classifier has no transport, mutation or credentials. It
accepts deleted/deleted_terminating only after the caller's native absence checks.
An active instant record additionally requires fulfilled status, an explicit false
ReplaceUnhealthyInstances, exact response identity and native test ownership tags.
Its explicit Instances list must contain valid unique instance IDs. Missing lists,
positive capacity without IDs, malformed metadata and ambiguous ownership stop.
An explicit empty list is accepted only with both fulfilled capacities zero.

The caller must prove each returned instance belongs to the hash-bound captured
instance set, then issue a FRESH exact-ID DescribeInstances check for each. Every
returned instance must be terminated, empty native results or an exact allowed
InvalidInstanceID.NotFound. Permission/connection errors and all other instance
states fail closed. The original tagged/native/captured compute, disk, VPC, ENI,
ALB and other managed-resource checks still run before Fleet classification.

Accepted instant request history receives its own public counter and unique
verified-instance count. It is never mislabeled as terminal/expired history.
Active maintain/request, unknown types, deleted_running and other states remain
failures. No Fleet deletion or DescribeFleetInstances call is introduced. A
previously uncaptured launched ID requires review; it is never silently ignored.

## Why dev passed while test stopped

The frozen dev executor invokes validate-aws-cost-cleanup.sh, which also rejects
all active Fleet states. Dev's recorded audit accepted eight terminal/expired Fleet
records. Its evidence does not prove active instant behavior was exercised. The
predecessor test auditor independently implemented stricter captured/private-state
checks but kept the same all-active rejection. Its tests omitted an instant-active
fixture. This is a shared coverage gap exposed by different runtime data, rather
than evidence that the infrastructure or GitOps manifests failed to deploy in test.

Infrastructure modules and platform/application declarations have substantial reuse;
approval/evidence executors remain checkpoint-specific and are not fully one common
runtime. Passing one environment or mocks is not proof of every service state/error
variant. Production may still expose configuration/permissions/dependency differences.
This repair shares the Fleet semantic function and tests dev/test/prod parameters,
but only the guarded test executor uses it. Frozen dev evidence is not rewritten and
the legacy wrapper rejects disposable aws-prod audits; this is not a prod executor.

Before a live prod rehearsal, consolidate applicable guarded orchestration into a
reviewed common core, leaving environment/account/state/release/budget/approval as
explicit bindings. Replay every discovered dev/test edge case against that core,
including CLI zero-retry envelopes, planned/state data-source differences, finalizer
cleanup dependencies, targeted destroy dependency closure and orphan ENI ownership.
Validate prod-specific non-disposable semantics and its exact offline entrypoints.
Do not promise identical behavior merely because deploy manifests are shared.
