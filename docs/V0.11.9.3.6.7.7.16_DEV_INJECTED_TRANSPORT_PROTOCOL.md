# v0.11.9.3.6.7.7.16 aws-dev injected transport protocol

Implementation baseline: `f006cc2be6ebbdee1dd874a89f70fbd6bdaf2a95`.

This checkpoint implements the `.7.7.15` transport design as a pure injected
protocol core and fixed-fake conformance harness. It does not construct a live
backend, read credentials, expose a command or create a durable live receipt.

## Protocol boundary

The core accepts all data explicitly: exact main, phase, synthetic receipt
prefix, fresh verify envelope, phase approval, injected current/completion UTC,
state-after hash, ordered postconditions, fixed fake transport and fixed fake
journal. It has no filesystem, environment, host clock, subprocess, SDK,
Kubernetes, AWS or Terraform access.

All eight aws-dev stages and 23 operation IDs remain closed. The core creates a
canonical request for each operation with the `.7.7.15` approval bindings and:

1. appends an in-memory intent before the fake call;
2. performs exactly one fixed-fake call;
3. validates an exact canonical response;
4. appends the response observation;
5. checks the complete ordered postcondition set and state relation; and
6. appends one terminal in-memory record only after every check passes.

Any exception or uncertainty stops immediately. No operation is retried or
repaired and no terminal record is produced after a partial attempt.

## Approval and receipt separation

The offline verify and approval envelopes bind the exact environment, phase,
main, inputs, scope, operation set, proof, state-before, predecessor, UTC
window and budget. Verify lifetime is at most 15 minutes and the approval
window is at most eight hours with a one-minute start reserve.

The result is deliberately a
`guarded-dev-offline-protocol-receipt-v1`, not a live receipt. It identifies
the live receipt schema only as a candidate, sets `simulation_only=true` and
`live_execution_authorized=false`, and is neither durable nor acceptable as
live authority. A historical live receipt also cannot seed this offline fake
prefix.

## Saved plans and state

Only `eks-delete` and `final-delete` accept the exact reviewed binary, JSON,
text, machine-gate and provider-lock hashes plus Terraform version and default
workspace. These two stages require a state transition. The other six stages
reject a saved-plan bundle and require state-before and state-after hashes to
remain identical.

The ExternalSecret drain remains read-only. Incident-only finalizer, storage,
backup, Secret and state powers never enter a request.

## Fixed fake conformance

The fixed fake derives a canonical success response only from the reviewed
canonical request. Tests may inject one explicit failure or malformed response
to prove fail-closed behavior. Exact concrete fake types are required, so a
custom subclass cannot silently become a backend.

Run:

```bash
bash scripts/validate-v0.11.9.3.6.7.7.16-dev-injected-transport-protocol.sh
```

The validator checks source and predecessor hashes, AST and privacy boundaries,
runs 50 tests and recursively replays `.7.7.15`. All validation is offline.

## Next boundary

The next increment may compose this injected core with a restart-safe offline
receipt adapter and the same fixed fake. It must still add no live backend,
credential reader or command. A live adapter and any aws-test or aws-prod use
remain separate future reviews.
