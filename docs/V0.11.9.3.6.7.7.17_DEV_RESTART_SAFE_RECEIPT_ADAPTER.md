# v0.11.9.3.6.7.7.17 aws-dev restart-safe receipt adapter

Implementation baseline: `f3a85b5ffc22a927076c6a37a9338b18d110b50c`.

This checkpoint composes the `.7.7.16` injected protocol with a strict local
receipt adapter and the same exact fixed fake. It makes synthetic offline
progress restart-safe without constructing a live backend, reading credentials
or exposing an execution command.

## Durable offline boundary

The caller supplies an absolute directory owned by the current user with mode
`0700`. Each completed phase appends exactly three owned, single-link `0600`
canonical JSON files:

1. an exclusive attempt marker before the first fixed-fake call;
2. the synthetic `.7.7.16` terminal receipt; and
3. a completion marker bound to the receipt hash.

Writes use exclusive no-follow opens, file synchronization and directory
synchronization. The final JSON byte is a local commit byte: an injected fault
at the after-write boundary leaves an invalid partial object instead of a
complete-looking receipt. A partial or pending triplet, unknown entry, link,
mode drift, non-canonical object, changed main, receipt-chain drift or replay
stops the session. Nothing is removed or repaired automatically.

## Restart and state continuity

A new adapter instance reloads the exact completed prefix before each phase.
The eight stages retain their closed order and all 23 fixed-fake operations.
The next approval state-before hash must equal the prior receipt state-after
hash. Only the two reviewed Terraform phases may change the synthetic state;
the inherited protocol continues to enforce that rule.

A durable attempt always precedes an operation call. Failure, a false
postcondition, invalid state relation or any one of twelve injected local I/O
faults leaves evidence that blocks another attempt. There is no retry, repair,
resume-over-pending behavior or conversion of the offline chain into live
authority.

## Deliberate non-live scope

The adapter performs only strict local receipt-directory reads and writes. It
does not read the host clock, environment variables, credentials or historical
private rehearsal evidence. It cannot invoke subprocesses, SDKs, AWS,
Kubernetes or Terraform. Its receipts retain the synthetic `.7.7.16` schema,
`simulation_only=true` and `live_execution_authorized=false`.

Run:

```bash
bash scripts/validate-v0.11.9.3.6.7.7.17-dev-restart-safe-receipt-adapter.sh
```

The validator checks hashes, AST and privacy boundaries, runs 41 local offline
tests and recursively replays `.7.7.16`. The tests rebuild the adapter between
phases, complete all eight phases into 24 files, and cover write ordering,
tamper, replay, partial state and fault stops.
