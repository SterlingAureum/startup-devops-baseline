# v0.11.9.3.6.7.7.1 共同 guarded runtime 纯规则

应用基线：`6927b6a256bb45ad85a12d9f8824a3b0e1352b68`。实现状态为 shared pure rules
implemented offline。前序 `.7.7` 的复核结论和历史证据保留；本包完成第一批规则模块，
完整 adapter 迁移尚未完成，也没有新的 live 执行入口。

## 模块与调用边界

`scripts/guarded_runtime_rules.py` 是可导入的纯模块，不读取系统时间、环境变量或文件，
不调用 AWS/Kubernetes/Terraform，不写 marker、不执行重试。所有数据和 policy 由调用方
显式传入，返回值只能证明这些输入满足某条规则，不能授予操作权限。
异常使用 `RuleViolation` 固定标签，不带原始值或凭据。

| 函数 | 输入与判定 |
| --- | --- |
| parse_utc | 严格秒级 Z 时间，拒绝 offset/fraction 和无效日期。 |
| validate_window | 显式 start/end/current、最大时长和启动剩余 reserve；两个有效边界 inclusive。 |
| validate_observation_age | 当前时间与 observation TTL，等于 TTL 仍有效，与前序 test 规则一致。 |
| validate_proof | created/expires/current/deadline、TTL 和 original_created；expiry 排他，不能重置 creation time。 |
| validate_confirmations | 显式目标与精确 phase mapping；拒绝跨环境 flag、无关空确认和已知 endpoint/TF overrides。 |
| absence_error | bytes stdout/stderr、operation 和该 operation 的允许 absence codes；只识别单一精确 CLI envelope。 |
| json_object | 已读 bytes，拒绝重复键、非对象、无效 JSON 和非有限数。 |
| state_addresses | v4 state 的精确 managed/data instance 地址，支持 count/for_each 与嵌套 indexed module。 |
| classify_state | plan/state/list 的集合与计数；返回 private address sets，属于诊断结果。 |
| validate_post_apply | 内部重算集合，检查 create 覆盖、无额外 managed 与精确 reviewed extra-data；拒绝删除/替换等 action。 |

窗口最大时长、TTL、reserve 和阶段确认值都由 reviewed adapter 传入，本模块不内置当前
main、账户、历史8h窗口、预算或90/50/40/7资源数。阶段确认值缺失 `-once` 这样的后缀
会在精确比较时失败，仍需调用方从版本化的 contract 提供完整期望值。

proof 的 `original_created` 必须来自已核验且未改写的 proof/saved-plan 证据。
模块要求 created 与它相同、expires 等于 min(deadline, created + TTL)，并检查当前时间
未到 expires。修改两个时间或使用 mtime 不能由 adapter 当作原始证据。纯函数本身
无法验证文件哈希或时间来源，adapter 仍需完成这些绑定。

## 兼容回归与更严格的输入边界

29 项离线测试直接对照冻结的 dev UTC 解析、test window/confirmation/absence 解析和
post-apply state 分类。历史96 plan changes、90 create、103 instance、80 block、七条
额外 data 的合成 fixture 被实际重放，各个 legacy aggregate 字段保持一致；新模块
没有调用 incident-specific waiver。它提供额外 private address sets，由 reviewed
adapter 明确固定本次允许的 extra-data 地址，不能只按 data type 或 count 放行。

新接口有意更严格：

- dev 的 offset/fraction 时间写法不纳入新 interface；正常秒级 Z 时间与 dev/test 一致。
- state list 必须等于从实际 index_key 推导出的当前 instance 集合；重复地址、deposed、
  未知 mode、无效 index、JSON 重复键或指数溢出都停止，不能靠前缀归类掩盖不一致。
- post-apply validator 拒绝 update/delete/replacement、managed read 和 data create；
  精确 reviewed extra-data 集合不能夹带没有实际出现的宽泛例外。

地址子集支持 ASCII Terraform identifier、非负 count index 和 JSON quoted for_each key，
含嵌套 indexed module。未知语法停止；adapter 不应降级到宽松分类。
classifier 不核验 managed before ID、真实云资源状态或 ownership，也不批准 destroy plan。
service absence parser 不把 CLI 错误自动转为通用缺失结论：allowed codes 必须由对应
service operation 的固定 policy 提供，未知错误或非空 stdout 留给 read-only review。

## adapter 迁移与后续实施

现有 live adapters 没有导入新模块，其源码和历史证据 hash 均冻结。新模块的 dev/test/prod
参数测试不是这些环境的 live 验证，也未创建 prod adapter。迁移应使用新版本执行器，
先以 fake transport 对照现有成功/失败路径，再单独审核 main/account/state/release、
时钟、权限、允许调用、私有路径和一次性 marker。

本批对应 `.7.7` 中 error envelope、state classification 和 proof/confirmation 三类规则。
既有 Fleet 纯规则继续独立保留。下一批处理 cleanup dependency：先 drain dependent
ExternalSecret，再移除所需 scoped RBAC/namespace，保持控制器可用；同时补 captured
ENI/SG continuation 的正反例。targeted destroy 的精确 dependency closure gate 也仍
需要未来迁移，不把 test 的50项清单复制成其他环境的常量。

本模块未实现 durable AttemptJournal、transport、cleanup action 或完整 adapter。
这些都保持后续明确范围：hash/身份绑定、原始 creation time、fresh clock、固定 API
allowlist、managed before ID、exclusive attempt 和私有日志必须在 adapter 执行层保留。
通过纯规则不意味着可以重新运行历史窗口或自动修复旧失败。
