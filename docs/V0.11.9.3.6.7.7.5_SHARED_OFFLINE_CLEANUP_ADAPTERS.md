# v0.11.9.3.6.7.7.5 三环境离线 cleanup adapters

应用基线：`dee9917b3e462dd21a29ebaca49685cfc3d37489`。

本增量把共同 runtime、cleanup 与 journal 规则组合为五个 fixed-fake cleanup
阶段，补齐 `.7.7.4` 之前未实现的 ESO/runtime drain、业务 namespace、NodePool/
EC2NodeClass 和 captured ENI→SG 收尾。41 项离线测试覆盖 dev/test/prod × 五阶段
的 15 个成功组合。没有调用或修改任何 live 执行器。

## 阶段与前置关系

| 阶段 | 离线行为 | 关键停止条件 |
| --- | --- | --- |
| drain-external-secrets | 对删除中的精确 ExternalSecret 只返回 waiting；对象归零后记录 absence | ESO/RBAC 不可用、策略或 finalizer 未知、namespace 已提前删除 |
| delete-business-namespaces | 按审核顺序模拟删除精确 Namespace | 名称不在 allowlist、UID/resourceVersion 漂移、未知 finalizer |
| drain-runtime | 聚合确认 NodeClaim/PV/计算/卷/ALB/TG/DNS 均为零 | inventory 不完整或任一计数仍非零 |
| delete-node-config | 按审核顺序模拟删除 NodePool 和 EC2NodeClass | 任一类型缺失、对象漂移、未知 finalizer |
| eni-sg-cleanup | 先 ENI，原生 absence 后再判定 SG；已不存在则跳过 mutation | ENI attached/associated、归属漂移、SG 仍有 ENI 或其他 SG 引用 |

每个阶段都要求此前步骤的逐条 confirmed simulation receipt，顺序必须是
`CLEANUP_STEPS` 的精确前缀。receipt 只是 fixture 证明，不代表历史或真实 live 操作。
ExternalSecret 允许此前 aws-test 实测的 `CreateOrMerge/Retain` 组合，但本 adapter
不会修改其 finalizer；实际阻塞仍须另行设计、审核和授权。

## 固定输入与时钟

`OfflineCleanupAdapter(environment, phase, main, repository_root=...)` 只接受：

- bytes 形式的 inputs/scope/state，均由 `offline-cleanup-approval-v1` 固定 SHA-256；
- 显式 dev/test/prod、us-east-1、12 位账户格式、环境后缀 cluster 和预算；
- 固定绝对 journal 路径及精确 `CONFIRM_<ENV>_OFFLINE_CLEANUP`；
- `ScenarioClock` 的单调 UTC 样本和 exact `CleanupScenarioTransport`；
- 最长 8 小时窗口、至少 60 秒启动余量、900 秒 proof TTL、60 秒 observation TTL。

reserve 前、每个 intent 前和 intent fsync 后都重新验证窗口/proof；intent 后再次验证
观测时效。每个 fake 调用后的 native postcondition 和最终 state-unchanged 证明必须在
执行截止前完成。时钟、身份、资源与成本都是测试数据，不是价格或账单保证。

## 一次性与失败语义

模拟 mutation 前必须在持久私有 journal 写入 intent 并 fsync。明确失败写 terminal
failure；返回结构不确定、fake transport 中断或后置核验失败保留 pending。已完成、失败
或 pending 的目录都不能再次调用 fake mutation。多个对象中前一项成功、后一项失败时，
前者保持 success，后者保持 failure/pending；不会重置或补写虚假完成回执。

ESO 或 runtime 仍有对象时不 reserve journal、不调用 fake backend，仅返回 waiting；
确认为空时用 observed-absent 事件记录完成。ENI/SG 若原生查询确认对象已不存在，也以
observed-absent 记录，禁止重复删除。代码没有 force finalizer、detach、SG rule 修改、
自动重试/修复或凭据读取路径。

公开 success/failure report 只含环境、阶段、计数和 journal 哈希，不含账户、cluster、
对象名、UID、资源 ID、私有路径或原始错误。journal 的 Linux O_EXCL/flock/fsync 约束
来自冻结的 `.7.7.3` 实现，测试只在仓库外 synthetic 私有目录落盘。

## 边界与后续

这是离线 adapter，不是真实 AWS/Kubernetes transport，也不授权 prod 或任何 live 操作。
历史 aws-test teardown、residual audit、窗口、批准和 marker 保持收口且不可复用。
未实现 ExternalSecret finalizer repair、强制 Namespace/PV 清理、backup/container 删除，
也未迁移现有 dev/test live adapter。下一批先审核 `.7.7.4` 与本批组合后的全阶段 parity/
gap，再独立设计 live 迁移；prod 仍需新的价格、预算、proof 和人工批准。
