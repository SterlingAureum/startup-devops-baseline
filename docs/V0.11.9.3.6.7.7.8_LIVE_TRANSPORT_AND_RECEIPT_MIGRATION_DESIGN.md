# v0.11.9.3.6.7.7.8 live transport 与 receipt 迁移设计

应用基线：`50b27de63e48ff4602f3f4d8680f2ece75bc8adc`。

`.7.7.7` 已完成 dev/test/prod × 八阶段的 24/24 fixed-fake 组合验证。本增量只把
未来 live 迁移边界固化为可执行的纯规则和机器可验证 contract，不实现任何 live
transport、命令入口或持久文件写入。

## 不转换 synthetic receipt

离线 receipt 只能证明 fixture 顺序和纯规则组合正确，不能证明实时账户、集群、state、
对象身份或 mutation 结果。因此未来 live 链不得把 `.7.7.7` synthetic receipt 或历史
aws-dev/aws-test receipt 转换成新格式，也不能把它们作为第一阶段前驱。

每个环境必须从新的实时 preflight 和 executor verify 开始：

1. `freeze-applications` 是索引 0，live receipt 的 predecessor 必须为 `null`；
2. 后续阶段只能消费同一环境、紧邻前一阶段的精确 receipt SHA-256；
3. skip、重排、跨环境 receipt、failed/pending receipt 或进程内未持久结果全部拒绝；
4. 每个阶段都重新绑定 main、输入、scope、state、proof、操作集、预算与时间窗。

## versioned transport

`guarded-live-transport-v1` 使用按阶段封闭的操作枚举，不接受原始 shell、动态命令模板、
endpoint/credential override、自动重试或自动修复。只有 `eks-delete` 和 `final-delete`
包含对已审核 saved plan 的 show/apply 能力；通用 transport 没有重新 plan 能力。

八阶段顺序保持：

1. `freeze-applications`
2. `drain-external-secrets`
3. `delete-business-namespaces`
4. `drain-runtime`
5. `delete-node-config`
6. `eks-delete`
7. `eni-sg-cleanup`
8. `final-delete`

每次 mutation 前仍需 durable intent，结果不确定时保留 pending 并停止。transport 的
success acknowledgement 不能直接生成 receipt；必须先完成独立后置观察和 journal
completion。

## approval command

未来命令固定分为 `verify` 与 `execute`：verify 永不 mutation，execute 必须取得新的阶段级
人工批准。一次批准只覆盖一个环境、一个阶段和一次 attempt，并绑定：

- transport version、protected-main 和审批文本哈希；
- private inputs、scope、state、proof、operation set 和 predecessor receipt 哈希；
- start/end、proof created/expires 时间及总预算上限。

历史批准和窗口不能复用；无关确认变量、继承的 AWS/Terraform override、自动 retry/repair
确认均需 fail closed。

## durable receipt

`guarded-live-phase-receipt-v1` 只允许在 terminal success 后创建。设计要求私有持久目录
`0700`、文件 `0600`、canonical JSON、exclusive create、文件和目录 fsync，并拒绝符号链接
与硬链接替换。receipt 只保存绑定哈希和结果标志，不公开资源身份；其精确 SHA-256 作为
下一阶段唯一前驱。

failed/pending、重复 attempt、automatic retry、incident repair 或 synthetic 字段都不能
写成成功 receipt。进程重启后也必须从持久 journal/receipt 恢复，不能依赖内存状态。

## incident 与环境 rollout 边界

ExternalSecret finalizer 删除、强制 Namespace/PV finalizer、未捕获资源删除、临时备份版本
删除、Secret 强制删除或 value 读取以及 state 编辑/导入，均不属于正常 transport。
若真实执行遇到这些情况，必须停止并另做 observation、修复设计和人工批准，不能自动回到
正常 receipt 链。

三个环境仅做 schema 覆盖。目前 live-enabled 环境数为零；未来第一候选只能是 aws-dev，
aws-test 必须等待 dev 迁移证据，aws-prod 在独立价格、预算、账户、release、scope、proof
和人工批准前保持禁用。
