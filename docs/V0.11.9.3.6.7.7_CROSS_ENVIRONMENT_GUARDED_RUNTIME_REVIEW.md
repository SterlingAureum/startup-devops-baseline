## 复核结论

基础设施模块可复用，但当前受控执行流程并不是一个完整的共同运行层。
dev residual audit 的版本执行器调用 `scripts/validate-aws-cost-cleanup.sh`；该 shell
仍按 FleetState 拒绝 active。test 的 `.7.6.6.2` 执行器采用独立的 captured/native/tagged
审计，并调用 `scripts/aws_fleet_audit_classification.py`。Fleet 审计分类已提取为共用纯函数；
dev/test/prod 参数回归证明的是分类规则，不是三个环境的 live adapter 已验证。

dev 历史成功证据接受的是八条 terminal/expired Fleet 记录，test 此次接受的是四条
instant 请求历史，并逐一核验四个 captured instance 的原生 absence。两次真实输入
不同，dev 的成功不能代替遗漏的 instant-active 回归。test 暴露的是实现与测试覆盖缺口。

每行 contract 保存可解析的测试方法引用和完整源码 SHA-256。新 validator 用 AST 核验
方法存在，再通过前序聚合目标链重放现有离线回归。这些引用不会自动补足缺失测试。
`partial-regression` 两项必须在共同运行层实现时补齐，当前不能记录为端到端覆盖：

- ESO：模拟删除 scoped RBAC 后无法 patch，以及保留权限时正常完成的两条路径；
  在 namespace 和其 RBAC 删除之前 drain dependent ExternalSecret；完成后才撤销权限，
  未知 finalizer 必须停止。
  历史单对象 finalizer 修复的独立批准不能成为通用自动修复规则。
- ENI/SG：用新私有快照测试附着、requester-managed、账户、网络、公网 association、
  引用与消失情况；记录每次 mutation 的唯一 attempt，不提供 detach 或自动重试。

ESO ready 不等于有 cleanup 权限：这次 namespace 卡住存在流程顺序缺陷，人工中断
结束了等待而不是产生该缺陷。历史调查与独立修复记录见
[剩余清理说明](V0.11.9.3.6.7.6.3_AWS_TEST_REMAINING_CLEANUP.md)。
EKS/ENI 收尾证据见 [teardown evidence](V0.11.9.3.6.7.6.5_AWS_TEST_TEARDOWN_EXECUTION_EVIDENCE.md)。

## 共同运行层的接口与实施顺序

contract 固定六个拟议接口：EnvironmentProfile、ReviewProof、ServiceObservation、
PlanScope、CleanupDependencies、AttemptJournal。纯规则接受显式输入并返回判定；
AWS/Kubernetes/Terraform adapter 负责固定 allowlist、原始输出及调用，不能扩展批准范围。
历史证据/执行器作为冻结输入保留，新共同模块和新 adapter 使用新版本，不追写历史。

1. 先提取 clock/phase/error/state 的纯规则，做现有正反例的兼容回归；
   saved plan 的 creation time 不能因 adopt、mtime、main 合并或续接而重置。
2. 实现 dependency-aware cleanup 和 captured ENI/SG continuation，补齐上面两项缺口；
   先取消业务协调，再 drain 业务依赖，保留所需控制器/权限，最后才删 EKS 与 VPC。
3. 新 adapter 用 dev/test/prod 的离线 profile 和 fake transport 共用同一套正反例；
   比较 state、IAM、release、DNS、范围和错误路径，禁止执行器里的隐式环境回退。
4. 完成上述代码和回归后，单独规划 prod 的 immutable release、fresh preflight、
   当前价格/预算与窗口，任何 live 阶段重新审核和批准。

本包完成复核 contract、源码/方法/配置一致性门和现有回归重放，不声称该迁移已经实现。
后续实现目标和验收要求写在每项 `futureAcceptance`，不替用户授权任何 live 操作。
