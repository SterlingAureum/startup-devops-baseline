# v0.11.9.3.6.7 guarded aws-test live-creation preflight

## Purpose

This checkpoint implements—but does not execute—the read-only readiness gate
before any aws-test Terraform plan or billable infrastructure creation.

It starts only after the aws-dev teardown and residual-cost audit chain is
recorded as complete. It binds that evidence, the reviewed aws-dev-to-aws-test
release promotion, the current dev/test/prod release files, the aws-test local
backend declaration and the historical apply wrapper by SHA-256.

Applying and validating this package performs no GitHub, AWS, Terraform,
Kubernetes, GitOps, traffic or environment operation.

## Why the existing apply wrapper is not the next step

`scripts/apply-aws-test.sh` initializes Terraform, creates a plan and
immediately applies it in one invocation. That behavior predates the guarded
live-rehearsal evidence chain and does not provide a separate review boundary
between plan and apply.

This checkpoint fingerprints the wrapper for drift detection but never invokes
it. Direct invocation remains forbidden. A later plan/executor checkpoint must
separate the private reviewed plan from a new exact-main execution approval.

## Read-only preflight model

The preflight requires:

- clean `main`, with `HEAD` and `origin/main` equal to one reviewed full SHA;
- the `.6.7` implementation baseline and immutable image source commit to be
  ancestors of that exact main;
- `AWS_ENVIRONMENT=aws-test` and the expected private 12-digit account ID;
- all aws-dev/aws-test create, destroy and prior execution controls unset;
- byte-exact `.6.1` aws-dev residual-cost audit evidence;
- byte-exact `.6.4` aws-test release-promotion evidence;
- byte-equal aws-dev/aws-test release files and the held aws-prod release;
- no active aws-dev, aws-test or aws-prod rehearsal EKS cluster;
- an absent aws-test local Terraform state file, or a regular version-4 state
  containing zero resource blocks and zero instances.

The aws-test Terraform root intentionally still declares a local backend.
Therefore this phase directly inspects the local state file without running
`terraform init`, `state`, `plan` or any other Terraform command. A symlink,
malformed state, nonempty state or unreadable file fails closed. No resource
attributes or state path are emitted.

AWS access is limited to:

```text
sts get-caller-identity
eks list-clusters
```

The returned JSON omits the account ID and cluster identities. It authorizes
neither Terraform plan nor environment creation.

## Post-merge private preflight

Do not use implementation baseline `c95af1633718eed3429e34311ed55910dbb53a7e`
as the live control-plane commit. After this increment reaches protected main,
capture the new full SHA and use it below:

```bash
git status --short
git rev-parse HEAD
git rev-parse origin/main

umask 077
export AWS_ENVIRONMENT='aws-test'
export EXPECTED_CONTROL_PLANE_COMMIT='<exact new protected-main SHA>'
export EXPECTED_AWS_ACCOUNT_ID='<private 12-digit account ID>'
export CONFIRM_AWS_TEST_CREATE_PREFLIGHT='observe-reviewed-aws-test-create-preflight'

unset CONFIRM_AWS_ENVIRONMENT_DESTROY
unset CONFIRM_AWS_DEV_TEARDOWN_EXECUTION
unset CONFIRM_AWS_DEV_APPLY
unset CONFIRM_AWS_TEST_APPLY
unset CONFIRM_AWS_DEV_RESIDUAL_COST_AUDIT_EXECUTION
unset AWS_TEST_APPLY_MODE

export AWS_TEST_PREFLIGHT_DIR="$(mktemp -d /tmp/v0119367-aws-test.XXXXXX)"
export AWS_TEST_PREFLIGHT_JSON="$AWS_TEST_PREFLIGHT_DIR/preflight.json"
export AWS_TEST_PREFLIGHT_STDERR="$AWS_TEST_PREFLIGHT_DIR/preflight.stderr"

python3 scripts/preflight-v0.11.9.3.6.7-aws-test-live-creation.py verify \
  --expected-control-plane-commit "$EXPECTED_CONTROL_PLANE_COMMIT" \
  >"$AWS_TEST_PREFLIGHT_JSON" \
  2>"$AWS_TEST_PREFLIGHT_STDERR"

PREFLIGHT_EXIT=$?
printf 'preflight_exit=%s\n' "$PREFLIGHT_EXIT"

stat -c '%a %n' \
  "$AWS_TEST_PREFLIGHT_DIR" \
  "$AWS_TEST_PREFLIGHT_JSON" \
  "$AWS_TEST_PREFLIGHT_STDERR"

sha256sum \
  "$AWS_TEST_PREFLIGHT_JSON" \
  "$AWS_TEST_PREFLIGHT_STDERR"

wc -c "$AWS_TEST_PREFLIGHT_STDERR"
cat "$AWS_TEST_PREFLIGHT_JSON"
```

Expected ready-state boundaries include:

```text
status=aws-test-live-creation-preflight-ready-for-separate-plan-review
account_verified=true
account_id_emitted=false
active_rehearsal_environment_count=0
terraform_state_resource_block_count=0
terraform_state_resource_instance_count=0
legacy_apply_wrapper_invoked=false
terraform_command_executed=false
terraform_plan_executed=false
terraform_apply_executed=false
environment_creation_authorized=false
mutation_executed=false
aws_test_created=false
```

Review the exit code, exact commit, redacted JSON, SHA-256, empty stderr and
`0700/0600` permissions. Do not run the legacy apply wrapper after preflight.

## Next boundary

A successful live preflight is only readiness evidence. It must be recorded or
bound into a separately reviewed private aws-test creation-plan checkpoint.
That successor must establish cost and time limits, produce a reviewable
create/read/no-op-only Terraform plan and keep apply behind a new executor
verify plus explicit approval.

GitOps bootstrap, runtime qualification, promotion and teardown remain later
independent phases. This checkpoint grants none of those permissions.
