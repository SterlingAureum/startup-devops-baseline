# v0.12.1.1 Guarded State-Bootstrap Plan

v0.12.1.1 is regenerated on the green v0.12.1.0.1 CI compatibility repair and
turns the v0.12.1 backend declaration into a guarded, plan-only
operator entry point. It can produce one private saved Terraform plan for the
state-bootstrap root after separate approval. It cannot apply that plan,
create backend resources, attach an IAM policy, or migrate state.

The canonical contract is
`delivery/contracts/v0.12.1.1-guarded-state-bootstrap-plan.json`.

## Delivered controls

The entry point `scripts/execute-v0.12.1.1-state-bootstrap-plan.py` has two
explicit phases:

- `verify` performs local, command-free checks and emits only redacted hashes,
  timing and control-plane identity;
- `execute` repeats every verification gate, checks the approved AWS account,
  initializes an exact private copy with `-backend=false`, saves a Terraform
  plan, renders private JSON/text views, and applies the machine plan gate.

Both phases require a clean `main` worktree whose `HEAD` and `origin/main`
equal the private request's exact reviewed commit. The request and tfvars must
be regular non-symlink files with mode `0600` beneath mode `0700` directories
outside the repository. The output directory must not already exist.

The approval window is at most one hour and must have at least 15 minutes
remaining when verification starts. `execute` additionally requires exactly:

```bash
export CONFIRM_STATE_BOOTSTRAP_PLAN=plan-state-backend-foundation
```

Apply, destroy and migration confirmations must be unset.

## Exact accepted plan

The machine gate accepts exactly 13 managed `create` actions:

- the S3 bucket, versioning, ownership, public-access block, SSE-KMS and TLS
  policy resources;
- the rotation-enabled KMS key and alias; and
- five unattached exact-key IAM managed policies.

Known data sources may be `read` or `no-op`. Every update, delete,
replacement, import, policy attachment, EKS resource, unexpected managed
resource or changed private input stops the attempt. Critical planned values
must still show versioning enabled, bucket-owner enforcement, complete public
blocking, SSE-KMS with a Bucket Key, KMS rotation, a 30-day deletion window
and `force_destroy = false`.

The initial bootstrap root must have no local Terraform state. Any state file
means this is no longer a first-create plan and requires investigation rather
than reuse of this entry point.

## Private request preparation

Copy the tracked placeholder template into a private owner-only directory:

```bash
install -d -m 0700 /private/owner-readable
install -m 0600 \
  delivery/examples/v0.12.1.1-state-bootstrap-plan-request.example.json \
  /private/owner-readable/state-bootstrap-plan-request.json
install -m 0600 \
  infra/terraform/aws/state-bootstrap/terraform.tfvars.example \
  /private/owner-readable/state-bootstrap.tfvars
```

Replace every placeholder. The request binds:

- the exact protected-main commit;
- the expected 12-digit AWS account, retained only in the private request;
- the private tfvars absolute path and SHA-256;
- the reviewed bucket name, KMS alias and additional tags;
- a new private output directory; and
- a bounded UTC approval interval.

Keep the real bucket name, account ID, principal identity and all plan output
out of Git, tickets, chat and public CI artifacts.

## Command-free verification

From the exact protected-main checkout, run:

```bash
python3 scripts/execute-v0.12.1.1-state-bootstrap-plan.py verify \
  --private-request /private/owner-readable/state-bootstrap-plan-request.json
```

A successful verification explicitly reports `terraform_plan_authorized` as
false and `commands_executed` as an empty list. Review that output before
granting a distinct plan approval.

## Separately approved plan execution

Only within the request's active approval window:

```bash
export CONFIRM_STATE_BOOTSTRAP_PLAN=plan-state-backend-foundation
python3 scripts/execute-v0.12.1.1-state-bootstrap-plan.py execute \
  --private-request /private/owner-readable/state-bootstrap-plan-request.json
unset CONFIRM_STATE_BOOTSTRAP_PLAN
```

The executor uses the normal AWS credential chain, pins the configured region
to `us-east-1`, rejects an account mismatch, and ignores endpoint override
variables. It invokes only Terraform version, `init -backend=false`, `plan`
and `show`, plus the STS caller-identity read. It stages exact reviewed `.tf`
bytes under the private output directory so provider initialization cannot
modify the repository checkout.

The output directory is sensitive and remains mode `0700`; every contained
file is mode `0600`. It includes the saved plan, JSON/text renderings, command
logs, source manifest, machine-gate result and a private plan record. Public
stdout includes hashes and counts but no account ID, bucket name, ARN, plan
body or AWS response.

## Human review and stop point

Review the private text and JSON plan, the machine-gate record, input/source
hashes, all command stderr, and the expiry. Stop on any unexplained provider
warning, identity difference, unexpected resource, unreviewed tag or stale
plan.

Successful plan generation is not permission to apply. v0.12.1.2 must define
and separately approve consumption of the exact unexpired saved-plan digest,
then validate the live S3/KMS/IAM-policy foundation while retaining protected
local bootstrap state.

v0.12.2 remains the sole owner of backend declaration changes, non-empty state
migration, immutable local backup, lineage/address/resource-ID comparison,
lock-contention proof, zero-change verification and object-version recovery.

## Offline validation

Run:

```bash
bash scripts/validate-v0.12.1.1-guarded-state-bootstrap-plan.sh
```

The validator uses synthetic plan fixtures and injected command results. It
does not read credentials or invoke Git, AWS, Terraform, Kubernetes or GitHub.
