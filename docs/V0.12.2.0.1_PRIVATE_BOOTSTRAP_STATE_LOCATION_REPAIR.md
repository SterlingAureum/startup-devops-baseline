# v0.12.2.0.1 Private Bootstrap-State Location Repair

v0.12.2.0.1 corrects one design-only state-location assumption before the
v0.12.2.1 preflight is implemented. It performs no AWS or Terraform command,
does not copy or move state, and grants no migration authority.

The canonical repair contract is
`delivery/contracts/v0.12.2.0.1-private-bootstrap-state-location-repair.json`.

## Observed mismatch

The v0.12.2.0 contract named
`infra/terraform/aws/state-bootstrap/terraform.tfstate` as the migration
source. That tracked-root-relative location was not the target used by the
reviewed v0.12.1.2 apply.

The saved plan was produced from a private staged source and the exact binary
plan was applied there. The successful apply wrote the working state at the
relative path `source/terraform.tfstate` beneath the original private plan
bundle. It also preserved a second copy named
`state-bootstrap.tfstate.applied` beneath the original private apply output
directory. v0.12.1.2.0.1 recovery verified that these two private files were
byte-identical and bound them to the public applied-state SHA-256:

```text
83bca892fef5f5eefffba3de247c4694daccf7201309262ff8dd73b61bc1b995
```

No real private directory, AWS identity, resource identity or state byte is
published by this repair.

## Corrected migration source

v0.12.2.1 must accept the original private plan/apply/recovery request chain
and derive both state files from the already-bound private directory fields:

- `privatePlanBundleDirectory` + `source/terraform.tfstate` is the canonical
  migration source;
- `privateApplyOutputDirectory` + `state-bootstrap.tfstate.applied` is an
  independent preserved cross-check; and
- both files must be regular non-symlink mode `0600` files with the exact
  public digest and byte-identical contents before any operational command.

The repository-root state path is neither required nor accepted as a fallback.
If an unreviewed state file appears there, the future preflight must stop rather
than infer that it is equivalent.

Do not rename, move, edit or replace either existing private state copy. The
new immutable migration backup required by v0.12.2.0 must be a third copy made
from the canonical private plan-bundle state into a new private output
directory. It cannot replace either incident/evidence artifact.

## Successor boundary

v0.12.2.1 must bind all original private plan, apply and recovery requests,
their SHA-256 values, the plan bundle, apply output, recovery output and the
applied-state digest. File validation and byte comparison occur before any
Terraform or AWS command.

This repair does not add the v0.12.2.1 request example or executor and does not
establish a live approval window. Those remain the next separately reviewed
increment.


The validator binds the correction to the existing apply/recovery source code
and predecessor evidence while executing no AWS or Terraform operation.
