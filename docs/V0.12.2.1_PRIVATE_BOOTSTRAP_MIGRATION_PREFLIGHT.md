# v0.12.2.1 Private Bootstrap Migration Preflight

v0.12.2.1 adds a guarded preflight for the first non-empty Terraform state
migration. Applying this repository increment runs no AWS or Terraform command,
reads no private evidence and does not migrate state.

The canonical contract is
`delivery/contracts/v0.12.2.1-private-bootstrap-migration-preflight.json`.

## What changes

The bootstrap root now contains the empty partial declaration
`backend "s3" {}`. No bucket, key, KMS ARN or credential is tracked. The
declaration alone does not initialize the backend or move state.

The preflight is bound to the original private v0.12.1.1 plan request,
v0.12.1.2 apply request and v0.12.1.2.0.1 recovery request. It accepts only the
canonical private plan-bundle `source/terraform.tfstate` and the byte-identical
preserved `state-bootstrap.tfstate.applied` copy. A repository-root state file
is not an accepted fallback.

## Prepare a new approval window

Copy
`delivery/examples/v0.12.2.1-bootstrap-migration-preflight-request.example.json`
to a new owner-only private file. Set its parent to mode `0700`, the request and
backend-config files to `0600`, and use a new output directory name that does
not exist. Set `expectedMainCommit` to the protected-main commit containing
this increment.

The private `bootstrap.s3.tfbackend` must contain exactly:

```hcl
bucket       = "VALUE_FROM_APPLIED_STATE_OUTPUT"
key          = "bootstrap/terraform.tfstate"
region       = "us-east-1"
encrypt      = true
kms_key_id   = "VALUE_FROM_APPLIED_STATE_OUTPUT"
use_lockfile = true
```

Do not include access keys, secret keys or session tokens. Record its SHA-256
in the private request. The approval window may be at most one hour and must
have at least 15 minutes remaining when either phase starts.

## Command-free verification

```bash
python3 scripts/execute-v0.12.2.1-bootstrap-migration-preflight.py verify \
  --private-preflight-request "$PREFLIGHT_REQUEST"
```

`verify` checks protected main, the complete private evidence chain, both
state copies, the exact 13 managed addresses, terminal recovery evidence,
current Terraform source and the private backend config. It executes no AWS or
Terraform command and writes nothing.

## Separately approved preflight execution

After reviewing the redacted verification output, set only the preflight
confirmation and execute once:

```bash
export CONFIRM_STATE_BOOTSTRAP_MIGRATION_PREFLIGHT=prepare-reviewed-bootstrap-state-migration
python3 scripts/execute-v0.12.2.1-bootstrap-migration-preflight.py execute \
  --private-preflight-request "$PREFLIGHT_REQUEST"
unset CONFIRM_STATE_BOOTSTRAP_MIGRATION_PREFLIGHT
```

Execution first creates a third mode-`0600` immutable state backup and a
private staged migration source. It then checks the Terraform version and
performs read-only AWS validation of the empty versioned S3 bucket, KMS key and
five unattached IAM policies. It writes a state inventory, source manifest,
live validation and an exact private `terraform init -migrate-state
-force-copy` command plan.

The planned init command is not executed. No init, plan, apply, state push,
destroy, IAM attachment or migration is authorized by v0.12.2.1.

## Handoff

Human-review the private preflight result, state inventory, source manifest,
live validation and command plan. v0.12.2.2 must use a new approval request and
a new time window. Expiry of the v0.12.2.1 window does not invalidate completed
private preflight evidence, but it cannot authorize migration.

## Offline validation

```bash
bash scripts/validate-v0.12.2.1-private-bootstrap-migration-preflight.sh
```

The repository validator and injected tests execute no live AWS or Terraform
operation.
