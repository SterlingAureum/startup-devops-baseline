# v0.12.2.3.1.0.1.0.1 Refresh-Only Plan Evidence Recovery

The v0.12.2.3.1.0.1 execution produced a valid saved refresh-only plan and
then stopped at an incorrect local evidence gate. Terraform 1.14.5 represented
the seven reviewed state refreshes in `resource_drift`, returned an empty
`resource_changes` array, and retained the seven expected outputs as `no-op`.
That is the reviewed refresh-only plan shape; the former 13-resource-change
assertion belonged to the preceding ordinary plan.

The existing plan is preserved. It must not be regenerated. This increment
repairs the offline shape validator and completes only the read-only post-plan
checks that the stopped execution did not reach.

## Bound existing evidence

Command-free verification binds the failed request, protected incident commit,
canonical remote-state digest, binary plan, JSON plan, text plan and exact
seven-entry drift digest. It requires:

- `applyable=true`, `complete=true` and `errored=false`;
- exactly seven reviewed `resource_drift` updates;
- an empty `resource_changes` array;
- the exact seven reviewed outputs, all with `no-op` actions;
- no prior recovery result and no re-execution of the plan.

The verifier also reconstructs the original plan, preflight, migration,
identity-rebase recovery and failed-proof request chain. Private state, plan
contents, AWS identity, resource identifiers and object version IDs remain
outside the repository.

## Authority boundary

`verify` runs no AWS or Terraform command and writes no private evidence.
`execute` requires a new protected-main-bound request, a fresh approval window
and this single confirmation:

```bash
export CONFIRM_REFRESH_PLAN_EVIDENCE_RECOVERY=complete-read-only-refresh-plan-evidence-recovery
```

Execution may only read AWS identity, pull/list the current Terraform state,
read the S3 state object history and verify that the temporary plan lock was
released. It requires unchanged canonical state bytes, unchanged state-object
history, one plan lock version, one corresponding delete marker and no current
lock object.

Terraform init, every Terraform plan, apply, state push, destroy, IAM
attachment, direct lock writes, force unlock, automatic retry and automatic
rollback are prohibited.

## Private request and execution

Copy the example request to the owner-readable private root. Replace the main
commit and account placeholders, keep the failed request/output paths exact,
choose a new output directory that does not exist, and create an active window
of no more than one hour.

```bash
python3 scripts/execute-v0.12.2.3.1.0.1.0.1-refresh-plan-evidence-recovery.py verify \
  --private-recovery-request "$REFRESH_EVIDENCE_RECOVERY_REQUEST_01"
```

After separate approval, execute from an isolated subshell:

```bash
(
  unset CONFIRM_BOOTSTRAP_REFRESH_ONLY_PLAN
  unset CONFIRM_BOOTSTRAP_REMOTE_STATE_PROOF
  unset CONFIRM_STATE_BOOTSTRAP_PLAN
  unset CONFIRM_STATE_BOOTSTRAP_APPLY
  unset CONFIRM_STATE_BOOTSTRAP_RECOVERY
  unset CONFIRM_STATE_BOOTSTRAP_MIGRATION_PREFLIGHT
  unset CONFIRM_STATE_BOOTSTRAP_MIGRATION
  unset CONFIRM_STATE_BOOTSTRAP_IDENTITY_REBASE_RECOVERY
  unset CONFIRM_TERRAFORM_APPLY
  unset CONFIRM_TERRAFORM_DESTROY
  unset CONFIRM_STATE_PUSH

  export CONFIRM_REFRESH_PLAN_EVIDENCE_RECOVERY=complete-read-only-refresh-plan-evidence-recovery

  python3 scripts/execute-v0.12.2.3.1.0.1.0.1-refresh-plan-evidence-recovery.py execute \
    --private-recovery-request "$REFRESH_EVIDENCE_RECOVERY_REQUEST_01"
)
```

Human review of the recovered existing plan remains mandatory. Only a later,
separately approved v0.12.2.3.1.0.2 increment may reconcile state by applying
that exact saved refresh-only plan.
