# v0.12.2.3.1.0.2.0.1.2.0.1 Post-Apply State Recovery

The reviewed refresh-only saved plan applied successfully with zero remote
resource changes. Terraform advanced the remote state serial from 1 to 2 while
retaining its lineage and complete 13-managed/9-data address inventory.

The executor then stopped at an invalid whole-object comparison. A
refresh-only plan with no resource changes exposed an empty
`planned_values.root_module`, while `terraform show -json` correctly exposed
all 22 persisted state resources. Offline reconstruction proves that the seven
managed changes exactly equal the reviewed `resource_drift.after` values. The
only additional state change is the `aws_caller_identity.current` data source:
its session ARN and user ID changed while its bound AWS account remained
unchanged. Every other state instance is byte-equivalent.

This recovery never reapplies the plan. Verification binds the stopped
incident artifacts without operational commands. A separately approved
execution may only read AWS identity, Terraform state and S3 state/lock
history, prove the single state-version and lock-version/delete-marker deltas,
and write private recovery evidence. Init, plan, apply, state push, destroy,
force-unlock and direct S3 mutation remain forbidden.
