# v0.12.2.4.1 Validator Orchestration Deduplication

## Outcome

The repository-wide quality gate now reaches the complete v0.12 validator
history without directly launching every member of the same successor-to-
predecessor chain.

Before this increment, `validate-ci-quality-gates.sh` directly launched all 23
v0.12 validators. Twenty-two of those validators already formed one linear
chain in which each successor launches its predecessor. The root invocation
therefore replayed earlier validators repeatedly.

After this increment, the root launches exactly two v0.12 entries:

1. the independent v0.12.1.0.1 CI compatibility validator; and
2. the v0.12.2.4.1 orchestration validator.

The orchestration validator statically proves that the other 22 validators are
present in one acyclic, single-predecessor chain and then launches only the
latest chain entrypoint. Every existing v0.12 validator remains reachable and
runs once through that entrypoint.

For the existing 22-member chain, the effective historical validator launches
fall from 254 (one independent validator plus the triangular chain replay) to
23. The new orchestration validator itself is one additional lightweight
process, so the v0.12 section contains 24 total validator processes instead of
254 while preserving the same historical coverage.

## Safety boundary

- No historical v0.12 validator is edited.
- No GitHub Actions workflow, trigger, required-check name or branch-protection
  expectation changes in this increment.
- Unknown repository changes still run the complete quality-gate suite.
- The validator remains offline and runs no AWS or Terraform command.
- The paused Terraform state exercise gains no execution authority.

Change-impact path routing, pull-request/main-push deduplication, and the
duplicate image-publish quality-gate dependency remain explicitly deferred to
v0.12.3.1. Keeping those changes separate makes the first efficiency repair
small and allows its effect to be measured before workflow semantics change.

## Local validation

Run the focused validator before creating the pull request:

```bash
bash scripts/validate-v0.12.2.4.1-validator-orchestration-dedup.sh
```

The output includes the statically verified unique chain count and the elapsed
seconds for the single v0.12 chain execution. The ordinary full local quality
gate remains available for final pre-merge parity:

```bash
bash scripts/validate-ci-quality-gates.sh
```
