# v0.12.3.1.1 Release-Change Routing Repair

## Incident

After v0.12.3.1 reached protected `main`, the image publisher created promotion
PR #169. Its merge tree changed only
`apps/demo-api/helm/values/releases/aws-dev.yaml`. The automatic classifier sent
that expected desired-state update to the full historical gate. A v0.11 source
contract intentionally pins the complete Helm tree, so the run stopped with
`repository-tree-drift`.

The promotion commit and release-file update were valid. The selected gate was
not.

## Repair

Automatic routing now selects `release` only when the complete diff contains
exactly one of the three reviewed release files:

- `apps/demo-api/helm/values/releases/aws-dev.yaml`
- `apps/demo-api/helm/values/releases/aws-test.yaml`
- `apps/demo-api/helm/values/releases/aws-prod.yaml`

Any additional, renamed, adjacent, unknown, or ambiguous path remains `full`.
Reusable callers cannot request `release` explicitly.

The targeted release gate validates the exact release schema and identity
separation, promotion behavior and governance, and Helm rendering for dev,
test, and prod. Gitleaks remains unconditional and the Trivy configuration scan
continues for release mode. It does not replay immutable historical repository
validators. Both predecessor topology guards recognize only this exact reviewed
successor and continue to report the original deduplicated topology and counts.

## Boundaries

This repair does not rewrite a v0.11 contract or digest, merge PR #169, perform
an AWS operation, or authorize Terraform state work. Isolating future full
historical validation from already-promoted mutable release values remains
v0.12.3.2 work.
