# v0.12.3.2 Post-promotion Static Historical Attestation

## Outcome

Promotion PR #169 legitimately changed only the aws-dev demo-api release file.
Replaying v0.11 validators against the promoted current tree was invalid because
some historical contracts intentionally pin the complete Helm tree.

An interim detached-snapshot replay confirmed that boundary, but also showed
that repeatedly executing 112 frozen entrypoints imports obsolete assumptions
about filesystem modes, worktree locations and durable journal directories into
every current pull request. Routine CI now uses static historical attestation
instead of runtime historical replay.

The required quality gate verifies the exact reviewed commit
`f0736dcb8b1e5a36f2faf0594f9ef222ed9268b7`, proves it is an ancestor of the
current HEAD, compares the current v0.11 entrypoint manifest with the exact Git
blob at that commit, verifies all 112 historical entrypoints are regular Git
blobs recorded as `100755`, and verifies the pinned pre-promotion release
SHA-256. The commit already binds the complete historical tree.

## Runtime boundary

Routine CI:

- does not create a detached worktree;
- does not execute a v0.11 validator;
- does not export a historical snapshot root into current validators;
- runs current v0.12.3 routing, contract and topology structure checks;
- preserves documentation, release-only and fail-closed full routing; and
- preserves the existing required-check name and workflow triggers.

The older v0.11 and v0.12 validators remain tracked for audit history, but they
are not treated as a runtime regression suite for an unrelated current change.
An intentional historical change must update its reviewed evidence explicitly;
routine CI will not silently reinterpret an old contract against a new tree.

## Deliberate limits

This increment does not alter a v0.11 contract or digest, delete historical
validators, change the promoted release, reuse a pull-request result on a main
push, change the required check name, or change workflow triggers. Repository
physical restructuring and broader commercial archival remain v1.0 work.

No AWS, Kubernetes, Terraform, state, migration or recovery operation is
authorized. The paused Terraform state exercise remains paused.
