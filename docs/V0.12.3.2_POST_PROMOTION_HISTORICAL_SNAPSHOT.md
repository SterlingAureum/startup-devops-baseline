# v0.12.3.2 Post-promotion Historical Snapshot Isolation

## Outcome

Promotion PR #169 legitimately changed only the aws-dev demo-api release file.
The targeted release gate accepted that mutable desired-state update, but a
later unrelated core change would still replay v0.11 validators against the
new release bytes. Some of those historical contracts intentionally pin the
complete Helm tree and would therefore stop with `repository-tree-drift`.

The full quality gate now keeps current validation and historical validation
separate. Current v0.12 validators run from the checked-out branch. The 112
deduplicated v0.11 entrypoints run from a temporary detached worktree at
`f0736dcb8b1e5a36f2faf0594f9ef222ed9268b7`, the last green protected-main
commit before the promotion changed release desired state.

Two current v0.12 validators also retain direct v0.11 predecessor calls for
standalone compatibility. During full snapshot orchestration, those exact
transitive calls inherit the reviewed snapshot root and execute their v0.11
targets there; the v0.12 checks themselves continue to read the current
checkout. Direct standalone use without snapshot variables preserves the
original current-root behavior.

## Fail-closed snapshot boundary

Before a historical entrypoint runs, the latest validator requires:

- the exact reviewed snapshot commit, with no caller override;
- full Git history and proof that the snapshot is an ancestor of current HEAD;
- an exact, clean detached snapshot worktree;
- byte-identical current and snapshot v0.11 entrypoint manifests;
- exactly 112 unique, well-formed and executable v0.11 entrypoints; and
- exact snapshot routing for both reviewed transitive v0.12-to-v0.11 calls;
- automatic worktree cleanup on success or failure.

Executable entrypoints are bound to Git's portable executable state: every
manifest entry must be a regular non-symlink file recorded as `100755` in the
snapshot index and executable in the checkout. Host umask differences such as
filesystem mode `0755` versus `0775` are not repository drift.

The snapshot is never pushed, committed or used as current release state. No
file in the active checkout is replaced. A future release-only promotion may
continue to change one reviewed release file, while a later core change can
still replay the immutable historical contracts against their reviewed tree.

## Deliberate limits

This increment does not alter a v0.11 contract or digest, archive historical
validators, reuse a pull-request result on a main push, change the required
check name, or change workflow triggers. Unknown, mixed, script, workflow,
Terraform and GitOps changes still select the full gate.

No AWS, Kubernetes, Terraform, state, migration or recovery operation is
authorized. The paused Terraform state exercise remains paused.
