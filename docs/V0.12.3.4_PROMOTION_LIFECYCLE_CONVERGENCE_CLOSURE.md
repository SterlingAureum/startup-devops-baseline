# v0.12.3.4 Promotion and Lifecycle Convergence Closure

This checkpoint closes the v0.12.3 application-release model without creating
or destroying infrastructure. The repository builds an application artifact
once, preserves its digest across aws-dev, aws-test and aws-prod, and prepares
only the next environment's release-file pull request after the preceding
qualification boundary is satisfied.

Promotion PR preparation may be automated, but review and merge remain human
owned. Production PR preparation enters the protected aws-prod GitHub
Environment. Neither the orchestrator nor the reusable promotion workflow
merges a PR, creates an EKS cluster, runs Terraform, performs an automatic
production rollback or treats an absent environment as permission to create
one.

An absent disposable environment produces `waiting_environment`. Infrastructure
creation, restoration and teardown remain separately reviewed infrastructure
lifecycle operations, with at most one disposable EKS rehearsal environment at
a time.

Promotion PR #169 supplies hosted evidence that an exact single release-file
change follows the targeted release route and remains compatible with later
full core gates. It does not prove a live aws-prod deployment, and this closure
does not make that claim. The final integrated dev/test/prod commercial
rehearsal remains v1.0 RC work.

The next v0.12 checkpoint is v0.12.4: EKS and platform dependency upgrade
lifecycle, compatibility matrices, deprecated-API preflight, one-minor upgrade
sequencing and rollback-versus-rebuild decisions.
