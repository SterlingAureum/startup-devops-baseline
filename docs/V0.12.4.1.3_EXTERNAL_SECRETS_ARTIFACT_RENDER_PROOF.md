# v0.12.4.1.3 External Secrets Artifact and Render Proof

## Outcome

This increment closes the offline artifact-and-render gate required by
v0.12.4.1.2. It does not change the repository's `2.8.0` GitOps pin and does
not authorize a Kubernetes read, dry-run, sync or upgrade.

Official GitHub release assets for chart `2.8.0`, `2.9.0`, `2.10.0` and
`2.11.0` were downloaded outside package application. Each downloaded byte
stream matched the SHA-256 returned for that named asset by the official
GitHub Releases API. Chart metadata also matched the chart tag and application
version. Because those releases are not marked immutable by GitHub, the URL is
not sufficient future evidence: any later download must match the recorded
SHA-256 before use.

## Rendered topology

Every version renders the same 37 object identities: 20 namespaced CRDs,
three Deployments, four Roles, two RoleBindings, one ClusterRole, one
ClusterRoleBinding, one Secret, one Service, two ServiceAccounts and two
ValidatingWebhookConfigurations. No ClusterSecretStore, ClusterExternalSecret,
ClusterGenerator, ClusterPushSecret or PushSecret CRD is rendered.

`serviceAccount.create: false` suppresses only the main controller account.
The chart still creates `external-secrets-webhook` and
`external-secrets-cert-controller` ServiceAccounts. CRD certificate management
also retains one cert-controller ClusterRole and ClusterRoleBinding. The safe
claim is therefore that cluster-scoped RBAC does not expand across the path,
not that the render contains no cluster-scoped objects.

The RBAC, webhook and ServiceAccount semantic digests are identical in all
four renders. All three Deployments change only their chart/application labels
and controller image tags at each hop.

## CRD review

- `2.8.0 -> 2.9.0` changes the ExternalSecret and SecretStore CRDs. Removed
  OpenAPI defaults are already explicit in the repository ExternalSecret
  (`Default` and `None`), while the SecretStore change adds unrelated
  1Password environment support.
- `2.9.0 -> 2.10.0` changes eight CRDs through provider additions,
  validations and audience descriptions. The repository uses only namespaced
  AWS Secrets Manager without an explicit audience.
- `2.10.0 -> 2.11.0` changes only SecretStore and confines the schema changes
  to Barbican and Keeper Security providers, not the repository AWS provider.

The repository's exact `external-secrets.io/v1` ExternalSecret and SecretStore
field paths remain present in every rendered CRD. Version `v1` remains both
served and storage through all four charts.

## Remaining gate

Artifact proof is complete, but live qualification is not. The GitOps pin
remains `2.8.0`; no chart archive or rendered secret is committed, and no AWS,
Terraform, Kubernetes or Argo CD command is authorized. The next checkpoint is
`v0.12.4.1.4-external-secrets-2.9.0-hop-plan`, which must bind the first-hop
release-note review, disposable aws-dev dry-run, convergence evidence and a
fresh approval boundary before any version mutation.
