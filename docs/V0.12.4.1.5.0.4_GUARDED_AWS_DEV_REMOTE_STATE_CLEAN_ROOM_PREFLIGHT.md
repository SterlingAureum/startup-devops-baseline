# v0.12.4.1.5.0.4 guarded AWS dev remote-state clean-room preflight

## Outcome

The dev Terraform root now contains only a partial `backend "s3" {}`
declaration. Bucket, key, region, KMS key and account guard remain in an ignored,
owner-readable private backend file. No credential or resource identity is
committed.

This checkpoint adds two deliberately separate phases:

- `verify` validates protected main, the private request, the exact backend
  configuration and current tracked Terraform source without running an AWS or
  Terraform command.
- `execute` requires a new confirmation and may only read the established
  S3/KMS/IAM foundation, prove the dev state/lock history and EKS cluster are
  absent, and copy the tracked AWS Terraform source to a private staging tree.

Neither phase runs Terraform. A successful preflight does not authorize init,
plan, apply or environment creation.

## Private inputs

Create the request from
`delivery/examples/v0.12.4.1.5.0.4-aws-dev-clean-room-preflight-request.example.json`
outside the repository. The request and backend config must be regular,
non-symlink files at mode `0600`; their parent must be `0700`. Both output and
staging directories must be new and have distinct absolute paths outside the
repository.

The private backend config contains exactly:

```hcl
bucket              = "PRIVATE_BUCKET_NAME"
key                 = "environments/dev/terraform.tfstate"
region              = "us-east-1"
encrypt             = true
kms_key_id          = "PRIVATE_KMS_KEY_ARN"
use_lockfile        = true
allowed_account_ids = ["PRIVATE_12_DIGIT_ACCOUNT_ID"]
```

Populate bucket, KMS and dev state-policy identities from the reviewed
state-bootstrap outputs. Do not derive them from names or copy them into Git.

## Command-free verification

```bash
python3 scripts/execute-v0.12.4.1.5.0.4-aws-dev-clean-room-preflight.py verify \
  --private-preflight-request "$PREFLIGHT_REQUEST"
```

The result must report `operational_commands_executed: []`, both execution
authorizations as false, the current source manifest digest and at least 15
minutes remaining. Review the request digest before granting the separate
read-only execution approval.

## Separately approved execute phase

After approval, set only:

```bash
export CONFIRM_AWS_DEV_CLEAN_ROOM_PREFLIGHT=inspect-empty-aws-dev-remote-state-clean-room
```

The executor reads AWS identity, the expected missing EKS cluster, S3 backend
controls and object history, KMS status/rotation and the unattached exact dev
state-access policy. It copies only Git-tracked `infra/terraform/aws` files to
the new private staging directory and records an exact source manifest.

The expected EKS `ResourceNotFoundException` is evidence of absence, not a
retryable failure. Any different error, existing state/lock history, attached or
changed policy, backend-control drift, unexpected local state, stderr on a
successful read, or source-manifest mismatch stops execution. There is no
automatic retry.

## Human review and successor

Review all private stdout/stderr, the source manifest and preflight evidence.
Success must show zero state and lock versions/delete markers, full bucket
protection, the exact enabled rotating customer KMS key, an unattached exact dev
policy, missing aws-dev EKS, and identical repository/staged source manifests.

Only that human review may start a new `v0.12.4.1.5.0.5` request and approval
window for `terraform init -reconfigure` plus one saved create plan. This
checkpoint does not authorize that successor.
