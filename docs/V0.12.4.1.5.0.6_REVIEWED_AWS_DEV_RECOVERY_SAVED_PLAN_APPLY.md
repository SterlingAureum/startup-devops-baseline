## Verify and approval separation

`verify` runs no AWS or Terraform command. It requires clean protected main,
the exact private recovery request, immutable Terraform source, all reviewed
artifacts, the existing initialized Terraform data directory, a new private
apply-output directory and an active approval window of at most three hours.

The verification result has `apply_execution_authorized: false`. A human must
then separately approve the exact protected-main commit, private apply-request
SHA-256, recovery request SHA-256, binary/JSON/record digests, counts and expiry.

## Exact execution

Before apply, the executor performs only AWS identity, expected EKS absence,
S3 state/lock history, Terraform version and existing-plan `terraform show`
checks. It then executes the exact saved plan once. It does not run Terraform
init or plan.

After a successful apply it records private state pull/list/show evidence,
requires all 96 reviewed addresses, verifies that the EKS cluster is `ACTIVE`,
and checks a positive bounded state-object version delta plus exactly one clean
native lock version/delete-marker cycle. Raw state, resource identities and S3
version IDs remain private.

Any apply or post-apply validation failure stops immediately. The executor does
not retry, roll back, destroy, force-unlock, push state, migrate state or mutate
S3 directly. A post-apply validation failure may mean that infrastructure and
state already exist; preserve all private evidence and do not rerun the plan.
