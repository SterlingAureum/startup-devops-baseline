# v0.12.4.1.5.0.7.1.1 Zero-drift plan gate repair

The first guarded teardown plan stopped before apply with the message that the
saved plan contained resource drift. Offline inspection proved that the plan
was complete, not errored, applyable, and contained zero drift entries. Its
JSON omitted `resource_drift` rather than encoding an explicit empty list.

The `.7.1` gate compared the optional field directly with `[]`, so omission was
misclassified as drift. This checkpoint uses an empty-list default and then
requires the resulting value to be a list with zero entries. A non-list value
or any real drift entry still stops the plan.

The stopped attempt-01 binary plan is not eligible for review or apply because
execution ended before the address inventory, human-readable plan, post-plan
lock audit and plan record were completed. Preserve its private directory as
incident evidence. Do not retry it automatically.

After this repair is merged, create a fresh request and use an attempt-02 plan
output directory. All `.7.1` two-approval, exact-saved-plan and post-destroy
boundaries remain unchanged.
