# v0.12.4.1.5.0.7.1.3 AWS dev final cleanup

Read-only recovery found one account-owned, available ordinary ENI in the
pending private subnet. It has no attachment or association and is neither
requester-managed nor operator-managed. No EKS cluster, active instance, NAT
gateway or subnet route-table association remains.

This checkpoint uses two separate approvals. `prepare` revalidates the exact
private ENI evidence, deletes only that bound ENI, proves its absence, and
creates a saved destroy plan that must contain exactly the pending subnet and
VPC. It does not apply Terraform. The operator then reviews the private plan
and creates a separately approved final request bound to every artifact digest.

`final` applies only that reviewed binary plan. Success requires exactly two
destroyed resources, an empty Terraform state, no state delete marker, a clean
lock lifecycle, and absent subnet and VPC. No init, replacement plan, unsaved
destroy, retry, rollback, force-unlock, state push, or unrelated AWS mutation
is allowed.
