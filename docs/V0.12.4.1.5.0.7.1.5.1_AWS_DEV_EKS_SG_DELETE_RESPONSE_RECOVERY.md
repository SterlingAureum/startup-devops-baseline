# v0.12.4.1.5.0.7.1.5.1 AWS dev EKS-SG delete-response recovery

The approved `.7.1.5` prepare phase stopped after EC2 returned a successful
JSON response for `DeleteSecurityGroup`. The response had `Return=true`, and
its `GroupId` matched the bound target digest, but the executor incorrectly
required empty stdout. No post-delete absence evidence or VPC saved plan was
created.

This checkpoint repairs the reusable delete-response parser so it accepts
either an empty success response or the exact bound JSON success response. It
does not retry the incident security-group deletion.

The separately approved `recovery` phase binds every preserved incident
artifact, verifies the security group is absent, revalidates the exact VPC-only
state, and creates a saved destroy plan containing only
`module.vpc.aws_vpc.this`. It exposes no direct AWS mutation, Terraform init or
Terraform apply.

After human review, a second request may authorize `final` to apply only the
reviewed binary plan. Success requires exactly one destroyed VPC, empty
Terraform state, VPC absence and a clean state/lock lifecycle. Automatic retry,
rollback, unsaved destroy, state push, force-unlock and direct S3 mutation
remain prohibited.
