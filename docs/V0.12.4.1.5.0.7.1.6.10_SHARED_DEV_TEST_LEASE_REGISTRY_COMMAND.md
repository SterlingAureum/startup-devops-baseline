# v0.12.4.1.5.0.7.1.6.10 shared dev/test lease registry command

## Delivered capability

This checkpoint adds the strict local command boundary around the lease-owned
registry composition. It accepts one execution-request file and one private
binding file, each in a distinct owned `0700` directory containing exactly one
owned canonical `0600` regular file. Symlinks, extra entries, noncanonical JSON,
relative paths and caller-supplied digest mismatches fail before claim creation.

The command requires one exact confirmation string and four expected SHA-256
values. It reads host UTC once, instantiates only the exact fixed fake, and
calls the `.6.9` lease-owned function. The command cannot accept a raw command,
failure selector, credential, endpoint, live or retry switch.

## Durable execution boundary

The command does not implement a second lifecycle. Approval validation,
exclusive durable claim-before-dispatch, terminal outcome recording and replay
rejection remain owned by the `.6.9` composition and the append-only lease
store. A second invocation stops on the existing claim before registry backend
dispatch.

Input and terminal failures emit one generic message without private paths,
payloads or resource identities. Private request, binding, approval, claim and
outcome values never appear in stdout or stderr.

## Implementation boundary

The command is a local fixed-fake exercise only. It invokes no subprocess, SDK,
credential reader, AWS, Terraform, Kubernetes, S3 or state command. It grants
no live authority and performs no automatic retry, repair or rollback.

The next checkpoint should exercise the complete dev/test phase chain through
fresh offline command processes with retained redacted summaries. Live backend
implementation and aws-prod execution remain unavailable.
