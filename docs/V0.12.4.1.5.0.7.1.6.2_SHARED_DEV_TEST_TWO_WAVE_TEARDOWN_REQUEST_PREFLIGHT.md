# v0.12.4.1.5.0.7.1.6.2 shared dev/test two-wave teardown request preflight

## Delivered capability

This checkpoint adds a command-free adapter around the shared two-wave
teardown core. It verifies one in-memory private request and emits a redacted,
non-authorizing preflight result. It does not read private files, inspect a live
environment, invoke an operational executor or execute AWS, Terraform,
Kubernetes or S3 commands.

The adapter supports `aws-dev` and `aws-test`, binds their exact independent
state keys and rejects `aws-prod`. Every accepted request represents exactly
one environment, one phase and one positive attempt number. Cross-environment
state keys and predecessor receipts fail closed.

## Phase boundaries

The ordered request vocabulary is:

1. controller cleanup;
2. first-wave plan;
3. exact first-wave saved-plan apply;
4. post-first-wave dependency inventory;
5. optional exact safe-residue deletion;
6. fresh second-wave plan;
7. exact second-wave saved-plan apply;
8. final read-only audit.

The first phase cannot inherit a predecessor. Every later phase must bind an
exact predecessor-receipt SHA-256. This checkpoint validates the request shape;
it does not claim that a predecessor was produced or that the ordered lifecycle
has run.

Early phases require both network and non-network managed-state counts.
Post-first-wave phases require network-only state, and the final audit requires
zero managed addresses. All state inventory identities are SHA-256 bindings;
no AWS resource identifier is emitted.

## Time, plan and residue controls

Plan, inventory and cleanup requests have a maximum one-hour window. Exact
saved-plan apply requests have a maximum three-hour window and cannot outlive
the human review expiry. An apply request binds the binary plan, plan record,
reviewed wave and expected managed-delete count.

A safe residue is accepted only in the dedicated deletion phase. Its category
must be allowlisted by the two-wave core, its identity is SHA-256 only, and it
must be exactly bound. Recognition does not grant deletion authority: the
request and preflight retain `deletionAuthorized: false` and require a separate
approval.

`aws-test` must set `remoteStateReady: true`; this is an input prerequisite,
not evidence that migration has happened. The future live test lifecycle still
requires its separately reviewed remote-state activation evidence.

## CI and authority

This adapter is active operational source code, so its offline checker and
mutation tests join repository structure validation. Historical private
execution evidence remains outside required CI and is never loaded.

Every authority flag must be false at verification time. The result names the
authority that a later human approval would need, but `executionAuthorized`
remains false. This checkpoint exposes no executor and grants no live read,
controller mutation, Terraform plan/apply, direct AWS deletion, retry,
rollback, state push or backend-retirement authority.
