# v0.12.4.1.5.0.7.1.6.5 shared dev/test phase execution lease

## Delivered capability

This checkpoint implements the single-use boundary between a reviewed approval
record and a future phase driver. It deliberately exercises only a closed
fixed fake. No AWS, Terraform, Kubernetes, S3, state or other live command is
present or authorized.

## Immutable approval consumption

The predecessor approval record remains immutable. Executor consumption is
represented by a separate content-bound claim in an owned `0700` execution
store containing exactly owned `0700` `claims` and `outcomes` directories.
Every record is canonical `0600` JSON.

The claim and outcome filenames are both derived from the approval-record
SHA-256. They use no-follow exclusive creation plus file and directory `fsync`.
The claim becomes durable before the fixed-fake driver can be called. Existing,
partial or uncertain claim state is never overwritten, repaired or retried.

Therefore each approval has only three safe observable states:

- no claim: no phase attempt began;
- claim without outcome: an attempt may have begun and retry is forbidden;
- claim plus terminal outcome: the single attempt ended and retry remains
  forbidden, regardless of success or failure.

## Exact execution request

The private execution request binds the exact receipt, approval record,
environment, state key, phase, attempt number, protected-main commit, requested
authority and reviewed execution-spec SHA-256. Its window is at most fifteen
minutes and cannot outlive the approval. It explicitly carries one-attempt-only
and no-retry semantics.

This checkpoint requires `simulationOnly: true` and
`liveExecutionAuthorized: false`. The fixed fake is accepted only by exact
type, is called exactly once after the durable claim and returns only a
redacted digest-bound response.

## Failure and evidence boundary

A fake failure writes a terminal failure outcome when possible and then stops.
A crash or write uncertainty may leave only the claim or a partial record;
that state is preserved for review and blocks all automatic retry. Success also
does not make the approval reusable.

Active-source checks join structure validation while historical private
evidence remains outside required CI. The next checkpoint may add separately
reviewed phase-specific drivers, but it must retain this consume-before-command
lease and cannot reinterpret an uncertain claim as unused.
