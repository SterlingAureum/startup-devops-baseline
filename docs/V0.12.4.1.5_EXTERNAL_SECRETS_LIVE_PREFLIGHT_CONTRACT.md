# v0.12.4.1.5 External Secrets Live Preflight Contract

## Outcome

This checkpoint turns the reviewed External Secrets `2.8.0 -> 2.9.0` first-hop
plan into an executable, fail-closed aws-dev preflight. It does not upgrade the
operator. The repository and live Argo CD Application must both remain pinned
to `2.8.0` throughout this checkpoint.

The executor has two deliberately separate phases:

1. `verify` validates the private request, exact protected-main commit, bounded
   UTC window, reviewed chart archive, reviewed full render and new private
   output location. It executes no AWS, Kubernetes or Helm command and grants
   no execution authority.
2. `execute` requires a separate human approval and exact confirmation value.
   It performs bounded AWS and Kubernetes reads, runs exactly one server-side
   dry-run of the reviewed `2.9.0` full render, and proves that a protected live
   projection is unchanged afterwards.

Successful preflight evidence does not authorize changing the GitOps pin.

## Why server-side dry-run is separate

The earlier artifact proof established deterministic local rendering. It could
not prove that the aws-dev API server, installed CRDs, admission chain and
current RBAC accept that render. The command used here is exactly:

```text
kubectl apply --server-side --dry-run=server --field-manager=v0.12.4.1.5-external-secrets-preflight -o name -f <private-verified-2.9.0-render.yaml>
```

The command may return resource identities only. Its stderr must be empty and
it must report exactly 37 unique objects. `kubectl diff` is not used because it
can disclose live object fields that are unnecessary for this gate.

## Private artifact preparation

Prepare the chart and render outside the repository in a `0700` directory.
This local preparation is not part of the approved live executor:

```bash
PRIVATE_ROOT="$HOME/.startup-devops-baseline-private"
ARTIFACT_DIR="$PRIVATE_ROOT/external-secrets-2.9.0-preflight-artifacts"

install -d -m 0700 "$PRIVATE_ROOT" "$ARTIFACT_DIR"

test "$(helm version --template '{{.Version}}')" = "v3.18.6"

CHART="$ARTIFACT_DIR/external-secrets-2.9.0.tgz"
VALUES="$ARTIFACT_DIR/external-secrets-2.9.0.values.yaml"
RENDER="$ARTIFACT_DIR/external-secrets-2.9.0.render.yaml"

curl --fail --location --silent --show-error \
  --output "$CHART" \
  https://github.com/external-secrets/external-secrets/releases/download/helm-chart-2.9.0/external-secrets-2.9.0.tgz

test "$(sha256sum "$CHART" | awk '{print $1}')" = \
  da2d5c126a103b4c1b16a9dc1c168c4332a3687144e88ac070e594f81a0b6578

yq '.spec.source.helm.valuesObject' \
  clusters/aws/base/platform/external-secrets.yaml >"$VALUES"

helm template external-secrets "$CHART" \
  --namespace external-secrets \
  --kube-version 1.36.0 \
  --values "$VALUES" >"$RENDER"

chmod 0600 "$CHART" "$VALUES" "$RENDER"

test "$(sha256sum "$RENDER" | awk '{print $1}')" = \
  880e6805213cf77cd89cf0e60e03624bc01c74d23a2c61693a1be2a5ce2ca8bb
```

Any digest mismatch stops the procedure. Do not substitute a newer chart or
regenerate the render with different values or a different Kubernetes version.

## Command-free verification

```bash
python3 scripts/execute-v0.12.4.1.5-external-secrets-live-preflight.py verify \
  --private-preflight-request "$PREFLIGHT_REQUEST_01"
```

The result must contain an empty `operational_commands_executed` array and
`preflight_execution_authorized: false`. Record the exact request SHA-256 from
that result before requesting approval.

## Separately approved execution

Only after a human approves the exact protected-main commit, private request
SHA-256 and current UTC window may the following isolated shell be used:

```bash
(
  unset CONFIRM_EXTERNAL_SECRETS_GITOPS_PIN
  unset CONFIRM_EXTERNAL_SECRETS_ROLLBACK
  unset CONFIRM_TERRAFORM_APPLY
  unset CONFIRM_TERRAFORM_DESTROY
  unset CONFIRM_STATE_PUSH

  export CONFIRM_EXTERNAL_SECRETS_LIVE_PREFLIGHT=run-reviewed-external-secrets-2.9.0-live-preflight

  python3 scripts/execute-v0.12.4.1.5-external-secrets-live-preflight.py execute \
    --private-preflight-request "$PREFLIGHT_REQUEST_01"
)
```

The executor requires the current kubectl context to equal the exact EKS ARN
returned for `startup-devops-baseline-dev`. It does not run
`aws eks update-kubeconfig` and it never changes the local kubeconfig.

## Live assertions

Before and after the dry-run, the executor validates:

- both Argo CD Applications are `Synced`, `Healthy` and idle;
- the operator Application remains pinned to `2.8.0`;
- the resource Application resolves the reviewed protected-main commit;
- all three operator Deployments are fully available on `v2.8.0` images;
- the main controller ServiceAccount retains its exact aws-dev IRSA role;
- RBAC remains four Roles, two RoleBindings, one ClusterRole and one
  ClusterRoleBinding;
- the two repository-used CRDs serve and store `external-secrets.io/v1`;
- `SecretStore/aws-secrets-manager` and
  `ExternalSecret/demo-api-postgresql` are Ready;
- the ExternalSecret still references `AWSCURRENT` and has no `force-sync`
  annotation.

The protected projections must have an identical canonical digest before and
after the server-side dry-run.

## Secret and mutation boundary

The executor never calls AWS `GetSecretValue`, never reads a Kubernetes Secret
and never emits a secret value or value digest. The ExternalSecret remote key
can exist only in the private raw evidence. The redacted terminal result emits
booleans, counts, versions and digests, not AWS account, ARN or resource
identity values.

No Git change, Argo CD operation, Helm operation, persistent Kubernetes write,
automatic retry or automatic rollback is permitted. Any command failure,
stderr output, identity mismatch, readiness regression or protected-projection
change stops immediately. Preserve the private output directory and do not
retry with the same request.
