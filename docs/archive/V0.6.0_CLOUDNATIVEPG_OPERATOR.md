# v0.6.0 CloudNativePG Operator Foundation

## Scope

v0.6.0 introduces the CloudNativePG database control plane to the `aws-dev`
GitOps environment.

Delivered:

- official CloudNativePG Helm chart `0.29.0`;
- CloudNativePG operator `1.30.0`;
- Argo CD lifecycle ownership;
- CRDs, RBAC, mutating webhook, and validating webhook;
- two controller replicas on separate stable system nodes;
- unified runtime validation.

Not delivered in this increment:

- PostgreSQL `Cluster` resources;
- PVCs or EBS storage;
- database-specific Karpenter capacity;
- S3 backup or WAL archiving;
- restore, PITR, failover, or application credentials.

This boundary installs the control layer without creating database or storage
costs.

## GitOps Ownership

The aws-dev root Application discovers:

```text
clusters/aws-dev/platform/cloudnative-pg.yaml
```

That child Application installs the official chart into `cnpg-system`. The
chart version is pinned so Git controls operator upgrades.

The operator Application uses automated prune and self-heal. Future
PostgreSQL `Cluster` resources must be managed separately and should not use an
automatic prune policy until their deletion and recovery safeguards are
explicitly validated.

## Placement Contract

The operator runs with two replicas. Required node affinity selects only nodes
that:

- have `workload=system`;
- do not have the `karpenter.sh/nodepool` label.

Required pod anti-affinity spreads the replicas across different hostnames.
This keeps database reconciliation available while application NodePools scale
to zero or experience interruption testing.

## Deploy

After the feature branch is pushed:

```bash
REPO_URL=https://github.com/SterlingAureum/startup-devops-baseline.git \
TARGET_REVISION=feature/v0.6-cloudnativepg-data-platform \
./scripts/deploy-aws-dev-root-app.sh
```

No Terraform change or apply is required for v0.6.0.

## Validate

Run the dedicated check:

```bash
./scripts/validate-cloudnative-pg-operator.sh
```

Or run the unified AWS validation:

```bash
./scripts/validate-all.sh
```

The dedicated script verifies:

- Argo CD reports the Application as `Synced` and `Healthy`;
- the core CloudNativePG CRDs exist;
- both admission webhook configurations exist;
- exactly two operator replicas are available;
- the replicas run on two different stable system nodes;
- no PostgreSQL `Cluster` resource exists.

## Removal Boundary

Deleting the Argo CD Application removes the namespaced operator resources.
Helm does not normally remove installed CRDs during uninstall. Do not manually
delete CloudNativePG CRDs after later versions create databases: CRD deletion
cascades to the managed custom resources and can result in irreversible data
loss.
