# v0.6.1 PostgreSQL Persistence Baseline

## Outcome

v0.6.1 adds the first stateful workload to `aws-dev`: one CloudNativePG-managed
PostgreSQL instance backed by an encrypted gp3 EBS volume.

## Runtime Contract

| Concern | Value |
|---|---|
| CloudNativePG | 1.30.0 operator from v0.6.0 |
| PostgreSQL | 17.10, pinned by immutable image digest |
| Namespace | `data-platform` |
| Cluster | `postgresql-baseline` |
| Instances | 1 |
| Application database and owner | `app` |
| CPU | 500m request and limit |
| Memory | 1Gi request and limit |
| Placement | existing `workload=system` Managed Node Group |
| StorageClass | `gp3-cnpg` |
| Volume | 20Gi encrypted gp3, ext4 |
| gp3 baseline | 3000 IOPS and 125 MiB/s throughput |
| Binding | `WaitForFirstConsumer` |
| Expansion | enabled |
| Reclaim policy | `Delete` |

Equal requests and limits give the database Pod Guaranteed QoS. The existing
EBS CSI add-on and its IRSA role provision the volume; no Terraform or IAM
change is required.

## GitOps and Data Safety

The operator and the database are separate Argo CD Applications. The database
Application uses automated self-healing but disables automated prune. The
Namespace, StorageClass, and Cluster also carry `Prune=false`.

These settings prevent ordinary Git deletion from automatically removing the
stateful resources. They are not a backup mechanism. The explicit cleanup and
destroy scripts delete the Cluster and PVC; because the StorageClass reclaim
policy is `Delete`, that also deletes the EBS volume.

## Credentials

CloudNativePG bootstrap creates the `app` database, the `app` owner, and the
`postgresql-baseline-app` Secret inside the cluster. No password or Secret
manifest is stored in Git. The validation scripts confirm required Secret keys
exist without decoding or printing their values.

## Deployment

Deploy or resync the root Application:

```bash
REPO_URL=https://github.com/SterlingAureum/startup-devops-baseline.git \
TARGET_REVISION=feature/v0.6-cloudnativepg-data-platform \
./scripts/deploy-aws-dev-root-app.sh
```

Run the normal, non-disruptive checks:

```bash
./scripts/validate-cloudnative-pg-persistence.sh
```

This validates the Argo CD Application, Cluster spec, generated credential
Secret, database Pod and placement, PVC/PV binding, live EBS volume properties,
and a local PostgreSQL connection.

## Controlled Persistence Test

```bash
./scripts/run-cloudnative-pg-persistence-test.sh
```

After the operator types `restart`, the test:

1. writes a marker row to the `app` database;
2. records the Pod, PVC, PV, and EBS identities;
3. deletes the only PostgreSQL Pod;
4. waits for CloudNativePG to recreate it;
5. proves that the same PVC, PV, and EBS volume are reused;
6. reads the marker after recovery.

The test causes brief database downtime and is intentionally excluded from
`validate-all.sh`.

## Destroy

```bash
./scripts/destroy-aws-dev.sh
```

The destroy workflow suspends root and database reconciliation, deletes the
Cluster and persistent storage, and only then removes the remaining
Kubernetes-managed AWS resources before Terraform destruction. v0.6.1 has no
backup or restore path; export required data before confirming destroy.

## Deferred

The following are deliberately outside v0.6.1:

- dedicated On-Demand database nodes;
- three-instance cross-AZ high availability;
- S3 backup and WAL archiving;
- restore and point-in-time recovery;
- failover validation;
- demo-api database integration.
