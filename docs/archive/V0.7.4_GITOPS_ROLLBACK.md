# v0.7.4 GitOps Rollback and Finalization

## Goal

Complete the v0.7 delivery baseline with a human-approved, Git-based image
rollback and one trace contract that validates both forward promotion and
historical restoration.

## Delivered

- manual-only `demo-api GitOps rollback` workflow;
- full-history checkout and selected-base ancestor validation;
- metadata-aware historical release validation;
- exact restoration of the historical aws-dev values file;
- deterministic rollback branch and reusable pull request;
- values-only diff enforcement;
- Helm lint and render before push;
- no AWS, Kubernetes, or Argo CD credentials in the rollback workflow;
- rollback contract fixtures in the reusable CI quality gate;
- promotion-or-rollback live trace through `DESIRED_REVISION`;
- final main-branch promotion and rollback exercise.

## Control Boundaries

```text
CI:
  validates and prepares a rollback branch

Git:
  retains the proposed and approved desired state

Human reviewer:
  approves or rejects the environment change

Argo CD:
  reconciles the merged desired state

Trace validator:
  performs a read-only convergence check
```

The rollback workflow does not deploy, approve, merge, call EKS, or invoke
Argo CD.
