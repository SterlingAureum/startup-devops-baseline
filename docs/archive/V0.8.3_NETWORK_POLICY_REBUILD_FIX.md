# v0.8.3 NetworkPolicy Rebuild Portability Fix

## Status

Validated. The permanent NetworkPolicy rules passed the AWS runtime matrix
without either temporary bootstrap policy.

## Incident

After the disposable aws-dev EKS cluster was destroyed and recreated, the
CloudNativePG primary initialized but replica bootstrap stalled. The generated
`join` Job repeatedly timed out when connecting to:

- `default/kubernetes` on TCP/443; and
- `postgresql-baseline-rw` on TCP/5432.

The existing data-platform default-deny policy had two portability defects:

1. CNPG instance policies selected `cnpg.io/podRole=instance`, but bootstrap
   Jobs use `cnpg.io/jobRole=join`.
2. PostgreSQL rw and Barman Service ClusterIPs were copied from the previous
   cluster into Git. Kubernetes allocated different addresses after rebuild.

A temporary ingress and egress policy restored the join path. All three
PostgreSQL instances then became `2/2 Running`, and fresh WAL archival to S3
completed successfully. The temporary policies are a recovery aid only and
must not become the steady state.

## Permanent design

Terraform now declares the EKS IPv4 Service CIDR explicitly:

```text
172.20.0.0/16
```

This value is immutable for the lifetime of an EKS cluster and is reused for
disposable rebuilds. The NetworkPolicy model uses:

- exact `kube-dns` and `default/kubernetes` Service addresses;
- the declared Service CIDR only on TCP/5432 for operator-managed PostgreSQL rw
  Services;
- the declared Service CIDR only on TCP/9090 for the Helm-managed Barman
  Service;
- the two Terraform-declared private subnet CIDRs as the post-DNAT Kubernetes
  API fallback; and
- Pod and namespace selectors for post-DNAT workload identity.

Standard Kubernetes NetworkPolicy cannot select a Service by name. Amazon VPC
CNI can enforce a packet before Service DNAT, so a destination Pod selector
alone is insufficient. A stable Service CIDR with port-bounded rules is the
rebuild-safe compromise; it is intentionally narrower than VPC-wide access but
broader than a single Service `/32`.

Two dedicated policies cover only the baseline join lifecycle:

- `allow-postgresql-baseline-join-egress` selects both
  `cnpg.io/cluster=postgresql-baseline` and `cnpg.io/jobRole=join`;
- `allow-postgresql-baseline-join-bootstrap` permits that source to reach only
  baseline instance Pods on TCP/5432 and TCP/8000.

The join Job receives Kubernetes API and replication access. It does not
receive Barman TCP/9090 or general public HTTPS access. The existing
`full-recovery` policy remains separate because object-store recovery has a
different lifecycle and requires public AWS HTTPS access.

## Apply sequence

First validate that the existing cluster already uses the declared Service
CIDR. Adding the identical value to Terraform should not replace the cluster:

```bash
aws eks describe-cluster \
  --region us-east-1 \
  --name startup-devops-baseline-dev \
  --query 'cluster.kubernetesNetworkConfig.serviceIpv4Cidr' \
  --output text

terraform -chdir=infra/terraform/aws/environments/dev plan
```

The AWS result must be `172.20.0.0/16`. Stop if Terraform proposes replacing
the EKS cluster.

Run the static checks, commit the repair, and refresh GitOps:

```bash
git diff --check
./scripts/validate-data-platform-network-policy.sh
./scripts/validate-ci-quality-gates.sh

TARGET_REVISION=feature/v0.8-production-security-baseline \
  ./scripts/deploy-aws-dev-root-app.sh
```

Confirm both permanent join policies exist before removing the recovery aid:

```bash
kubectl get networkpolicy \
  allow-postgresql-baseline-join-bootstrap \
  allow-postgresql-baseline-join-egress \
  -n data-platform

kubectl delete networkpolicy \
  temporary-cnpg-bootstrap-egress \
  temporary-cnpg-bootstrap-ingress \
  -n data-platform
```

Run the complete non-destructive matrix:

```bash
./scripts/validate-data-platform-network-policy-aws.sh
```

The validator fails if any temporary bootstrap policy remains. It checks the
live EKS Service CIDR and control-plane subnets, verifies all permanent policy
CIDRs, proves three-instance streaming and fresh WAL archival, and creates a
short-lived join-labeled probe. The probe must reach the Kubernetes API and
PostgreSQL rw Service, while Barman access remains denied.

The final line must be:

```text
data-platform NetworkPolicy aws-dev runtime validation passed.
```

## Rollback

If a replica or WAL path fails after removing the temporary policies, reapply
the previously validated temporary recovery policy, collect CNPG and
PolicyEndpoint evidence, and revert this Git commit. Do not delete PostgreSQL
PVCs or resynchronize the Cluster resource as a first response.

The AWS runtime matrix completed successfully before the External Secrets
migration resumed. Its final success marker was:

```text
data-platform NetworkPolicy aws-dev runtime validation passed.
```
