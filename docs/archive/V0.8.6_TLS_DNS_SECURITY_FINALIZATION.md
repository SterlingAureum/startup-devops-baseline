# v0.8.6 TLS, DNS, and Security Finalization

## Goal

Finish the v0.8 Production Security Baseline with a stable public hostname,
ACM-backed HTTPS, an HTTP-to-HTTPS redirect, a restricted EKS public API
endpoint, bounded security-log retention, and one final validation entrypoint.

The public application endpoint is:

```text
https://demo.dev.aureumstack.com
```

## Public IP privacy model

The repository deliberately does not contain the operator's public IP.
`eks_public_access_cidrs` has an empty, fail-closed default, and
`0.0.0.0/0` is rejected by both variable validation and an EKS resource
precondition.

Run the guarded updater whenever the workstation public IP changes:

```bash
CONFIRM_EKS_API_CIDR_UPDATE=restrict-current-ip \
  ./scripts/apply-eks-api-access-cidr.sh
```

The script discovers the current globally routable IPv4 address, passes its
`/32` directly to Terraform, stores the plan under `/tmp`, and deletes the
plan on exit. The process umask restricts that saved plan to the current user.
The plan is a disposable apply artifact, not Terraform state; deleting it only
fails the current run and does not remove the deployed-resource inventory. The
script does not update `terraform.tfvars`, `.env`, documentation, or any other
repository file. `MANAGEMENT_PUBLIC_IP` can be supplied explicitly when
automatic discovery is unavailable.

This update remains possible after an address change even when `kubectl` is
temporarily denied: Terraform changes the EKS endpoint allowlist through the
AWS API and does not require access to the Kubernetes API. After apply, the
script waits for EKS to become Active, refreshes kubeconfig, and verifies the
Kubernetes `/readyz` endpoint from the same terminal before reporting success.

## Ownership and deployment order

The TLS/DNS flow intentionally separates stable infrastructure from the
runtime ALB binding:

1. Terraform discovers the existing public `aureumstack.com` hosted zone,
   creates the ACM certificate and DNS validation record, waits for `ISSUED`,
   restricts the EKS endpoint, and enables `api`, `audit`, and `authenticator`
   logs with 14-day retention.
2. Argo CD applies the demo-api Ingress for
   `demo.dev.aureumstack.com`. AWS Load Balancer Controller discovers the
   matching issued certificate, provisions 80 and 443 listeners, and makes
   port 80 redirect to 443.
3. The root deployment invokes the DNS reconciler. It waits for the live ALB
   hostname and canonical hosted-zone ID, then idempotently UPSERTs the Route
   53 Alias. This automatically replaces a stale Alias after cluster rebuild.
4. The final validator compares the Route 53 Alias with the live Ingress ALB,
   verifies certificate identity, redirect behavior, HTTPS application paths,
   EKS endpoint restrictions, control-plane logging, Argo CD health, and the
   completed PostgreSQL rotation state.

No certificate ARN or ALB hostname is hardcoded in Git. ExternalDNS is not
introduced for this single fixed endpoint.

## Apply

First apply the AWS foundation and endpoint restriction:

```bash
CONFIRM_EKS_API_CIDR_UPDATE=restrict-current-ip \
  ./scripts/apply-eks-api-access-cidr.sh
```

If an old ignored `terraform.tfvars` contains `eks_public_access_cidrs` or
`eks_enabled_cluster_log_types`, remove those assignments after the first
successful update. The guarded script uses CLI variables so stale local values
cannot weaken this execution, but keeping the local file aligned avoids
surprising later manual plans.

Then apply the GitOps Ingress. The deployment refreshes and verifies kubeconfig,
waits for the ALB, and reconciles the stable Route 53 Alias automatically:

```bash
TARGET_REVISION=feature/v0.8-production-security-baseline \
  ./scripts/deploy-aws-dev-root-app.sh
```

The reconciler remains available as an independent repair command:

```bash
./scripts/reconcile-demo-api-dns.sh
```

## Validate

Run the non-runtime contract first:

```bash
./scripts/validate-tls-dns-security.sh
```

Then validate the live final state:

```bash
./scripts/validate-tls-dns-security-aws.sh
./scripts/validate-v0.8-final.sh
```

The second command rechecks all v0.8 repository contracts plus the read-only
PostgreSQL credential rollback final state and the live TLS/DNS/EKS controls.
It does not repeat the destructive NetworkPolicy matrices or credential
round-trip drill; those completed runtime exercises remain separate evidence.

On a rebuilt environment, the Terraform-managed Secrets Manager container
normally starts with `AWSCURRENT` only. That is a valid deployment state but is
not completed v0.8.5 rotation evidence. Re-run the guarded staging, activation,
and rollback/forward-recovery workflow in
`docs/archive/V0.8.5_POSTGRESQL_CREDENTIAL_ROTATION.md` before expecting
`validate-v0.8-final.sh` to pass. Deployment never triggers that drill
automatically.

## Teardown

`destroy-aws-dev.sh` deletes the Route 53 Alias before deleting the Ingress and
ALB. Terraform then deletes the ACM certificate validation record, certificate,
and CloudWatch log group with the rest of the disposable environment. Domain
registration and the public hosted zone are not destroyed.
