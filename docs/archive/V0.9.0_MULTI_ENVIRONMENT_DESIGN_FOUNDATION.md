# v0.9.0 Multi-Environment Design Foundation

## Goal

Close the completed v0.8 branch lifecycle and establish the stable design
contract required before implementing multi-environment manifests or promotion
automation.

This checkpoint is repository-only. It creates no AWS, Kubernetes, DNS,
database, or Secret resources.

## Delivered

- All active aws-dev Applications sourced from this repository track `main`.
- The matching namespace, admission, NetworkPolicy, and External Secrets
  contract tests expect `main`.
- A new active-revision validator classifies all internal-repository
  Applications, preserves local `HEAD`, requires aws-dev `main`, and rejects
  feature revisions in active cluster and script contracts.
- v0.8 is marked complete and v0.8.6 is released in project documentation.
- The roadmap positions v0.9 as the Multi-Environment GitOps Promotion
  Baseline and moves observability into v1.0.
- The environment and promotion model defines one EKS cluster per AWS
  environment, ordered immutable-digest promotion, isolation boundaries, and a
  cost-aware sequential runtime strategy.

## Active Repository Revisions

| Scope | Required revision |
|---|---|
| `clusters/local/` internal repository Applications | `HEAD` |
| `clusters/aws-dev/` internal repository Applications | `main` |
| Third-party Helm and component Applications | Reviewed pinned version |

Historical checkpoint documentation under `docs/archive/` retains the feature
branch commands used during those versions. Those records are not active
desired state and are intentionally excluded from the convergence rule.

## Static Validation

Run from the repository root:

```bash
./scripts/validate-active-gitops-revisions.sh
./scripts/validate-namespace-guardrails.sh
./scripts/validate-application-admission-policies.sh
./scripts/validate-startup-apps-network-policy.sh
./scripts/validate-data-platform-network-policy.sh
./scripts/validate-external-secrets-gitops.sh
./scripts/validate-ci-quality-gates.sh
```

Confirm that no active v0.8 feature revision remains:

```bash
rg -n 'targetRevision: feature/v0\.8-production-security-baseline' \
  clusters scripts docs \
  --glob '!docs/archive/**'
```

The final command must return no matches. Feature references in archived v0.8
checkpoint documents are expected and must not be globally replaced.

## Optional Live AWS Confirmation

If aws-dev is still running, perform a read-only convergence confirmation after
the v0.9.0 change is merged:

```bash
kubectl -n argocd get applications \
  -o custom-columns='NAME:.metadata.name,REVISION:.spec.source.targetRevision,SYNC:.status.sync.status,HEALTH:.status.health.status'
```

The root Application and all seven internal-repository child Applications must
show `main`. Allow third-party Applications to show their pinned release
versions. All Applications should converge to `Synced` and `Healthy`.

Then run the existing non-destructive final validator if the management `/32`
currently permits cluster access:

```bash
./scripts/validate-v0.8-final.sh
```

This checkpoint does not require repeating FIS interruption, PITR, credential
rotation, credential rollback, or other destructive drills already completed
for v0.8.

## Acceptance Criteria

- Active internal-repository GitOps sources have no feature revision.
- Root and child aws-dev Applications agree on `main`.
- Existing static security contracts pass with the converged revision.
- CI quality gates include and pass active-revision validation.
- README, Roadmap, Changelog, and environment model describe the same version
  and environment topology.
- aws-test and aws-prod remain design targets only; no new cloud resources or
  duplicate dev manifests are introduced.
