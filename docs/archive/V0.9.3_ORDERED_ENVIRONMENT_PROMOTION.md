# v0.9.3 Ordered Environment Promotion

## Status

Implemented as a file-level increment. No AWS resources are created or changed
by this checkpoint.

## Objective

Extend the existing build-once aws-dev Promotion PR into an ordered
multi-environment transport path:

```text
build -> aws-dev -> aws-test -> aws-prod
```

The same image digest and source/build identity cross every environment
boundary. Environment configuration, Secrets, databases, backups, certificates,
and Terraform state remain isolated.

## Workflow Ownership

| Edge | Owner | Result |
|---|---|---|
| build -> aws-dev | `demo-api-image-publish.yaml` | aws-dev release PR |
| aws-dev -> aws-test | `demo-api-promote-environment.yaml` | aws-test release PR |
| aws-test -> aws-prod | `demo-api-promote-environment.yaml` | aws-prod release PR |

The environment workflow rejects build to test/prod, dev to prod, reverse,
and same-environment transitions.

## Safety Contract

The workflow:

1. must be dispatched from `main`;
2. captures the source release from `origin/main`;
3. validates its exact release schema and immutable digest;
4. copies the full identity without changing any field;
5. verifies the exact `repository@sha256:digest` exists in GHCR;
6. renders the target environment/release Helm pair;
7. fails if any path except the target release file changes;
8. fails if `main` moves before branch push or PR creation;
9. serializes runs with an independent concurrency group per target;
10. creates a PR but never merges it and never accesses EKS.

The stale-main rule is intentionally conservative. Even an unrelated main
commit invalidates the captured state and requires a rerun, ensuring that the
PR is always prepared against one explicit repository snapshot.

## Validation

Run:

```bash
./scripts/validate-demo-api-promotion.sh
./scripts/validate-ci-quality-gates.sh
```

The first command covers both successful environment edges, rejected edges,
source immutability, target-only mutation, invalid digest rejection, stale
snapshot rejection, workflow permissions, main-only source capture, GHCR
inspection, target concurrency, and PR-only behavior.

## Deferred to v0.9.4

This checkpoint does not add environment validation evidence, CODEOWNERS,
GitHub Environment reviewers, generalized environment rollback, or production
approval policy. It establishes the ordered transport mechanism that those
governance controls will protect.
